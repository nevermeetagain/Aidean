# ADR-0003：多平台账号与余额共享路线确权（维持自研 IdP，拒绝现阶段引入成品 IAM）

> 状态：已接受 | 日期：2026-09-18 | 关联：ADR-0005-SSO统一认证选型接入指南》、《登录方案-评审与决策》G0 判定

## 一、背景

平台目标：Aidean 主站与一系列子项目（AideanBot、AideanWiki 及后续）大概率位于不同域名与服务器，需实现同一账号多平台登录与余额共享。

- 基础（核心）需求：AideanBot 使用 Aidean 主账号登录，余额共享。
- 期望（非核心）需求：AideanWiki 保留自有账号体系，同时支持主账号联合登录，余额共享。

2026-09-18 对外部方案（Casdoor 速览文章引申的成品 IAM 选型讨论）进行了逐点评估，对照真实代码现状得出结论，本文档固化该结论与演进触发条件。

## 二、现状基线（改造前实测）

- IdP 已建成并运行：主平台 `apps/web` 内嵌 OAuth2/OIDC IdP（`app/oauth/*` 七端点 + `/.well-known/openid-configuration` + RS256/JWKS）；middleware Edge fail-closed 验签。
- 令牌安全面：RS256 + kid 轮换双活；RefreshToken 持久化轮换链（重放→整链撤销）；`User.tokenVersion` 全端失效；aud=clientId 令牌隔离；PKCE 仅 S256；redirect_uri 精确白名单防开放重定向。
- 余额共享基建已存在：`GET /api/v1/internal/billing/wallet`（client 凭据 + `wallet:read` scope，实时返回 balance/held/available）；`billingService.getWalletView`；BalanceHold 预扣体系（hold→capture→void→`releaseExpiredHolds`）+ 对账测试。
- AideanBot 已接入：`oidc_clients.wechat-rag`（含 3333 回调）；Bot 后端（FastAPI）`/auth/login` 302 → 主平台 authorize，`/api/v1/auth/callback` 换码建会话；SSO 链路实测通过（307→登录→code+state→会话）。
- 登录通道：微信扫码通道 G0 关闭（个人主体未认证，48001）；邮箱验证码通道为当前主推进项（M4）。

## 三、决策

**维持 ADR-0002 自研 IdP 路线；现阶段不引入 Casdoor/Keycloak/ZITADEL/Logto 等成品 IAM。**

裁决要点（详细论证见 research/sso-balance-final-plan.md）：
1. 问题错位：成品 IAM 治"身份入口分散"，本平台身份入口从未分散——主平台即 IdP，且 OAuth2/PKCE/轮换撤销/全端失效/防开放重定向均已落地；真正阻塞项是微信认证资质（行政门槛），任何 IdP 均无解。
2. 成本错位：引入成品 IAM = 新运行时（违铁律 5）+ 用户库同步税 + 密码哈希迁移 + tier/钱包深度耦合迁不动 + 微信带参二维码事件登录无现成适配。
3. 期权已锁：对外端点为标准 OIDC 子集，未来切换 IdP 时子平台仅改 issuer、零代码改动。

## 四、多平台接入铁律（L1 固化）

1. **身份锚点**：`sub`（= 主平台 `User.id`）为唯一跨平台身份键；邮箱仅作登录标识，禁止作跨平台外键。
2. **Client 注册规范**：oidc_clients 单表管理（clientId / redirectUri 精确白名单 / scopes / pkceRequired / firstParty）；新增子平台 = 新增一行 + seed 脚本。
3. **余额权威唯一**：主平台为唯一余额写入权威；子平台展示层经 internal wallet API 实时查询，禁止本地持久化余额；子平台消费统一经主平台网关计费（usage/hold/capture），子平台零余额写权限。
4. **预扣结算**：长任务用 BalanceHold hold→capture→void；`releaseExpiredHolds` 兜底；幂等键 = requestId。
5. **跨域传递**：跨注册域一律走 OIDC 授权码重定向，禁止跨域 Cookie 共享。

## 五、AideanWiki 双账号模型（L3，待 Wiki 项目本体就位后实施）

- Wiki 本地账号体系保留；登录页提供"使用 Aidean 账号登录"（authorization code + PKCE）。
- 绑定映射表 wiki_user ↔ aidean sub：显式确认绑定；**禁止同邮箱自动合并**（防账号接管）。
- 未绑定用户余额功能置灰引导；绑定后激活（与 L2 同一读写路径）；解绑/换绑落 AuditLog。

## 六、演进触发条件（L5，重评成品 IAM 的门槛）

满足任一条件时重评（候选池：Casdoor[Apache-2.0]、Keycloak[Apache-2.0]、ZITADEL[AGPL-3.0，商用注意]、Logto[MPL-2.0 待核]）：
1. 接入产品 > 5（ADR-0002 原触发线）；
2. 出现不受信第三方接入方；
3. 企业客户要求 SAML/LDAP/SCIM；
4. MCP/Agent 服务需要统一鉴权面。

## 七、后果

- 正面：零迁移成本；既有测试资产（auth 20+ spec、billing hold/capture 对账）直接复用；子平台接入保持"一行注册+标准跳转流"。
- 负面：协议正确性责任自担（P1.6 e2e + 外部安全评审兜底，沿袭 ADR-0002）；back-channel logout、JWKS 轮换自动化等加固项需自行排期。
- 约束：本 ADR 不解除任何铁律；L3 实施时须遵守铁律 3（版本锚点）与文档索引同步。
