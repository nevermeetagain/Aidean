## §一 数据流图

**SSR 主路径：**

```
浏览器 ──GET /models──▶ RSC 页面(app/models/page.tsx, Server Component)
                            │ 进程内直调，无 HTTP 环回
                            ▼
              LadderService.getMatrix(type, filters, sort)
                            │
                   ┌────────▼─────────┐
                   │ Redis GET        │
                   │ ladder:matrix:v{VER}:{type}:{hash12}
                   └────────┬─────────┘
                HIT?        │        MISS?
             ┌──────────────┴───────────────────┐
             ▼                                  ▼
       返回缓存矩阵                     ladderRepository 聚合查询
                                       （ai_models ⋈ model_scores(isCurrent)
                                         ⋈ vendors；stations 榜走 api_stations）
                                             │
                                     Redis SETEX TTL 3600s 回写
                                             │
浏览器 ◀── SSR HTML(首屏含天梯矩阵图) ◀── 扁平排行 entries[]（rank=综合分名次；MatrixItem 含 vendorCountry 国别 / vendorPriority 优先级）
```

**客户端筛选路径：**

```
筛选/排序变更 ─▶ fetch /api/v1/ladder?type=...&sort=...&filters...&offset=0&limit=100（含 updatedWithin 时间窗）
            ─▶ route handler 校验 LadderQuerySchema(@aidean/shared)
            ─▶ LadderService.getMatrix（同一份读穿缓存逻辑；offset/limit 对构建后的 entries 切片）
            ─▶ JSON 信封返回（200 成功 / 20002 非法参数）
```

**无限滚动（v1.9 / v2.0 续载链）：**


**测评「综合」默认口径（v1.8）：**

```
LADDER_BENCHMARK_COMPOSITE="composite"（真源 lib/features/ladder/types，SSR 与 store 初始态共用）
    ─▶ 服务端 applyFilters 对 benchmark 透传不过滤（综合 = 全量口径 = 四维测评分数平均值）
```

**降级分支：**

- `REDIS_URL` 缺失或连接失败 ⇒ `getRedis()` 返回 null ⇒ **直查 DB** 构建，不经 SETEX 回写；
- 直查分支的慢查询记入 slow-log（观测通道），供后续索引优化取证。
- 任意分支失败不抛裸异常，统一收敛到 API 错误码信封（错误码清单见《API接口文档.md》）。

- MatrixItem 含 `vendorPriority`（v1.9；取 `vendors.priority`）：矩阵列贴轴排序依据。
- SSR 首屏取数与 store 初始态共用 `LADDER_DEFAULT_MODEL_TYPES`（类型默认「推理」），保证首屏数据与客户端筛选态一致、挂载后零重复请求。

## §三 缓存键规范

- **格式**：`ladder:matrix:v1:{type}:{hash12}`
- **hash12**：`murmur3x64(JSON.stringify(sortedQuery)).toString(16).slice(0, 12)`
  - `sortedQuery`：对 query 对象键名做字典序排序后稳定序列化，保证「同参数 ⇒ 同键」；不同参数高概率不同键（碰撞概率由 48bit 十六进制截断兜底，天梯参数空间内可忽略）。
- **TTL**：写入用 `SETEX key 3600`（秒）。
- **失效**：`invalidateLadderCache()` 用 `SCAN(MATCH ladder:matrix:* , COUNT 100)` 游标循环收集后逐批 `UNLINK`；禁止 `KEYS` 全量扫（防阻塞 Redis 主线程）。
- **版本段 bump 策略**：`v{VER}` 由 shared 常量 `LADDER_CACHE_VERSION` 单点管理。凡矩阵结构、口径、档位规则发生不兼容变更时手动递增版本段——新键即时生效，旧键等待 TTL 自然过期即可，无需扫描清理（牺牲 1 小时冗余换取零停机切换）。
  - 当前 `v8`：stations 榜 composite 量纲归一（0–5 星级 ×20 → 0–100，对齐分带窗口/区段阈值/性能轴口径），旧 v7 stations 缓存为 0–5 量纲（顶带恒空）不兼容，bump 强制全量重建。
  - 历史：`v6`（v1.9 管理配置版，MatrixItem 增 vendorPriority）→ `v7`（R-83 T3 分数带分窗，band 元数据入指纹）→ `v8`（本次 stations 量纲归一）。

## §四 公式白名单（自定义排序公式安全求值器）

作用域：`/models` 排序栏的自定义公式输入，最终用于矩阵单元格分值重排。

- **变量白名单**（以 `Record<string, number>` 注入求值器）：
  - `{score}` —— compositeScore（0–100）
  - `{priceInput}` —— 输入价（USD / 百万 token）
  - `{contextLength}` —— 上下文长度
- **运算符白名单**：`+ - * / ( )` 与十进制数字字面量。不支持一元负号、比较符、函数调用、赋值。
- **实现**：AST 递归下降求值，`Parser` 类内部三步：
  1. `tokenize` → 数字 / 变量`{x}` / 运算符 / 括号（非法字符在此拒绝）；
  2. `parse` → 文法 `expr → term → factor`（乘除优先级高于加减，括号递归下降覆盖）；
  3. `evaluate(vars)` → 后序遍历求值；`compileFormula(expr)` 缓存 AST 复用（缓存超上限即清空重建）。
- **错误契约**：全部错误抛 `FormulaError`（继承 Error，中文 message）：除数为零、未知变量、括号不匹配、非法字符、表达式为空等。
- **安全红线：绝不使用 eval 与 Function 动态构造执行体。** 原因明示：
  1. **CSP**：生产部署的 Content-Security-Policy 若为容纳 eval 而放开 `unsafe-eval`，将同时放大一切 XSS 的损害半径，得不偿失；
  2. **供应链注入面**：公式文本来自后台配置乃至未来的用户自定义，交给 eval 即等于开放远程代码执行入口；白名单 AST 把可执行域严格收敛到四则运算，攻击者无从逃逸。

## §五 分数带分窗加载链路（v1.9 / R-83 T3，2026-09-26 实装）

```
SSR 首屏：getLadderLoadWindowPct() → service.getRanking({ bandIndex:0, bandHeight })
        → 顶带 entries（综合分 [100-h, 100]）+ data.band={index,height,gte,hasMore}
客户端触带底（LadderMatrixBoard onLoadMore）
        → GET /api/v1/ladder?...&band={index+1}
        → service.applyBandSlice：[max(0,100-(i+1)*h), 100-i*h) 边界归高带（75.00 属顶带）
        → 追加去重并档；hasMore = gte > 0；gte=0 末带 → 「到底了 · 已展示全部 N 个条目」
护栏（LadderBoard）：loadingMoreRef 同步互斥（防同 tick 双拉同带）；查询变更中止在途
        band 请求 + 序号作废 + loadingMore 复位（防旧带 hasMore=false 晚到误判穷尽）。
```

- **缓存**：bandIndex/bandHeight 入指纹（每带独立缓存）；结构加 band 元数据 → `LADDER_CACHE_VERSION` v6→v7。
