### 2.7 端口准则（该仓库 `AGENTS.md` 强制条款，原文要点）

- **3000 = 主平台专用**（宿主 `localhost:3000` 常驻运行，任何其他服务禁止占用）。
- **AideanBot frontend = 3333**：本地开发（`pnpm dev --port 3333`）与容器宿主映射（`3333:3000`）统一用 3333；容器内部仍是 3000（`next start` 默认，无需改动）。**同一时刻 3333 只能由本地 dev 或容器之一占用**（本地 dev 收尾必须杀进程；并行需求时 dev 临时换 3334 并在汇报中注明）。
- backend=8000、LangBot=5300、PG=5433、Redis=6380，变更需先经裁决并同步该文件。

该文件另含分析协议（5W1H 发散 → 苏格拉底双向钢人收敛 → 重构）与六步开发循环（PLAN → SPEC → APPROVE → IMPLEMENT → VERIFY → CLOSE）；代码改动必须同步对应文档与任务进度。

### 3.10 通知与可靠性参数

**`[email]`**：`FLEET_SMTP_ENABLED=0` · `FLEET_SMTP_SENDER/RECEIVER/HOST/PORT/AUTH_CODE`（全 `${VAR}`）· `FLEET_SMTP_USE_SSL=1`

**`[notify]`**（1=开 0=关）：`ON_TASK_START=0` · `ON_TASK_END=1` · `ON_MANAGER_QUOTA=1` · `ON_ROLE_QUOTA=1`

**`[request]`**：`TIMEOUT=600` · `RETRY_MAX=10` · `RETRY_DELAY=10`
口径：`429` / 超时 → 等 `RETRY_DELAY` 秒重试，最多 `RETRY_MAX` 次，仍失败才切换下一候选模型；`401` / `402` / `403` / `quota_exhausted` / `model_not_found` 为**硬失败**，立即切换。

**`[settings]`（REL-01）**：`TASK_STUCK_SECONDS=1800`（任务在 DOING 停留超过该秒数 → 事件 `task:stuck`；超过 2 倍 → `BLOCKED` 等人工，`fleet/rel/retry_timer.py`）· `FLEET_WATCHDOG=0`（控制台进程守护开关，缺省关，遵循 `FLEET_SCHEDULER` 模式）· `FLEET_SCHEDULER_MODE=auto`（服务重启后的调度总线初始模式：有活跃任务即自动推进；缺省 `step`）

### 4.3 技术栈漂移（重要风险，务必先读）

| 出处 | 结论 |
|---|---|
| `docs/03_solution/decisions/ADR-009-tech-stack.md`（**status: accepted**，2026-09-23，用户裁定） | 采用**方案 A：TypeScript 全栈**——前端 React+TS+Vite、后端 Node.js+Fastify(TS)、PostgreSQL(JSONB)、Redis+BullMQ、S3 兼容存储、SSE、`packages/contracts` 共享类型。候选 B（Python FastAPI + Celery）被明确否决，仅允许「局部」引入 Python 解析微服务 |

| `5432` | AideanThesis PostgreSQL | 独占 |
| `5433` | AideanBot PostgreSQL | 独占 |
| `6379` | AideanThesis Redis | 独占 |
| `6380` | AideanBot Redis | 独占 |
| `9900` | AideanFleet Manager（`FLEET_MANAGER_PORT`） | 独占 |

**结论（四条硬约束）**

1. **AideanBot 与 AideanThesis 三处端口两两纠缠**：Bot 占 3333/8000，Thesis 占 3000/8000。二者**共享 8000**，任一启动前必须为另一方改端口。
2. **主平台与 AideanThesis 共用 3000**，二者不可并行；AideanBot 虽不占 3000，但其 `AIDEAN_ISSUER` 依赖宿主的 3000（主平台）做 SSO 与网关联调，**主平台 3000 必须保持在线**（见 §7.2）。
3. **AideanBot 与 AideanFleet 共用 3333**，不可并行；需并行时按 AideanBot `AGENTS.md` 口径让 dev 临时改用 3334 并在汇报中注明。
4. 数据库端口已按项目错开（Thesis 5432/6379，Bot 5433/6380，Fleet 不用外部数据库——SQLite 落地），**数据库层可全并行**。

三条不可逾越的红线（引自 SSO 指南，此处仅作提醒）：

1. 用户密码只在主平台登录页输入，子平台任何页面不得出现密码输入框、任何后端不得转发密码；
2. 身份锚点为 `sub`（= 主平台 `User.id`），同一用户跨子平台 `sub` 一致；
3. 余额 / 套餐是实时数据，禁止本地持久化副本，一律实时查询。

**域名约定（2026-09-28 起）**：子平台对外统一使用主域名的**二级域名**（如 `<product>.aidean.com`，示意，最终以 DNS 分配为准），SSO 场景下 `redirect_uri` 白名单登记完整二级域地址、TLS 推荐通配符证书 `*.aidean.com`；主平台会话 Cookie 保持 **host-only** 不跨子域共享，跨子域登录态一律经授权码流建立。完整口径见《[子平台SSO接入指南](子平台SSO接入指南.md)》§2.1。

### 7.2 SSO 接入现状（按代码实测，2026-09-25）

| 子平台 | 状态 | 证据 |
|---|---|---|
| **AideanBot** | **已接入（唯一接入方）** | `docker/.env.example` 具备完整 OIDC 五件套：`AIDEAN_ISSUER=http://host.docker.internal:3000` · `AIDEAN_PUBLIC_URL=http://localhost:3000` · `OIDC_CLIENT_ID=wechat-rag` · `OIDC_REDIRECT_URI=http://localhost:3333/auth/aidean/callback` · `OIDC_CLIENT_SECRET`；后端有 `providers/aidean/`；前端有 `/auth/aidean/callback` 路由；另有 `AIDEAN_GATEWAY_URL=http://localhost:3000/api/v1/gateway/chat` 接统一计费网关 |

> AideanThesis 若接入，需注意其当前是**账密自建体系**，与红线 #1 冲突（子平台出现了密码输入），接入 SSO 时须一并移除本地账密路径。

### 7.3 依赖主平台的其他形式

- **AideanBot**：运行时依赖主平台的 SSO Issuer 与统一计费网关（`AIDEAN_GATEWAY_URL` 指向主平台 3000）——**主平台 3000 不可下线**，否则 Bot 的登录与 AI 计费均不可用。
- **AideanFleet / AideanThesis**：与主平台无运行时依赖，仅共享端口规划与（未来的）账号体系。
- 三个子平台之间**无任何相互调用**。

## 八、维护规范

2. **更新触发**：任一子平台发生端口变更、技术栈升降级、包名 / 镜像名更名、仓库迁移、认证方式变更或状态阶段变更时，须同步更新 §1 总览表、§2~§4 对应小节、§5 端口矩阵、§6 不一致对照表中的相关行。
3. **版本标记**：按本仓库铁律 3，修改本文档须在文首更新版本标记（`版本 / 更新 / 变更`）。
4. **验证方式**：新增或修改子平台条目时，端口与技术栈数据必须来自对应仓库的实际文件（`docker-compose*.yml` / `compose.yml` / `.env.example` / `pyproject.toml` / `package.json` / `Makefile` / `*.yml` workflow），**不接受凭记忆填写**。§4.3（AideanThesis README 与 ADR-009 双双失准）、§6 第 7/8 行（AideanFleet 声明与实际不符）即为反例——这些失准只能靠读源码发现。

6. **漂移登记**：发现「文档 / ADR 与代码不一致」时，按 §4.3、§4.8、§6 的写法在本文档登记（标注出处、实测值、结论），不擅自替子平台改 ADR。
