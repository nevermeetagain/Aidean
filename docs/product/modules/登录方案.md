# 上篇：评审与决策

## A1. 需求与结论

| # | 需求 | 强度 | 结论 |
|---|---|---|---|
| R1 | 微信扫码登录 | 必须 | 可满足：主路线为[带参二维码](../../governance/术语表.md#登录通道)事件登录，前提是服务号处于微信认证有效期内（G0 门禁先行确认） |
| R2 | 邮箱验证码登录 | 非必须 | 可满足：独立通道，纯服务端能力，无资质门槛，可与 R1 并行开发 |
| R3 | 与既有 JWT/子平台 SSO 兼容 | 隐含 | 所有登录通道只负责"核验身份"，成功后统一签发主平台 JWT；子平台 SSO 零改动 |

**定版**：主路线 = 认证服务号 + 带参数二维码事件登录（个人开发者唯一能拿到"真扫码"体验的官方路径）；微信开放平台「网站应用」扫码因企业主体门槛不可用；若 G0 确认服务号未认证，则以[口令码](../../governance/术语表.md#登录通道)过渡或仅上邮箱通道。

## A2. 两份外部方案评审

### A2.1 方案1（口令码路线）

#### A2.1.1 方案来源与所用工具
- 证据类型：微信官方权限口径比对 + 本机代码走读（AideanFleet `fleet/console/server.py`、`fleet/notify/smtp.py`）+ 项目安全面审计。
- 所用"工具"：官方权限表比对、源码行号级引用、免鉴权路径/cookie 属性/限流缺失盘点。

#### A2.1.2 事实逐条核验

| 断言 | 核验 | 说明 |
|---|---|---|
| 开放平台「网站应用」扫码需企业/组织主体，个人不可用 | ✅ 成立 | 官方要求"已审核通过的网站应用 + 微信登录能力审核"；个人主体无法创建网站应用 |
| `qrcode/create` 仅认证服务号可调，其余返回 48001 | ✅ 成立 | 官方文档适用范围原文："本接口仅支持「服务号（仅认证）」账号类型调用" |
| 网页授权仅认证服务号支持 | ✅ 成立 | 官方文档：仅已认证服务号（政府/媒体等有例外） |
| 个人主体仅能注册订阅号；服务号必须组织主体 | ✅ 成立 | 官方开放社区口径；个人订阅号自 2014-08-26 起不支持微信认证 |
| 消息推送服务器配置 URL 不强制 ICP 备案 | 🟡 基本可信 | 服务器配置仅要求 80/443 + 公网可达；强制备案的是"网页授权域名/JS 接口安全域名"两项设置，以当次后台实测为准 |
| "已关注用户扫码进会话不会推任何事件" | ❌ 有误 | 仅对**普通二维码**成立；**带参二维码**已关注用户扫码会推送 SCAN 事件（官方文档明示）。方案1据此否定扫码路线，导致其结论对"服务号已认证"场景偏保守 |
| `fleet/console/server.py` 等行号级引用（_sessions/_EXEMPT_PATHS/httponly 等） | ⚠️ 未核验 | 当前工作区与 AideanFleet 本地检出均未检到该文件；引用须在对应仓库核对后采信 |
| 163 授权码曾在 `docs/assets/reference/base.md` 泄露 | ⚠️ 未核验 | 但"上线前重置授权码"是无条件正确的动作，照做即可 |

#### A2.1.3 评价
- 优点：资质门槛拆解最彻底，唯一把"48001 api unauthorized"钉死并给出降级路线的；口令码路线是"无任何认证资质"下的唯一真解；安全前置（免鉴权路径、httponly、登录限流）价值高。
- 局限：把"未认证"当作默认前提；目标对象是本地控制台工具（127.0.0.1:5000），不是主平台 Web 服务；对"服务号已认证"场景给出的路线体验偏弱（多一步发消息）。

#### A2.1.4 需求满足度
R1 部分满足（"扫码+发口令"变体可行，但非纯扫码确认）；R2 满足。作为未认证时的降级路线保留。

### A2.2 方案2（服务号网页授权桥接）

#### A2.2.1 方案来源与所用工具
微信官方文档两个官方链接（开放平台网站应用授权登录、服务号网页授权）+ 消费级产品通用跨设备登录模式。

#### A2.2.2 事实核验
- 网站应用扫码（qrconnect / wxLogin.js / snsapi_login、code 10 分钟一次性）→ ✅ 与官方文档一致；
- 公众号 AppID 不能直接调网站扫码登录 → ✅ 正确；
- 网页授权 snsapi_base 静默、code 5 分钟一次性、redirect_uri 全域名精确匹配 → ✅；
- "网页授权不要求先关注公众号" → ✅ 正确（比方案1口径更准）；
- 局限：未覆盖未认证/个人主体的降级路径；其"方案B"二维码内容是登录链接（扫码→微信内开网页→授权→确认），比带参二维码事件多两跳，且需配置**网页授权域名**（要求备案域名）；未涉及消息回调的 5 秒/幂等工程细节（因其不依赖回调）。

#### A2.2.3 需求满足度
R1 满足（前提：认证服务号）；R2 满足。其"手机端确认登录"交互是安全最佳实践，本定版吸收（换票接口天然要求二次确认）。

### A2.3 需求覆盖矩阵

| 需求 | 方案1 | 方案2 | 本定版 |
|---|---|---|---|
| R1 微信扫码（必须） | 部分（口令变体） | 满足（需认证服务号） | 满足（主路线=带参二维码事件）；未认证时降级口令码 |
| R2 邮箱验证码 | 满足 | 满足 | 满足（独立通道） |
| 与 SSO/JWT 兼容 | 未涉及 | 有账号统一原则 | 满足（明确挂接点=同一 JWT 签发链路） |
| 个人开发者资质边界 | 最完整 | 部分 | 已钉死并写入 G0 门禁 |

## 2. M0 资质门禁

### 2.1 G0-S1 ⛔ 确认服务号主体与认证状态
- **目的**：定分支。`qrcode/create` 与网页授权均要求"微信认证有效期内"的服务号。
- **操作**：登录 mp.weixin.qq.com（服务号）→ 设置与开发 → 账号设置：记录①主体类型；②微信认证状态与认证到期时间；③首页右上角账号类型。
- **验证**：能明确回答"服务号是否处于微信认证有效期内"。
- **反馈**：三项记录 + 预判分支（A=已认证 / B=未认证 / C=仅本地自用）。

### 2.2 G0-S2 ⛔ 核对接口权限清单
- **操作**：设置与开发 → 接口权限，确认两项：①"生成带参数的二维码"；②"网页授权获取用户基本信息"（①为主路线必需，②仅 H5 增强需要）。
- **验证**：①（最好①②）均显示"已获得"；任一缺失 → 走 M2-B 降级路线。
- **回滚**：无（只读）。

### 2.3 G0-S3 部署形态确认
- **操作**：确认主平台生产部署形态（standalone + 域名/IP/端口），给出 `curl -I https://<域名>` 或等效可达性证据；确认服务器出口 IP（微信 IP 白名单要用）。
- **验证**：回调域名公网可达（404 也算可达，超时不算）。

### 2.4 G0 判定记录（2026-09-17 闭环）

- **回滚**：迁移文件保留 down 语义；生产执行前先备份。

### 4.6 A-S6 二维码创建端点（改造既有桩）
- **目的**：落实 P2.1 状态机起点 `STATE_INIT → qrGen → POLLING`。
- **操作**：改造 `apps/web/app/api/v1/wechat/qrcode/route.ts`：
  1. `WECHAT_APPID` 缺失 → 维持 `{enabled:false, reason:'CHANNEL_NOT_CONFIGURED'}` 安全降级（不破坏现有 e2e 容错断言）；
  2. 生成 `sceneId = crypto.randomUUID()`（防枚举）；
  3. Redis `wx:login:{sceneId}` = `{"state":"pending"}` TTL 300s；
  4. 服务端调 `POST cgi-bin/qrcode/create`：`action_name=QR_STR_SCENE`、`expire_seconds=300`、`scene.scene_str=sceneId`；
  5. 返回信封 data：`{enabled:true, sceneId, qrUrl:"https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=<urlencode(ticket)>"}`。
- **验证**：dev 配好凭据后 `curl` 端点拿到 ticket；浏览器打开 `qrUrl` 能看到二维码。
- **对齐**：状态一次性绑定当前登录流程；缺配置继续降级。

### 4.7 A-S7 状态查询端点
- **操作**：`GET /api/v1/wechat/qrcode/status?sceneId=`：①校验 sceneId 为 UUID 格式（非法直接 400，防枚举）；②读 `wx:login:{sceneId}`；③TTL 过期或缺失 → `state:'expired'`；④`state:'confirmed'` 时生成一次性换票 `ticket = token_hex(16)`，Redis `wx:ticket:{ticket}` = userId TTL 60s，并把该 sceneId 状态标记为已消费（重复轮询不再发新票）。
- **验证**：单测覆盖 pending / confirmed / expired / 已消费四态；sceneId 非法输入 400。
- **对齐**：P2.1"状态一次性绑定当前登录流程"。

### 4.8 A-S8 事件回调处理（POST /api/wechat/callback）
- **目的**：P2.2 的核心——事件驱动身份核验。
- **操作**：
  1. signature 校验（同 A-S2）；
  2. XML 解析（`ToUserName/FromUserName/MsgType/Event/EventKey/MsgId`）；
  3. `MsgId` 幂等：Redis `SETNX wx:msgid:{MsgId}` TTL 24h，重复直接回 200"success"；
  4. 事件分派：`event=SCAN` 取 `EventKey`；`event=subscribe` 取 `EventKey` 去掉 `qrscene_` 前缀；其余事件/消息回"success"；
  5. 校验 `wx:login:{sceneId}` 存在且为 pending（不存在=过期或伪造，静默忽略）；
  6. 以 `FromUserName`（openid）upsert User（`wechatOpenid` 唯一键）；禁用账号置态后不签发；
  7. 置 `wx:login:{sceneId}` = `{"state":"confirmed","userId":...}`（沿用剩余 TTL）；
  8. **5 秒内**回复 200：返回被动回复 XML（欢迎文案）或空串"success"；重逻辑一律不做在回调里。
- **验证**：测试号/沙箱扫码：pending→confirmed；重复推送不重复建用户；伪造 sceneId 无效果。
- **对齐**：P2.2"合法回调一次生效；重复/过期无重复用户"。

### 4.9 A-S9 换票签发（POST /api/v1/wechat/confirm）
- **操作**：body `{ticket}` → `GETDEL wx:ticket:{ticket}`（原子一次性）→ 命中 userId → 复用既有 auth 签发链路（禁用账号拒绝）→ 签发同一套 JWT + `aidean_token` cookie（HttpOnly+Secure+SameSite=Lax）→ 返回信封 `{code:0,data:{user}}`。
- **验证**：扫码全链：二维码→手机确认→前端换票→`/api/v1/auth/me` 返回身份；同一 ticket 第二次使用被拒。

### 4.10 A-S10 状态机单测（对齐 P2.1 验证命令）
- **操作**：Vitest：生成/等待/成功/过期/取消可观测；缺配置降级；ticket 一次性；sceneId 防枚举。
- **验证**：新增用例全绿；全量单测不低于当次基线（以当次实测为准，不复用历史数字）。

### 4.11 A-S11 端到端沙箱验收（对齐 P2.2 验证命令）
- **用例清单**：①正常扫码登录；②300s 过期→前端重出码；③重复回调幂等；④未注册首次扫码自动建号；⑤已注册二次扫码直接登录；⑥绑定冲突显式规则（见 §8.1）；⑦禁用账号不签发。

## 8. M5 账号打通与扩展性

### 8.1 绑定与合并规则
- 唯一键：`wechatOpenid`、`email` 各自唯一，天然防重复建号。
- 冲突显式规则：①登录态用户主动绑定另一身份 → 验证通过后直接挂到当前 User；②匿名扫码/验证码命中已有账号 → 直接登录该账号（不新建）；③**禁止**按昵称/头像/邮箱前缀自动合并账号。
- 微信与邮箱互为备用登录方式，不强制绑定微信。

### 8.2 登录通道注册表（可扩展性）
- `apps/web/lib/server/auth/channels.ts`：每通道实现 `probe()`（能力探测，如 qrcode 端点降级）与 `verify()`（产出已核验身份）；现有 `password`、新增 `wechat_qr`、`email_code`。
- 新增通道（GitHub/Google OAuth 等）只注册实现，不改签发层；子平台 SSO 零改动。

### 8.3 升级路径
- **需求确认（2026-09-17）：主平台注册账号在全部子平台免注册使用——既有架构已满足，零开发**：子平台经 `/oauth/authorize` 授权码流接入主平台登录页（见《子平台SSO接入指南》），身份锚点 `sub = User.id`；邮箱验证码通道签发同一 JWT 体系，对子平台透明。
- 未来企业化：服务号绑定微信开放平台 → User 增加 `unionId`（可空）→ 可平滑升级开放平台标准扫码。
- 子平台（AideanWiki 等）经 `/oauth/authorize` 走主平台登录页，自动获得新通道。

## 9. 性能设计

| 项 | 设计 | 升级路径 |
|---|---|---|
| 登录态轮询 | 2s 间隔 GET status，Redis O(1) 读 | SSE（复用主平台流式基建）→ WebSocket |
| Redis 键 | 全部 TTL ≤24h；命名空间 `wx:*` / `ec:*` / `rl:*` | 可拆独立 logical DB |
| access_token | 中控缓存 7000s + 单飞刷新锁 | 已覆盖多实例 |
| 回调 5s 预算 | 同步仅做核验+置态+短回复 | 欢迎语/通知走队列 |
| 邮件发送 | 异步投递，失败可重试 | 队列化 |

## 10. 风险登记册

| 风险 | 概率 | 缓解 |
|---|---|---|
| 服务号认证过期/未认证 | 中 | G0 门禁先行；M2-B 口令码降级；或仅邮箱通道 |
| AppSecret/SMTP 授权码泄露 | 低 | 仅服务端环境变量；泄露立即重置轮换 |
| 回调伪造/重放 | 低 | signature 校验 + MsgId 幂等 + sceneId UUID + 一次性 ticket |
| 验证码爆破 | 中 | 哈希存储 + 一次性 + 锁定 + 双维限流 |
| 163 送达率 | 中 | 测试期容忍；正式换 SES |
| 备案缺失 | 中 | 服务器配置先行；H5 网页授权等备案后再开 |
| e2e 断言漂移 | 低 | 微信区占位改真实 UI 后同步升级 auth-guard 断言 |

## 11. AideanFleet 控制台复用说明

方案1（口令码路线）的原始目标对象是 AideanFleet 本地控制台（127.0.0.1:5000）：
- 若 Fleet 只需"自己能用"的门禁：**邮箱白名单验证码**最省事（复用 `fleet/notify/smtp.py`，`SMTP_RECEIVER` 指向自己），无需公网、无需微信。
- 微信扫码对本地工具有价值的前提是暴露公网回调，与单机自用定位冲突；不建议为 Fleet 接微信。
- 方案1的代码行号引用未能在本仓库核验，实施前须在 AideanFleet 仓库逐一确认（_sessions/_EXEMPT_PATHS/cookie 属性等）。
