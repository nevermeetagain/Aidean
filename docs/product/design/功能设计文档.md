| 层 | 选型 | 说明 |
|---|---|---|

| 部署 | Docker Compose | 镜像优先国内源 |

## 二、架构分层

```
请求 → middleware（鉴权/限流/功能开关）
     → app/api/v1/*（路由层，统一响应）
     → lib/services/*（业务逻辑）
     → lib/repositories/*（数据访问，Prisma 封装）
     → PostgreSQL + Redis
页面（Server Component 取数 + SEO）
     → components/*（视图，含 Client 交互组件）
     → hooks/* + stores/*（客户端状态）
```

- **Repository Pattern**：所有 DB 访问经 `repositories/`，禁止在路由层直接写 Prisma。
- **Service Pattern**：业务规则（排名、计费、采集编排）集中在 `services/`。
- **配置集中**：`lib/config/` 统一 env / 主题 / 站点 / 语言。

## 三、核心模块实现要点

### 3.1 天梯图数据流（2026-09-03 M-LADDER 修订：快科技式扁平排行）
1. 用户打开 `/models` → Server Component 取数（Prisma 聚合）。
2. 构建排行：**一行 = 一个模型/站点**，entries 按当前排序键全序输出；`rank` 字段恒为综合分降序的同分并列名次（competition ranking 1,2,2,4），与展示排序解耦（参照快科技 CPU 天梯图形态）。
3. 筛选/排序 → 生成 `filterHash` → `GET /api/v1/ladder?filters={hash}&sort=...`。
4. 命中 Redis（`ladder:matrix:v3:{type}:{hash}`，1h）直接返回，未命中查 DB 并回填。
5. 表格/柱状图共用同一份 `rankingData.entries`，切换视图不重复请求。

### 3.2 排名算法
- `services/ranking/algorithm.ts`：四维加权；`formula-parser.ts`：自定义公式解析（变量 + 运算符 + 安全计算）。
- 权重存 `ranking_weights` 表，后台调整触发重算 + `ranking:v1:*` 缓存失效。

### 3.3 用户与余额
- 注册：写 `users` → 签发 JWT；登录：bcrypt 校验 → Access(24h)+Refresh(7d)。
- 充值：创建订单 → 第三方支付回调 → 更新 `recharge_orders` + `users.balance`。
- 预扣费：事务内 `balance decrement` + 写 `transactions`，失败回滚退还。

**（B）SyncAdapter 接口签名**

```ts
// types.ts（契约真源）
type SyncSource = "official_api" | "crawler" | "manual";

interface SyncContext {
  batchCode: string;
  source: SyncSource;
  operatorNotes?: string;
  lastCursor?: string;      // 增量源的分页/游标（可用于断点续采）
}

interface RawModel {
  providerCode: string;     // 对应 Vendor.code
  modelCode: string;        // 对应 AiModel.modelCode（全局唯一键）
  nameDisplay: string;
  modelType?: string;       // 归一化到 ModelType enum
  parameterCount?: string;
  contextLength?: number;
  isOpenSource?: boolean;
  pricing?: {               // 可选，落到 ModelPrice
    inputPerMillion?: number; outputPerMillion?: number;
    inputCacheReadPerMillion?: number;
    currency?: string;
  };
}

interface SyncSummary { created: number; updated: number; unchanged: number; failed: number; }

interface SyncAdapter {
  readonly source: SyncSource;
  fetch(ctx: SyncContext): Promise<{ models: RawModel[]; nextCursor?: string }>;
}
```

- 适配器职责：**只做「拉取 + 字段映射成 RawModel」**，不做 DB 写（写一律走 writers）。
- 新源接入 = 实现 `SyncAdapter` + 注册表登记即可，orchestrator 与 writers 零改动。

**（C）checksum 去重算法（防重复采集，D4）**

```
checksum = sha256( canonicalJson({ providerCode, modelCode, ...业务字段 }) )
```
- `canonicalJson`：键按字典序排、值 JSON.stringify 紧凑、无尾空格——保证**同内容两次采集指纹一致**。
- 判重逻辑（writers/upsert 内）：
  1. 查 `ModelChangeLog` 最近一条同 `modelCode` 的 checksum；
  2. **同指纹** → 标记 `unchanged`（不触发 `updatedAt`、不产生噪声变更流）；
  3. **异指纹** → 落一条 `changeType="updated"` 的 `ModelChangeLog`（`before_data`/`after_data`/`changed_fields` 全落）+ UPSERT。
- `SyncBatch.batchCode @unique` 为批次边界；同一批内同模型去重以 checksum 为准。

**（D）writer UPSERT 主键规则**

### 3.6 统一计费网关（MVP 核心）
- **计费引擎三分叉**：① 本系统计费 `（上游单价×加价率）×（Token 数×倍率）`，走平台 Key 池或用户自有 Key；② 上游计费，用户自有 Key 按平台单价原样记账；③ 套餐直连，兑换某平台套餐后按该平台规则计费（倍率不生效）。按请求维度选择路径。限时优惠直接替换计费基准单价（折扣价或 0）。
- **协议中转层**：网关入口兼容 OpenAI / Anthropic 两种请求格式；出站按上游平台能力自动转换（仅兼容 OpenAI 格式的上游由平台中转 Anthropic 请求）。
- **降级链**：优先级 1~99 路由（free 模型自动加载为最低优先级）→ 请求不通自动降级到次级 → 用户未配置且余额不足时兜底切 free 模型。
- **Key 池调度**：`station_keys` 每站多 Key 按权重分流 / 并发；故障 Key 自动摘除并告警。
- **免费额度**：按等级 × 模型配额（天/周/月刷新），扣减优先于余额扣费。
- **限时优惠**：优惠价随上游价格采集同步（adapters 同步 `model_prices`）；**直接影响计费价**——可能是折扣也可能免费（免费时计费为 0），展示价同步切换。
- **等级映射**：Opus/Sonnet/Fable/Haiku 到具体模型的映射由用户定义（`user_tier_mappings`）；free 等级由后台定义默认免费模型，控制台自动加载、不可配置。
- **敏感配置**：加价率与 Token 倍率仅存 `station_billing_rules`，仅经 admin 接口读写，序列化白名单保证不外泄。

## 附录 D：模型提供商定价数据模型（v0.9.0 新增）

### D.1 设计目标

平台聚合商（ModelProvider）的定价数据需要完整描述每个模型的三维度价格（输入 / 输出 / 缓存命中），并支持 K Tokens 与 M Tokens 两种标价口径的自动换算。

### D.2 ProviderModelOffering 字段清单

| 字段 | 类型 | 说明 |
|------|------|------|
| `listedAt` | DateTime? | 模型在平台上线/挂载时间 |
| `defaultMultiplier` | Decimal(8,4) | 可用倍率，默认 1.0 |
| `priceInput` | Decimal?(19,6) | 输入标价（原币） |
| `priceOutput` | Decimal?(19,6) | 输出标价（原币） |
| `priceCache` | Decimal?(19,6) | 缓存命中标价（原币） |
| `priceUnit` | String | 标价单位：`per_million_tokens` 或 `per_1k_tokens` |
| `discountInputMin/Max` | Decimal?(19,6) | 输入折扣价区间（元/M Tokens） |
| `discountOutputMin/Max` | Decimal?(19,6) | 输出折扣价区间（元/M Tokens） |
| `discountCacheMin/Max` | Decimal?(19,6) | **缓存命中折扣价区间（元/M Tokens）**（v0.9.0 新增） |
| `effectiveFrom` | DateTime | 有效期起始 |
| `effectiveUntil` | DateTime? | 有效期结束 |
| `isActive` | Boolean | 是否启用 |

### D.3 折扣价计算公式

```
折扣价(元/M Tokens) = 标价(原币/M Tokens) ÷ (充值比例 × 倍率)
```

当标价单位为 `per_1k_tokens` 时，先换算为 M Tokens 口径：
```
标价(原币/M Tokens) = 标价(原币/K Tokens) × 1000
```

K Tokens 与 M Tokens 折扣价换算：
```
折扣价(元/K Tokens) = 折扣价(元/M Tokens) ÷ 1000
```

### D.4 缓存折扣价闭环

此前 `cachedTokens` 仅落库不参与折算（见《网关计费时序契约》§2.1 待闭环注记）。本次新增 `discountCacheMin/Max` 字段，为缓存命中维度提供与输入/输出一致的折扣价数据结构，使缓存价格在前台 providers 页面、admin 管理面板、以及未来扣费链路中均可完整表达。

### D.5 前台展示格式

providers 页面价格表采用三行制（输入 / 输出 / 缓存命中），每行展示：
- **标价**：原币 + 单位（K 或 M Tokens）
- **折扣价 / K Tokens**：元/K Tokens
- **折扣价 / M Tokens**：元/M Tokens

换算说明区块附带公式与示例，确保用户可自行验证价格。
