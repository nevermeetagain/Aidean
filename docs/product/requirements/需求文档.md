## 一、概述

**AI 模型与云服务的「天梯图」评测平台**——用可视化排行榜 + 多维排序，让开发者和企业"扫一眼"完成模型与云服务选型。

- **核心目标**：天梯图可视化评测，免费看数据，对比测评按次从余额扣费；统一计费网关一次充值通吃所有接入平台。
- **生态目标**：以主平台为门户展示自研平台产品与子平台（[AideanWiki](../../governance/术语表.md#aideanwiki) 知识库、[AideanBot](../../governance/术语表.md#aideanbot) 机器人（生态内亦称 WeChatRag）、AideanFleet、AideanThesis 等），打通"评测选型 → 统一调用 → 知识库落地"链路。
- **参考**：ai-bot.cn（差异点：以天梯图为核心，而非简单列表）。

## 二、用户角色

| 角色 | 诉求 |
|---|---|
| 普通访客 | 浏览天梯图、模型详情、历史测评 |
| 免费注册用户 | 筛选排序、收藏、充值，享对应等级 free 模型与免费额度 |
| 付费用户 | 实时对比测评（¥2/模型/次）、统一计费网关调用、查看消费记录 |
| Pro / Max 用户 | 按等级享有更优 free 模型集、折扣与免费额度权益 |
| 管理员 | 维护数据、配置算法权重、管理 Key 池 / 计费规则 / 兑换码 / 套餐 |

## 三、核心功能需求

### 3.1 天梯图（核心）
- **两类榜单**：模型对比天梯图（大模型榜）、大模型云服务天梯图（模型站榜，原"API 站"榜更名）。
- **两个版本**：专业版（技术类型）、应用版（业务场景）。
- **两种视图**：排行榜表格（矩阵式，默认）/ 柱状图。
- **工具栏三行制（v1.10 纵向重排）**：行1 = 专业版/应用版（左）｜五维筛选（右）；行2 = 视图切换（天梯图/柱状图，左起首位）+ 排序 + 分度值 + 阵营开关（国外（左）/国内（右））；行3 = 标题「模型性能天梯图 · 卡片越靠上综合分越高 · 点击卡片查看详情」（左）｜数据更新时间（右）。
- **五维筛选**：类型 / 协议 / 测评集 / 标签 / 时间（即时生效，互斥展开）；类型、协议、标签、时间多选，测评单选；开源 / 闭源作为标签选项并入标签组（不再单设开源下拉框）。
- **五种排序**：综合评分（默认）/ 上下文长度 / 响应速度 / 价格 / 自定义公式。
- **分度值（v1.7）**：排序下拉右方新增分度值下拉——性能轴最小一格代表的分值；默认 = 后台配置颗粒值，用户可在常见档位（0.1/0.2/0.5/1/2/5 等）间即时切换，轴刻度密度与卡片档位随之变化。
- **性能轴全量程（v1.7）**：轴量程恒为 0 → 顶格，**下拉到底部时性能轴分数必须达到 0**；每格均标注性能值。
- **后台配置（管理员）**：模型厂商优先级（1-99，数值越小离性能轴/分隔栏越近）；性能轴固定颗粒值（默认 0.1，合法域 0.01–10，作为分度值默认值）。
- **无限滚动（v1.7 修订）**：下拉近底部自动加载下一页，若性能轴未达 0（仍有数据）则每段自动续载；数据穷尽处提示「到底了」；天梯页面不展示页脚。

### 3.2 模型详情页
- 左侧固定目录（基本介绍 / 参数信息 / 在哪里可调用 / 基准测试 / 测评示例，v1.16 新增「在哪里可调用」），平滑滚动 + 高亮。
- 参数表：模型名、类型、参数集、上下文、开源、价格、官网跳转、API 推荐。
  - **计价展示口径（C-10 / U-15 待裁决）**：现行代码按价格行原币原单位展示（如 USD / 1K Tokens），平台不做换算；「统一 ¥/M Tokens + 汇率配置键」方案见 ADR-P005，U-15 裁决后由 TASK-047/048/053 落地，裁决前不得出现任何 ¥ 换算值。原文「¥5=$1 换算」保留为待裁决选项，不作为现行口径。
  - **限时优惠展示（v1.16 实装）**：生效价 = 窗口内优惠价，否则当前价；优惠期显示「限时优惠 / 限时免费 · 截至 <北京时间>」徽标与原价划线（/pricing、模型详情），输入与输出价同为 0 才称「限时免费」。
- 基准测试弹窗（点击基准名打开，含分项指标、来源、版本、测试日期与核验状态）、历史测评示例（同题多模型回答并排，来自公开示例，v1.16 已替换「即将上线」占位）。
- 「在哪里可调用」：平台挂载与折扣价 + 多源上架观测（源分级、在架状态、原币价、最后采集时间、来源链接；中转源标注「身份未验证」，见 §3.4.2 REQ-M-014）。

### 3.4.1 数据供给方式（D-3=A：先发布后补采集）
- **决策状态**：D-3=A——MVP 阶段以人工录入 + seed 演示数据为主，自动采集（sync）作为 P1 降级。
- **人工路线（MVP）**：管理员经后台 CRUD 手动录入模型信息、基准测试数据、价格信息。所有写入留 `audit_logs` + `model_change_logs`。
- **自动采集路线（P1）**：`lib/sync` 框架已建骨架（adapters/mappers/writers），支持从上游平台采集 model/contextLength/prices 等字段。字段所有权按 §功能设计文档 五、字段所有权矩阵 执行——sync 不覆盖人工字段。
- **provenance 保障（已落地）**：每条数据标注 `sourceType`（SELF/OFFICIAL）和 `sourceName`，前台展示来源徽标；未核验数据（`verifiedStatus=0`）不出现在天梯图读侧。
- **过渡期**：seed 演示数据批量置 `verifiedStatus=1`（演示环境豁免），生产环境上线前须人工逐条审核。

### 3.4.2 模型源监控
> 设计：[模型源监控设计](../../architecture/模型源监控设计.md)｜契约真源：`packages/shared/src/schemas/monitoring.schema.ts`｜数据：《数据库文档》§二「模型源监控」。

目标：多源采集模型目录 → 按源保存证据 → 检测变化 → 后台可管理、前台可查询「某模型在哪些平台可调用、各卖多少钱」。范围收敛为**注册表内的源**，新增源走后台登记。

| 编号 | 分级 | 需求（可验证表述） |
|---|---|---|
| REQ-M-001 | MUST | 维护源注册表：分级（S1/S2/A/B/C）、类型、端点、是否需 Key、采集频率、条款状态、启停 |
| REQ-M-002 | MUST | 至少 3 个无需 Key 的公开目录源每日采集；需 Key 的源缺凭证时标记 credential_missing |
| REQ-M-003 | MUST | 保存目录快照（sha256 去重，原始响应不落盘，仅哈希+字节数+≤2KB 采样） |
| REQ-M-004 | MUST | 按源保存模型观测（首次/末次出现时间、原币价格） |
| REQ-M-005 | MUST | 快照 diff 产出 4 类事件（上架/下架/首次出现/价格变动≥1%）并留证据 |
| REQ-M-006 | MUST | 公开查询某模型在哪些源可调用 |
| REQ-M-007 | MUST | 价格以原币+单位保存；任何换算必须读统一汇率配置（不得硬编码） |
| REQ-M-008 | SHOULD | 可用性时序（llmtest 公开指标 + 自有探针） |
| REQ-M-009 | MUST | 用既有调度体系运行，单源失败隔离，结果后台可见 |
| REQ-M-010 | MUST NOT | API Key 不进入仓库、日志与快照 |
| REQ-M-011 | SHOULD | 后台可启停源、改频率、手动运行 |
| REQ-M-012 | MUST | 先登记契约与错误码（20004、50012）后实现 |
| REQ-M-013 | SHOULD | 后台监控页五态齐全（空/加载/错误/无权限/就绪）并有 E2E |
| REQ-M-014 | MUST NOT | 中转站自报的模型名不能当身份证据；relay 对外标「身份未验证」；不自动 promote |
| REQ-M-015 | MUST | 第三方数据按条款使用（署名、免费/授权层级） |
| REQ-M-016 | COULD | 中转真实性信号（如 thinking signature 校验） |

**明确不做（MUST NOT）**：不宣称覆盖全网所有模型站点；不抓需登录、有反爬或验证码的页面，不绕过任何访问限制；不把结构分层（稳定性星级）当评分写进天梯；不自动下架、不自动 promote 中转站（探针结果只作信号）；不并入 AGPL 代码；汇率口径（U-15）裁决前，监控数据不做 CNY 换算展示。

**待裁决**：U-M1 需 Key 源清单与凭证提供方式；U-M2 是否申请第三方评测数据 Key；U-M3 是否允许真实调用中转站探测及预算；U-M5 源映射实体（平台聚合商 vs 中转站）；U-M6 首批公开源范围与条款核验结论（现按 5 个公开源假设，条款状态 pending）。

### 3.5 用户与余额（MVP 核心）
- 注册 / 登录：邮箱 + 密码（**访问令牌 15 分钟 + Refresh 7 天**，RS256；访问令牌时长后台 `security.accessTokenTtlMinutes` 可配 5–60 分钟；密码 bcrypt）。
  - C-2 裁决（U-1，以代码为准）：原文「JWT 24h」与 `constants.ts` ACCESS_TTL_SECONDS=15min 冲突，按代码口径改写。
  - **微信扫码登录：暂停**（C-1 / U-11 默认维持暂停；前台入口整块隐藏，恢复须用户裁决）。
- **用户等级**：普通用户 / Pro 用户 / Max 用户；后台按等级配置适用的 free 模型、折扣及各 free 模型的免费额度（额度支持天 / 周 / 月刷新）。
- 余额制预付费：充值档位（体验¥10 / 基础¥55 / 标准¥115 / 专业¥600 / 企业¥2500）；**在线支付（微信 / 支付宝）暂停**（C-1 / U-11），现阶段以兑换码与后台调账入账。
- 付费操作预扣费，失败退还；消费记录按日期分组。

### 3.6 统一计费网关（MVP 核心）
一次充值，通吃平台接入的所有大模型服务平台（如 SiliconFlow、百炼、DeepSeek 开放平台等）。

**API 供给（双模式混合）**
- 优先使用用户自有平台 API Key；未配置时走平台 Key 池统一供给。
- 后台可对每个平台配置多个 Key，用于分流 / 并发。

**优先级路由与降级**
- 优先级 1~99，1 为最高；高优先级模型请求不通时，自动切换到次级优先级。
- 控制台自动加载 free 模型，作为最低优先级兜底。
- 用户未配置私有模型且余额不足时，自动切换到 free 模型。

**控制台双形态（共享同一份底层路由配置，可随时切换）**
- **通用版**：将具体模型绑定至 Sonnet / Opus / Fable / Haiku 模型等级（可不配置），固定序 Opus > Sonnet > Fable > Haiku。
- **专业版**：对具体模型配置 1~99 优先级；等级默认映射 Opus=1 > Sonnet=2 > Fable=3 > Haiku=4。
- **等级映射由用户定义**：用户自行决定各等级绑定的具体模型；free 等级由系统后台定义用户默认使用的免费模型，自动加载、不可配置。

**计费规则（后台按站二选一，默认本系统计费）**
- 本系统计费：`余额扣费 =（上游单价 × 平台加价率）×（实际 Token 数 × Token 倍率）`；两项倍率默认 1.0（不加价），均为后台敏感配置、**用户不可见**。
- 以模型服务平台为准：按该平台单价原样计费（用户自有 Key、套餐直连场景）。

**协议中转**
- 网关入口兼容 OpenAI 与 Anthropic 两种请求格式；对仅兼容 OpenAI 格式的上游平台，自动做协议中转。

**自定义平台渠道**
- 用户可自填 base_url + API Key 接入任意平台（兼容 OpenAI / Anthropic 格式）；此类调用**不扣平台余额**（费用用户自理），平台提供**无限制的免费中转**（仅路由 + 协议转换）。

**限时优惠**
- 合作平台可对某最新模型配置限时优惠；优惠**直接影响计费价**（可能是折扣，也可能免费——免费时该模型计费为 0），并随上游价格采集同步展示价。

### 3.7 套餐兑换（平台内权益）
- 用户余额可兑换平台支持的套餐（如私有化部署 DeepSeek 天卡），履约闭环在平台内。
- **套餐直连**：兑换某平台套餐后，请求默认路由至该平台并按该平台计费规则计费（包天卡类套餐平台加价率与 Token 倍率不生效，不赚差价）。

### 3.8 兑换码
- **余额码**：兑换获得余额；后台批量生成、一次性核销、可设有效期。
- **定向套餐码**：与合作平台联发，仅可兑换指定平台的指定套餐。

### 3.9 功能开关
- 按 Key 控制模块启用 / 禁用（如 `ladder.station`、`gateway.chat`、`favorites.*`、`chat.support`）；关闭则入口隐藏、页面 403、API 拒绝（50011）。
- **实装口径（v1.16 实测）**：后台 `/admin/feature-flags` 列表 + 单项切换（`GET /api/v1/admin/feature-flags`、`PATCH /api/v1/admin/feature-flags/[id]`）；开关读取失败 fail-open 并记日志（依据 ADR-P002 / DESIGN-001；fail-open 口径待 U-7 最终裁决）；新增/删除开关不开放后台写入（由 seed/迁移维护）。

### 3.10 后台管理功能域（D-1 暂定 B：仅 P0 四域）

> 决策状态：D-1 暂定方案 B——仅补齐 P0 四域（models / users / benchmarks / audit），P1 域（stations / billing-rules / quotas / feature-flags / announcements）留后续迭代。

**敏感配置约束（对应 §3.6）**：加价率、Token 倍率、卡商密钥等敏感配置仅经 admin 接口读写，API 响应经序列化白名单过滤，公开接口不暴露。

## 四、排名算法

| 维度 | 默认权重 | 可调 |
|---|---|---|
| 官方评测基准 | 25% | ✅ |
| 实际评测基准 | 25% | ✅ |
| 风评 | 25% | ✅ |
| 自测 | 25% | ✅ |

综合得分 = 各维度得分 × 权重 / 100；权重后台可调并触发重算、缓存失效。

### 3.11 首页与导航（UI 规格）
- **一级导航（八项，v1.16 以代码 `lib/navigation.ts` 为准，C-3 / U-2）**：首页 / 资讯 / 产品 / 价格 / 文档 / 路线图 / 合作 / 关于；「产品」二级下拉含 模型天梯图（/models）、模型服务提供商（/providers）与各子平台介绍页（/products/[slug]，桌面端悬停/键盘聚焦展开）；**Logo 点击回首页**。原文「模型」一级项已并入「产品」下拉。
- **首页结构（自上而下）**：多级菜单栏 → banner 图 → 平台介绍 → 模型 → 产品 → 路线图 → 合作 → 关于（关于置底）。
- **模型部分**：模型天梯图、模型对比、模型可使用 API 对应的平台详情页、大模型云服务平台天梯图。
- **合作部分**：合作企业 logo 列表多行排列、交替滑动（第一行从右到左循环，第二行从左到右，依此类推）。
- **价格页（价格中心）**：网关 token 计费单价表（展示价与官方一致）+ 余额充值档位 + 产品（AideanWiki/WeChatRag）等级权益价格。

## 五、全局强约束

1. **多套浅色主题**：整体视觉永远浅色（**不提供深色模式**）；主题切换指多套浅色主题（不同主色色相）间切换；默认中文。
2. 搜索框仅存在于顶部导航栏（C-4：现行顶栏尚无搜索框；`/docs` 页内另有文档检索框（DocsReader「搜索文档」），与本条字面冲突——顶栏全站搜索是否实现、文档页内检索是否保留，待 U-5 一并裁决）。
3. 导航栏上方无数据条 / 统计元素。
4. 项目名统一 "Aidean"。
5. 所有筛选即时生效，无确认按钮；首页数据走缓存。
6. **价格透明**：前台展示价格必须与各模型服务平台官方价完全一致；平台加价率与 Token 倍率对用户不可见（后台敏感配置，不出现在任何公开接口）。
7. **评测分数可信度标注（provenance）**：所有 benchmark 数据必须标注数据来源（sourceType）与核验状态（verifiedStatus）；未核验数据（verifiedStatus=0）在前台展示时必须有「演示数据」标识，且不得使用「官方测试」等暗示权威来源的文案；只有 verifiedStatus=1 的数据出现在天梯图排名计算中。
8. **端口口径（C-5，ADR-P006）**：Aidean 本地与部署端口固定在 3000–3100 段（默认 3000）；BotHot 回调保留 3200 段；AideanBot 3333 回调是否保留待 P-2 裁决。
9. **非功能要求（C-6 / U-13）**：本文不设无基线的数值目标；性能与质量以《任务规划》`11_基线指标.md` 的首测值为基线（如 web 单测覆盖率 Lines 67.06% / Branches 79.7%），优化任务须先有基线。

## 六、MVP 定义

**MVP = 天梯图（两类榜单）+ 用户系统（邮箱登录、三级等级）+ 余额系统 + 统一计费网关 + 测评对比 + 套餐兑换 + 兑换码**。

> v1.16（C-1 / U-11）：微信扫码登录与在线支付（微信 / 支付宝）**暂停**，移出当前 MVP；恢复时须用户裁决并重开对应任务卡。

> 更新说明（v1.11）：原 MVP 定义将「测评、对比、套餐兑换、兑换码」列为延后项，但实测均已实装——evaluations API 3 条路由 + evaluation service 440 行 + admin packages + redemption-codes 5 条路由 + package/redemption 子域实装——故纳入 MVP 范围。仅「平台产品展示」「桌面端」仍延后。
