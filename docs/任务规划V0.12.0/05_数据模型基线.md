### 2.1 `monitor_run_requests`
| 字段 | 类型 | 可空 | 默认 | 约束 |
|---|---|---|---|---|
| id | uuid | 否 | uuid v7（应用侧） | PK |
| source_key | varchar(40) | 否 | — | FK → monitoring_sources.key（ON DELETE CASCADE） |
| status | varchar(16) | 否 | 'pending' | CHECK IN ('pending','running','done','failed') |
| requested_by | uuid | 否 | — | 管理员 user id（不建 FK，与审计口径一致） |
| result_count | int | 是 | — | ≥0 |
| error | varchar(2000) | 是 | — | — |
| created_at / started_at / finished_at | timestamp(3) | 否 / 是 / 是 | now() / — / — | — |

索引：`UNIQUE (source_key) WHERE status IN ('pending','running')`（幂等键）；`(source_key, created_at DESC)`（运行历史分页）。生命周期：保留 90 天，由 monitor_catalogs 每次执行顺手清理 `finished_at < now()-90d`（不新增调度项）。无软删。

### 2.2 `reliability_observations` 唯一键
- 先去重：按 `(entity_type, entity_id, window_start)` 分组保留 `created_at` 最新一行；**删除行数 >1000 → 迁移中止**（`RAISE EXCEPTION`），交用户决定（T120-13 熔断）。
- 再建：`UNIQUE (entity_type, entity_id, window_start)`；写入改为 upsert（批 100）。
- 窗口口径沿用 TASK-099：上海自然日 `[00:00, 次日 00:00)`。

## 三、查询路径与索引核对
| 查询 | 索引 |
|---|---|
| 调度领取：`WHERE status='pending' ORDER BY created_at LIMIT 1 FOR UPDATE SKIP LOCKED` | 部分唯一索引覆盖（每源 ≤1 行未完成） |
| 运行历史：`WHERE source_key=? ORDER BY created_at DESC` | `(source_key, created_at DESC)` |
| 可靠性 7 日：`WHERE entity_type='station' AND entity_id=? AND window_start >= ?` | 新唯一索引前缀 + 既有 `(entity_type, entity_id)` |
