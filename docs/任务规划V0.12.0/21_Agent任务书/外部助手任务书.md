## 二、Git 流程（每张卡都照做）
1. 只用自己的独立克隆；远端只认 `origin = https://github.com/nevermeetagain/Aidean`，只推 `main`，**禁止新建分支**。
2. 开卡前：`git status` 干净 → `git fetch origin` → `git rebase origin/main`。
3. 一卡一组提交，提交信息以卡号开头（如 `T120-03: …`）。
4. 推送前：再 `git fetch origin && git rebase origin/main` → 跑卡面「验证命令」+ 全量 tsc/lint/vitest + docs-rule/facts 一次 → `git diff --name-only origin/main...HEAD` 逐个对照卡面「允许修改」→ `git push origin HEAD:main`。
5. 被拒（non-fast-forward）：重复第 4 步；**禁止** `--force` / `--force-with-lease`。
6. 403 / 认证失败：立即停手报用户，不碰凭据、不换远端。
7. 冲突只在自己改过的文件里解；碰到 Hark 正在改的文件（见 09_所有权矩阵）→ 停，报 Hark。

## 三、纪律
- 端口：dev/e2e 只用 **3000**；被占用就停并报告占用进程，**不得换端口**。测试库用 55432。
- 熔断：同一验收连续 2 次失败 → 停止改代码，写清现象和已试过什么，标 blocked，报 Hark。
- 发现真缺陷（不是用例过期）→ 只登记到本卡 EVD 并抄送 Hark，不在本卡修源码。
- 证据：`06_validation/evidence/EVD-T120-xx/verify.txt` ≤40 行（命令 + 退出码 + 关键读数）；有偏离才写 `deviation.md`，每条 ≤5 行。
- 卡完成后在 `05_execution/task-index.md` 把状态改为「待验证」并附提交号；由独立验证者改为「已合并」。
- node_modules 空壳（RK-11-09）：跑一次归档修复命令，保留日志，不做归因调查。
