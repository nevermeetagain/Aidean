本文是 `/api/v1/gateway/chat` 全链调用时序的**唯一权威口径**，为网关域（`apps/web/lib/features/gateway/*`）与账本域（`lib/features/billing/*`）并行开发的文字 Contract：改时序先改本文，再改代码。

## 1. 调用时序（正常路径）

```
requireUserApi(鉴权)
→ 双格式 parse（OpenAI/Anthropic，失败 40000）
→ requestId 查重（usage_logs.requestId 唯一；已存在 → 40000 换键重试）
→ 渠道优先：isActive CustomChannel 直调（FREE_PROXY，免扣）
→ resolveRouteChain（请求模型链首 → 等级映射/优先级合并 → free 兜底）
→ listActivePackageStations（读取用户生效套餐覆盖面，一次）
→ 逐候选：站点(rating 序) × Key(加权挑选)
   ├─ StationBillingRule.billingMode=UPSTREAM → 用户自有 Key 直调（GW-KEY-01）：有有效 Key → 免扣直调上游；无 Key/失败/stream → 续降级
   ├─ 套餐覆盖本站（或平台通用）→ billingPath=PACKAGE（免扣）
   ├─ FREE 候选 → billingPath=FREE_QUOTA（免扣）
   └─ 其余 → billingPath=PLATFORM（高估预扣 hold）
→ 上游调用（非流 callUpstream / 聚合 callUpstreamAggregated / 透传 callUpstreamStream）
→ 结算：PLATFORM 按实 tokens ×(单价×加价率×倍率) captureHold（0 消耗 voidHold）；免扣路径跳过
→ 落用量：UsageLog 一条（requestId 幂等锚点，cached/reasoning tokens 细分）
→ 沉淀：UsageDailyStat 当日聚合 upsert（仅成功请求；失败不进成功口径聚合）
```

## 2. 五态 billingPath 语义

| billingPath | 扣费 | 写 UsageLog | 写 UsageDailyStat | 触发条件 |
|---|---|---|---|---|
| PLATFORM | hold→capture/void | ✅（quotaMinor=实扣） | ✅ | 站点规则 PLATFORM 且无套餐覆盖 |
| PACKAGE | 免扣（quotaMinor=0） | ✅ | ✅ | PackageOrder ACTIVE 且未过期，覆盖本站或平台通用 |
| UPSTREAM | 免扣 | ✅（stationId 归因，GW-KEY-01） | ✅ | billingMode=UPSTREAM 且用户有有效自有 Key（station_user_keys）；无 Key/上游失败/stream=true → 续降级；仅非流式 |
| FREE_PROXY | 免扣 | ✅（channelId 归因） | ✅ | 用户 isActive 自定义渠道；仅非流式 |
| FREE_QUOTA | 免扣+扣周期额度 | ✅（modelId 归因） | ✅ | free 候选；成功后 UserQuotaUsage 当期累加 |
| **billingExempt** | **免扣** | ✅（quotaMinor=0） | ✅ | `executeChat(..., { billingExempt: true })` → PLATFORM 站**跳过 hold/capture**，usage_log 仍写（tokens/station 归因）。#26 仲裁定论：评估域独占 ¥2/模型 计费，网关内部调用不重复扣 |

金额口径：`quotaMinor` = Σ(输入/输出单价 × tokens) × markupRate × tokenMultiplier（calcCharge，BigInt 分）。价格取 `isCurrent=true` 当期价（`effectiveFrom` 降序取 1）；价格数据问题上报，不在网关内改价。

**§2.1 usage 归一与日汇总口径**（并自《网关计时序契约》v1.0，2026-09-28 双真源仲裁收口）：

- usage 统一形状：`{ promptTokens; completionTokens; cachedTokens?; reasoningTokens? }`；归一源 `normalizeUsage`（shared schema）覆盖 OpenAI 官方 `prompt_tokens_details.cached_tokens`、DeepSeek 兼容 `prompt_cache_hit_tokens`、`completion_tokens_details.reasoning_tokens`、Anthropic 上游 `cache_read_input_tokens`/`cache_creation_input_tokens`；缺省 `cachedTokens ?? 0`、`reasoningTokens ?? 0`，上游 usage 缺失 → 0/0（宽松：不因计费字段异常丢弃成功响应）。
- 落库规则：明细行存原生 + 归一双份；汇总行只存归一；**`reasoningTokens` 计入 completion 计费**。
- 日汇总粒度：`userId × model × day`，`day` = 本地零点（与 free 周期口径一致）；入口唯一 `recordDailyStat`，重试/重放按 requestId 幂等；失败请求不进成功口径聚合。
- **已闭环（v1.5 更新）**：`ProviderModelOffering` 新增 `discountCacheMin/Max` 字段（migration `20260928180000`），缓存命中折扣价数据结构已与输入/输出对齐。前台 providers 页面与 admin 面板已展示缓存折扣价列。扣费链路接入 `priceCache` → `calcCharge` 仍为后续工作项。

**UPSTREAM 路径（GW-KEY-01）**：候选站 `billingMode=UPSTREAM` 且用户在该站存在有效自有 Key（`station_user_keys`，userId+stationId 唯一，AES-256-GCM 密文落库、密钥 JWT_SECRET 派生）→ 调上游前解密直调（复用 callUpstream 超时/30004 归一），**不 hold/capture——平台余额逐分不变**；成功照常写 UsageLog（billingPath=UPSTREAM、quotaMinor=0、stationId 归因）与 UsageDailyStat。无有效 Key / 上游失败 / stream=true（UPSTREAM 流式属二期，同 FREE_PROXY 非流式口径）→ lastError/lastPath 记录后 continue，按既有「换站→降级」序续行，全链败仍 30003。chat 双通道鉴权（requireGatewayPrincipal）：`Authorization: Bearer aid_ak_…` / `x-api-key` → 平台 API Key 校验（库内只存 HMAC-SHA256 哈希；无效/吊销/过期 → 401(10004)、缺 `gateway:chat` → 403(10008)、Key 级固定窗口限流 `rl:apikey:<keyId>:min` 超限 → 429(10006)，缺省 60 req/min）；无头 → 回落 JWT cookie，计费口径与 cookie 态完全一致。

## 3. 幂等与并发

- 幂等键：usage_logs.requestId 全局唯一；hold 幂等键 `gw:{requestId}:a{n}`（attempt 序号）；透传长窗口标记 `{holdKey}:stream-final`（1 分兜底冻结，终态化时全额 void）。
- 重放：同 requestId 再入 → 40000，上游零调用、零扣费。
- 并发同 requestId 双写：hold/capture 按 requestId 幂等 → 账面只扣一次；上游可能被调两次，MVP 接受（透传网关不做上游侧幂等）。

## 4. Key 生命周期（摘除/恢复闭环）

- `listAvailableKeys`：ACTIVE 或**冷却到期的 COOLDOWN**（cooldownUntil ≤ now）参与加权分流；DISABLED 永不参与。
- 失败：上游错误(30004) → `failureCount++`；达 `KEY_FAILURE_THRESHOLD(5)` → status=COOLDOWN + `cooldownUntil=now+KEY_COOLDOWN_MINUTES(5min)`，同请求即刻 failover（换 Key/换站/换候选）。
- 恢复：冷却到期自动回池；回池后首次成功 `markKeySuccess` 复位 ACTIVE、清零计数、清 cooldownUntil。

## 5. 流式时序（聚合 / 透传）

- 聚合（默认，`AIDEAN_GATEWAY_STREAM_PASSTHROUGH≠1`）：上游 SSE 攒流归一为非流式同形状 JSON；hold/capture/UsageLog 与非流同口径，`isStream=true`。尾帧 usage 缺失 → 按估算 tokens 保守记账（防漏记）。
- 透传（开关=1）：首字节即置 `:stream-final` 标记 hold → 边透传边计量（尾帧 usage/已产出字符）→ 流终态化：usage 实扣（缺失按已产出估算）、`finalizeStreamUsageLog` 回填（metadata.finalize = OK/ESTIMATED/ABORTED）→ 标记 hold 解冻。客户端断连（AbortError）仍按已产出 capture，不留 AUTHORIZED 孤儿。

## 6. 异常分支结算动作

| 分支 | 账面 | Key | 链路 |
|---|---|---|---|
| hold 时 40001 余额不足 | 无 hold | 不计数 | 移除付费候选（skipPaid），free 兜底续行 |
| 上游失败(30004) | voidHold 全额解冻 | failureCount++（阈值冷却） | 换 Key→换站→换候选 |
| 非上游异常（账本/编程） | voidHold 后上抛 | 不计数 | 终止（50000/原码） |
| 全链失败 | 各次 hold 均 void | — | 30003 + 失败 UsageLog（error 非空，quotaMinor=0，不进日汇总） |
| 透传断连 | 按已产出 capture | — | finalize=ABORTED |

## 7. 账本 Contract（网关只读调用，禁直写 wallets/ledger_entries）

```
billingService.hold(userId, requestId, amountMinor, now) → { holdId, idempotent }   // 40001=余额不足
billingService.captureHold(requestId, actualMinor, now) → { capturedMinor, idempotent } // 40004=hold 失效；actual>预扣 40000
billingService.voidHold(requestId) → { idempotent }                                   // 全额解冻，无流水
```

错误码段位：网关 30002 无路由 / 30003 全链失败 / 30004 上游错误；财务 40000/40001/40004。错误码增补须先登记《API接口文档》错误码表。

## 8. 安全红线

- 敏感字段永不序列化：`markupRate/tokenMultiplier` 仅 admin 面；渠道视图 `apiKey` 恒 `maskApiKey` 掩码（T3 后读 `key_masked` 列，不再读明文 `api_key`）。
- 自带 Key 不落明文日志：UsageLog/错误消息/metadata 均不含 Key；上游错误体截断 300 字。
- **T3 已收口（2026-09-16）**：`CustomChannel.apiKey` 明文债已按方案 B 清还——新增 `key_cipher`（AES-256-GCM，密钥 SHA256(JWT_SECRET) 派生）/`key_masked` 列；saveChannel 写侧 `encryptSecret`，executeChat FREE_PROXY 读侧 `decryptSecret(keyCipher) ?? apiKey` fallback 旧行；旧 `api_key` 列标记 deprecated 存掩码非明文；迁移 `0002_encrypt_custom_channel_key`。`StationKey.keyValue` 明文债仍在册（平台站 Key 池，属独立工作包边界）。

## 9. 验收对照（本契约对应证据）

同 requestId 重放不二次扣费（orchestrator spec）；流式中断按实际 token 结算、多余释放（stream-passthrough spec ①②③）；故障 Key 摘除切换、cooldownUntil 后恢复（gateway-svc spec Key 摘除/恢复 + orchestrator 冷却切换）；五态 billingPath 正确可解释（orchestrator PACKAGE×2 / UPSTREAM 跳过 / FREE_PROXY / FREE_QUOTA 用例）。并自《网关计时序契约》v1.0 并入：`stream-parse.spec.ts` 24 用例 + `fe01-console-call.spec.ts` 5 条 e2e 为 FE01 验收锚点；turbo shared 9/55 + web 38/363 全绿为入库线（历史计数，现行基线以《测试与验收文档》§13.8 为准）。

## 10. 前端告知义务（FE01，并自《网关计时序契约》v1.0）

1. 流式开关：默认走聚合回退，必须显式告知用户"无增量更新"（spec 断言）。
2. 余额为 0：预检闸门可见 + 提供充值入口（spec 断言）。
3. 调用失败：实扣文案只能是"以流水为准"或 `¥x.xx`（spec 断言：`charge === "以流水为准" || /^¥\d+\.\d{2}$/`）。
4. 视口：控制台在 360/768/1280 三视口无横向溢出、关键控件可聚焦（spec 断言）。
5. 死链：`/models` 卡片可达详情；`/ladder` stations 卡片不再链向模型详情（spec 断言）。

变更本契约必须同步更新 shared schema + service + FE01 spec，不得单边改。
