## 1. 总体架构

**Monorepo 分包**（ADR-0002，2026-08-26）：`apps/web` 为 Next.js 15 全栈应用（页面 + API Routes），共享能力下沉 `packages/*`（shared=类型/DTO/Zod 契约、ui=组件库、config=工程配置）：

- **Server Components + ISR**：天梯图榜单、模型详情等公开页面走 SSR/ISR，保证 SEO 与首屏。
- **API Routes**：`/api/v1/*` 对外提供 REST 接口，供 Web 客户端、未来的桌面端/移动端复用。
- 前后端分离形态 = **代码物理分包**（packages 边界），非部署分离；保留升级通道（网关流量证明需要独立伸缩时新增 `apps/api`）。

```
浏览器/客户端
   │
   ├─ 页面请求 → apps/web Next.js Server Components（SSR/ISR）→ Service → Repository → PostgreSQL/Redis
   └─ API 请求 → apps/web API Route（校验/鉴权/响应归一化）→ Service（业务编排）→ Repository → PostgreSQL/Redis
                    ↕ 类型/DTO/常量契约 ← packages/shared（Zod schema 唯一真源）
```

**架构图**：[archive/aidean-architecture.html](./archive/aidean-architecture.html)（archify 生成，showcase 9/9 校验）— 用户/管理员经 Nginx HTTPS 进入 Next.js 全栈单应用；应用经 Prisma 访问 PostgreSQL（50 model / 35 enum，public schema；口径以《数据库文档》§二 为准）与 Redis（缓存/限流/会话）；数据同步定时采集模型/模型站数据；统一计费网关代理转发至上游大模型服务平台；微信承担扫码登录与支付。

## 3. 后端分层三原则（继承旧体系）

1. **API Route**：只做参数校验（Zod）、鉴权、响应归一化，不写业务逻辑。
2. **Service**：业务编排、事务、计费、排名计算。
3. **Repository**：数据读写、分页、聚合；统一继承 base repository。

对应目录：`apps/web/app/api/v1/*` → `apps/web/lib/features/*/service.ts` → `apps/web/lib/features/*/repository.ts`（feature 自含分包，见《目录结构文档》§五）。

## 4. 关键架构决策

### D1：数据层从"原生 SQL"回归"Prisma + SQL 初始化并存"

- 旧半成品 package.json 声明 Prisma 但仓库无 schema.prisma，实际是原生 SQL 脚本（docker/sql/init/，约 60 张表）。
- 新架构：Prisma schema 作为应用层数据模型真源（反向工程自旧 SQL）；旧 SQL 中的触发器、分区、扩展等 PG 特性继续以 SQL 脚本形式由 docker 初始化承载。
- 取舍：获得类型安全与迁移管理；代价是触发器等数据库逻辑不进入 Prisma 管理体系，需文档同步（见《数据库文档》）。

### D2：同步管线（sync）作为独立模块

- 旧体系的 `lib/sync`（adapters/mappers/writers/orchestrator/scheduler/diff-engine）是核心特色：从 OpenRouter、LMArena 等外部源同步模型/价格/评分。
- 新架构保留该模块边界：adapter 对接外部源 → mapper 映射 → writer 入库，orchestrator 编排、scheduler 定时、diff-engine 增量。

### D3：i18n 重做而非修补

- 旧体系为自研字典 + 一个返回 key 原样的 stub hook，且声明了 ja 但无字典。
- 新架构：保留"字典文件 + getTranslations"的轻量思路（中英双语即可满足 .design.md），但补齐真正的 hook/上下文实现；不引入 next-intl 以避免过度设计。后续若需多语言再升级。

### D4：认证 JWT + API Key 双模式（继承旧 API 体系）

- Web 会话用 JWT（邮箱 + 密码 / 微信扫码，同一签发体系）；统一计费网关调用用 API Key。
- 统一计费网关是 .design.md 第 6 条的核心能力（MVP）：双模式供给（用户自有 Key 优先，平台 Key 池兜底）、优先级路由与故障降级、计费三路径（本系统计费 / 上游计费 / 套餐直连）、OpenAI ↔ Anthropic 协议中转；详见《功能设计文档》§3.6。

### D5：缓存策略

- Redis 承担：榜单查询缓存（ISR 之外的运行时缓存）、API 限流、网关路由的可用性状态。
- 模型站可用率/好评率等聚合数据走定时刷新，不实时计算。

### D6：前后端分离采用 Monorepo 分包（ADR-0002，2026-08-26）

- **形态**：`apps/web`（Next.js 全栈）+ `packages/shared`（Zod 契约/类型/常量/纯函数）+ `packages/ui`（组件库）+ `packages/config`；代码物理分包即"前后端分离"，保留 SSR/SEO，不破技术栈锁定。
- **分层复用**：基础层强制复用；业务层按 feature 隔离（`lib/features/*` 自含 service/repository/schema）；业务组件三次重复才提升公共（防过度抽象）。
- **高性能目录红线**：业务代码禁 barrel file；重库动态 import；`'use client'` 下沉叶子；路由目录即代码分割边界。
- **旧代码处置**：`src/` 归档至 `.example/history/current-legacy/`（只读），按新蓝图全新实施。
- 详细蓝图见《目录结构文档》v2.0。

### D7：客户端会话层（B11-06，2026-10-22，DEF-011-08 / Q-11-02=B）

- **问题**：令牌 Cookie（`aidean_token`/`aidean_refresh`）为 HttpOnly，站点页受 ISR 约束不能在 RSC 读 `cookies()`，客户端只能每页盲探 `/api/v1/auth/me` 与 `/api/v1/user/favorites` → 游客每页 2 条 401。
- **契约不动**：`/api/v1/auth/me` 对匿名仍返回 401（REST 语义）；收敛全部在客户端与 middleware 的「存在性提示」上完成。
- **会话提示 Cookie**（`lib/features/auth/session-hint.ts`）：middleware 按「access 或 refresh 令牌 Cookie 是否存在」同步一枚非 HttpOnly 的 `aidean_session_hint=1`（只表达存在性、不含令牌；状态一致时不写 Set-Cookie，不污染可缓存响应）。它**不是凭证**：伪造只会多一次 401 探测。
- **单一会话 store**（`lib/features/auth/session-store.ts`，框架无关；React 绑定 `hooks/useSession.ts`）：
  1. 已定案 → 直接返回缓存（SPA 内跨页、跨组件复用）；
  2. 无提示 Cookie → **零请求**定案匿名（游客路径）；
  3. 有提示 → 模块级单飞探测一次 `auth/me`；401/403 时先走一次 `refreshSession()`（同 tab 单飞 + 跨 tab 锁）再复探；5xx/网络 → 降级匿名、聚焦重试；
  4. `markLoggedIn()`/`markLoggedOut()` 在登录/登出流程显式失效并写/删提示；跨标签 BroadcastChannel（`aidean.session`）优先、`storage` 事件兜底；
  5. 聚焦/可见性复核只在「提示与已知态矛盾」或「已登录态超过 5min」时发请求（替代原 SWR 无差别 `revalidateOnFocus`）；
  6. 代际计数丢弃飞行中被登出/登录作废的结果；`onTransition` 供其他仅登录数据层（收藏等）在身份切换时重置/重载；`seed()` 预留给已知会话的服务端页面注入。
- **消费方**：`components/site/HeaderSession.tsx`（头部登录态）、`hooks/useFavorites.ts`（已知匿名跳过 `/user/favorites`）、`components/auth/AuthForm.tsx`（登录成功 `markLoggedIn`）、`components/site/UserMenu.tsx`（登出 `markLoggedOut`）。管理端登录/登出组件未接入（由 middleware 提示同步 + 整页跳转自愈）。
- **已知残余**：持有失效/已撤销令牌 Cookie 的浏览器（非游客）每次整页加载仍会有 1 次 `auth/me` 401（+1 次 refresh 失败），直至 Cookie 过期——这是 Q-11-02=B 下不可再省的权威探测。
- 新增模块须经 `sessionStore.whenSettled()` 取会话定案后再决定是否发仅登录请求，不得自行探测 `auth/me`。
