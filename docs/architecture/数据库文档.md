## 一、设计规范（调研结论，全表通用）

| 规范 | 内容 |
|---|---|
| 主键 | `@default(uuid(7))` UUIDv7（应用层生成，PG16 兼容，时序有序利索引） |
| 金额 | 一律整数最小单位（分）`BigInt *Minor` 字段；禁止 Float/Decimal 存余额 |
| 计费架构 | 账本三表分离：`wallets`（状态）/ `ledger_entries`（不可变双录流水）/ `balance_holds`（预扣） |
| 幂等 | `ledger_entries(walletId, idempotencyKey)`、`balance_holds.requestId`、`usage_logs.requestId` 三处唯一约束兜底 |
| 并发 | 乐观锁仅用于可变状态表（`wallets.lockVersion`）；流水表不可变故无需 |
| 软删除 | `deletedAt` 仅用于内容/配置类表；流水/用量/账本表禁用 |
| 审计 | 核心表带 `createdAt/updatedAt`；后台管理表带 `createdBy/updatedBy`；全量变更走 `audit_logs` |
| 命名 | Prisma 驼峰 + `@map` snake_case；表名复数 |

## 二、表清单（按域，共 **74 model / 37 enum** / public schema）

> **表数口径更正（2026-09-22 实测）**：本节原记「共 35 model」有误——35 实为 **enum** 数。实测 `grep -c "^model " prisma/schema.prisma` = **50**、`grep -c "^enum "` = **35**；与《测试与验收文档》§13.5 与台账 #4 的「50 表」口径一致（后者为 `migrations` 重放后的物理表数，含 schema 内 model 全部产出）。另注：《功能设计文档》§2 与《技术架构文档》§1 所述「52 表」为历史口径，**以本表 50 为准**。**2026-09-29 更新**：provider-pricing 轮新增 `model_providers`/`provider_model_offerings` 两表、#71 新增 `ProductCategory` enum，实测 **64 model / 36 enum**，现行口径以本数为准。
