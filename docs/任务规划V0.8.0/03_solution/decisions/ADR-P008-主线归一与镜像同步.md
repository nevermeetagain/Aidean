> V0.8.0 承接说明（2026-10-19）：本文件正文为 **V0.7.0 历史表述**（基线 ffa158c，业务树 77c7952），其中的「现状/镜像/待执行」均指当时；**当前事实以 V0.8.0 的 `02_事实基线.md`、`03a_统一需求追溯矩阵.md`、`24_叠加同步与开发线裁决.md` 为准**。契约唯一源仍为 `docs/任务规划V0.5.0/contracts/`（终审 Q1 逐字核对一致）。

- 状态：**提议**（待用户裁决 B-0）
- 背景：见 `../../23_主线二元分裂与归一方案.md` §1–§2。
- 决策（提议）：
  1. 任何实现卡开工前，必须完成 TASK-085，使「执行目标仓」与「规划推送仓」为同一棵业务树。
  2. 镜像历史只追加：快照同步以普通提交 + 快进推送完成，禁止 --force。
  3. 契约唯一源暂留 `docs/任务规划V0.5.0/contracts/`（他线 CI 据称直读该路径）；是否迁至 `packages/contracts/` 记为 U-20，归一后再议。
  4. 他线已完成的卡，只能由独立验证者（TASK-086）按卡内验证命令判定关闭，不以他线 EVD 或口头声明为准。
- 后果：S0 前增加 2–8h；方案B 可能节省最多约 70h 的 S0/S1 实施。
- 被否决的备选：直接在镜像继续实现（会与他线并行冲突）；把 huaweicloud 强推为镜像 main（改写镜像历史，丢失 V0.1–V0.4 文档链）。
