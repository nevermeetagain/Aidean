## 16.1 第一刀：S0 步行骨架与契约守卫

**为什么是它**（证据见 06、08）：
- TASK-001 是 43 张卡的祖先，TASK-006 是 19 张卡的祖先——不先做，后续并行无共同中间语言、无可复现的判定环境。
- S0 九张卡中 8 张为外部Agent 的小/中卡，风险低；唯一的 Hark 卡（001）是契约语义决策。
- 完成后的可演示行为：CI 空库重放迁移 → :3000 启动 → ready=200 → 注册登录 → 建 API Key → 控制台可见 → 匿名得统一错误信封。

## 16.3 每批下发给执行者的材料（最小上下文）
1. 对应任务卡 `05_execution/tasks/TASK-xxx.md`（唯一指令）；
2. 卡中「输入·契约」引用的 `contracts/*.contract.ts` 片段（或已落地的 packages/shared 文件）；

执行者不需要、也不应阅读其他卡；遇到卡内「阻塞条件」立即停止并回报。
