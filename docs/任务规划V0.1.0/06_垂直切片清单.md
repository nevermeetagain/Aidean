## 排序理由（先解锁依赖多的、先做不确定性高的）

1. **S0 第一**：步行骨架是「完成」的判定基础（无真库 e2e，后续每刀的 Done 都无法被独立验证者复现）；TASK-001 是 43 张卡的祖先（DAG 计算），TASK-006 是 19 张卡的祖先。S0 满足步行骨架六要素：健康/就绪检查（TASK-003）+ 鉴权写接口（既有 POST /user/api-keys，经 TASK-005 端到端复验）+ 一张表（api_keys）+ 一次迁移（空库重放迁移链，TASK-006）+ 前端打真实 API 的页面（/user/console）+ 统一错误响应（TASK-001/002 唯一源 + TASK-005 断言）。说明：项目已有完整骨架，故 S0 是「复验 + 加固」而非新建，第一刀不新建业务表（遵守 §13.13）。
2. **S1 第二（不确定性最高）**：唯一约束缺陷是静态推理结论，必须尽早在真库证实或证伪；它是 S4 的硬前置。TASK-010 证伪 → S1 其余卡取消、S4 直接依赖 TASK-010。
3. **S2 第三**：MUST 需求；其 `requireFeature` 被 S3 复用；改动网关入口，风险高，宜早暴露。
4. **S3、S4 随后**：S3 依赖 S2；S4 依赖 S1。二者同改模型详情页 → 串行（S3 先）。
5. **S5 在 U-5 裁决后**：不阻塞其他刀；与 S2 同改顶栏 → 排在 S2 后。
6. **S6 穿插**：只测量不优化（§9.1），给后续优化留基线。
7. **S7 收尾**：依赖用户裁决，且文档文件资源锁使其天然在末段。
8. **S8/S9 条件刀**：外部输入到位前不下发。
