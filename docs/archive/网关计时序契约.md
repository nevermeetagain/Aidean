# 网关计时序契约（v1.0 · WP-BE02/WP-FE01 落库依据）

> 真源：以本文件为准。调用链路、usage 口径、日汇总、事实头、前端告知义务，一律按此执行。
> 范围：`apps/web/lib/features/gateway/*`、`packages/shared/src/schemas/gateway.schema.ts`、
> `components/console/*`。落码：BE02（service/repository/schema）+ FE01（CallPlayground/UsageLedger/fe01 spec）。

## 1. 调用时序（chat/completions 统一入口）

```text
预检（余额/配额/网关可达/模型可调）
 → 上游请求（OpenAI 兼容 POST，超时/重试按端点策略）
 → SSE/JSON 归一（stream-parse：聚合回退路径必须显式告知无增量）
 → parseUpstreamUsage（宽松：缺失或形状异常计 0/0，不因计费字段异常丢弃成功响应）
 → 计费换算（prompt/completion 单价 × 倍率；cached 折扣按上游口径）
 → 落库三写（同事务/同日分区键：usage_log 明细 + 日汇总 recordDailyStat + 钱包流水）
 → 事实头回传（X-Usage-*：prompt/completion/cached/reasoning/charge/req-id）
```

任一环节失败：明细行可追（req-id 全链路透传），前端落"以流水为准"托底文案（FE01 spec 断言 `charge === "以流水为准" || /^¥\d+\.\d{2}$/`）。

## 2. usage 统一口径（唯一形状）

```ts
{ promptTokens: number; completionTokens: number; cachedTokens?: number; reasoningTokens?: number }
```

- 归一源：`normalizeUsage`（shared schema）：OpenAI 官方 `prompt_tokens_details.cached_tokens`、
  DeepSeek 兼容 `prompt_cache_hit_tokens`、`completion_tokens_details.reasoning_tokens`、
  Anthropic 上游 `cache_read_input_tokens` / `cache_creation_input_tokens`。
- 缺省规则：`cachedTokens ?? 0`，`reasoningTokens ?? 0`；上游 usage 缺失 → `0/0`。
- 落库规则：明细行存原生 + 归一双份；汇总行只存归一；`reasoningTokens` 计入 completion 计费。

## 3. 日汇总（recordDailyStat）

- 粒度：`userId × model × day`，`day` = 本地零点（与 free 周期口径一致）。
- 入口唯一：成功调用统一走 `recordDailyStat(userId, model, usage, quotaMinor, now)`；重试/重放幂等（req-id 去重）。
- 与余额页对账：`UsageLedger` 按同口径聚合，前端展示与流水一致。

## 4. 前端告知义务（FE01）

1. 流式开关：默认走聚合回退，必须显式告知用户"无增量更新"（spec 断言）。
2. 余额为 0：预检闸门可见 + 提供充值入口（spec 断言）。
3. 调用失败：实扣文案只能是"以流水为准"或 `¥x.xx`（spec 断言）。
4. 视口：控制台在 360/768/1280 三视口无横向溢出、关键控件可聚焦（spec 断言）。
5. 死链：`/models` 卡片可达详情；`/ladder` stations 卡片不再链向模型详情（spec 断言）。
