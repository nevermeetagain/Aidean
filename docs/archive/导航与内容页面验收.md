## 间歇性登录 401/10004 根因定位（记录，不改认证代码）

同一 curl 会话「登录 200 → 立即 auth/me 10004」与「3/3 全部通过」并存。证据：不同服务进程的 access JWT `kid` 不同（`8c897369…` → `3dfa09b4…`），即 dev 模式下签名密钥随进程/热重启重新生成，重启后旧密钥签发的会话即刻验签失败被判未登录。这与 api-auth-contract / sso-3333 间歇失败及本次闭环中一次还原 PUT 401 的现象一致。生产环境密钥来自持久化密钥束，不受影响；本仓库认证实现与测试断言零变更，问题作为环境事实保留。
