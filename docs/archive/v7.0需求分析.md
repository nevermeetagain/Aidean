## 二、5W1H 发散分析

### R-57 支付入口关闭

**What**：生产环境隐藏充值按钮，改为提示文案
**Why**：无商户凭证，不能真实收款
**Where**：RechargePanel.tsx 的「立即充值」按钮 + balance/page.tsx 的 isDev 传参
**When**：现在
**How**：RechargePanel 已有 isDev 分支——dev 显示 mock-pay，prod 显示「支付渠道接入中」。但「立即充值」按钮在两个环境都显示。需要：prod 环境下隐藏「立即充值」，显示「支付功能即将开放」
**风险**：不影响 dev 测试；prod 用户看到提示而非按钮

### R-58 邮箱组件修复

**What**：让 nodemailer 可正常 import，SMTP 配置后即可发信
**Why**：注册验证码邮件当前只打日志，用户收不到
**Where**：apps/web/package.json（添加 nodemailer + @types/nodemailer）、.env.example（SMTP_* 变量）、mailer.ts（已就绪）
**When**：现在
**How**：nodemailer 已在根 node_modules（pnpm workspace 安装），但 apps/web/package.json 未声明。添加声明后 tsc 可解析 `import('nodemailer')`。创建 .env.smtp.example 模板
**风险**：无运行时风险（SMTP 未配置时仍走日志兜底）

### R-60 每日备份

**What**：Docker 环境每日自动备份 PostgreSQL
**Why**：生产数据安全
**Where**：docker-compose.prod.yml（新增 backup sidecar）、scripts/db/backup.sh（已存在，扩展保留期）
**When**：每日 02:00
**How**：docker-compose 新增 `postgres-backup` 容器，基于 postgres:16-alpine，cron 定时执行 pg_dump → 本地 volume → 保留 30 份
**风险**：备份容器不影响主库运行

### R-71 聚合采集

**What**：新增聚合数据源适配器 + 3 个桩脚本真实实现
**Why**：当前仅 OpenRouter 单源，数据覆盖不足
**Where**：
  - 新增 adapters：ArtificialAnalysisAdapter、EpochAIAdapter、LLMStatsAdapter
  - crawl_models.ts：接入 additionalAdapters（HF + LMSys + AA + EpochAI）
  - crawl_agents.ts：新增 AgentIndexAdapter
  - crawl_mcp.ts：新增 SmitheryAdapter
  - crawl_skills.ts：新增 SkillsMPSAdapter
**When**：现在
**How**：每个 adapter extends BaseSyncAdapter，实现 fetch() + testConnection()。参考资料 1-3 提供了详细的源 URL 和字段映射
**风险**：外部 API 可能无响应或格式变化——adapter 内 try-catch，失败不阻断主同步

**钢人论证**：是否需要所有 16 个源？→ 否。用户说「聚合采集优于单个源头」，核心是 3-4 个聚合源（ArtificialAnalysis、EpochAI、OpenRouter、HuggingFace）即可覆盖 95%。agents/mcp/skills 是不同实体类型，需独立 adapter。

### R-72 排名脚本对齐 13 维

**What**：update_ranking.ts 改为调用 rankService.recap()
**Why**：当前脚本手写 2 维（benchmark/popularity），与 rankService.recap() 的 13 维加权不一致
**Where**：scripts/ranking/update_ranking.ts
**When**：现在
**How**：脚本直接调用 `rankService.recap()`，移除手写 computeComposite 调用。dry-run 模式改为预览 recap 结果
**风险**：无——recap 是幂等版本化写回

### R-69 非_admin 组件迁移

**What**：35 个非 admin 组件从手写 Tailwind 迁移到 @aidean/ui
**Why**：设计系统一致性
**Where**：components/{home,site,common,ladder,models,evaluations,console,auth,theme}/
**When**：本轮
**How**：逐组件替换 `<button>` → `<Button>`、手写 card div → `<Card>`、手写 badge → `<Badge>` 等。不改变组件行为，仅替换 UI 原语
**风险**：样式微调——@aidean/ui 组件的默认样式可能与手写 Tailwind 有细微差异

### R-70 调度触发器

**What**：Docker 添加 scheduler sidecar 容器
**Why**：ScheduledScript + runDueScripts() 已实现但无自动触发
**Where**：docker-compose.prod.yml（新增 scheduler 服务）
**When**：每分钟扫描到期脚本
**How**：scheduler 容器基于 node:alpine，cron 每分钟调用 `curl http://web:3000/api/v1/admin/scripts/run-due`（或直接 npx tsx runDueScripts）
**风险**：需新增 admin API endpoint 或直接脚本调用
