## 三、WF-2: 后端补齐（REST 规范 + 功能缺口）

### TP-2.1: 3 域 [id] DELETE 路由补齐 ✅

| 编号 | 文件 | 变更 | 安全设计 |
|------|------|------|----------|
| AT-2.1.1 | `api/v1/admin/redemption-codes/[id]/route.ts` | DELETE: 物理删除，须先禁用 | 仅允许删除 DISABLED/EXPIRED/USED 状态码 |
| AT-2.1.2 | `api/v1/admin/partner-keys/[id]/route.ts` | DELETE: 物理删除，须先停用 | 仅允许删除 isActive=false 的密钥 |
| AT-2.1.3 | `api/v1/admin/benchmarks/[id]/route.ts` | DELETE: 物理删除 | 管理员审核后移除无效/重复数据 |
| AT-2.1.4 | — | 三条 DELETE 均写 writeAudit (action=3) + tsc 0 新错误 ✅ |

**设计决策**：三个模型（Redemption / PartnerKey / Benchmark）均无 `deletedAt` 字段（schema 规定软删除仅用于内容/配置类表），因此采用物理删除 + 安全前置校验（须先禁用/停用）+ 审计日志的方案。

### TP-2.2: Benchmark CSV 批量导入结果增强 + 幂等修复 ✅

| 编号 | 文件 | 变更 |
|------|------|------|
| AT-2.2.1 | `BenchmarksManager.tsx` | handleImportCsv 响应类型扩展：skippedModels / total / syncBatchId |
| AT-2.2.2 | 同上 | 导入结果展示增强：跳过模型列表 + SyncBatch ID 展示 |
| AT-2.2.3 | `benchmarks/import/route.ts` | **幂等修复**：接收 `x-import-batch-id` header（可选），若已存在相同 importBatchId 的 Benchmark 则幂等跳过；未传入时仍生成 randomUUID（向后兼容） |

> **修复原因**：explorer-3 穿透发现 importBatchId 每次调用 `randomUUID()` 生成新值，注释声称的幂等性实际未实现。修复后客户端可通过 header 传入相同 ID 实现去重。

### TP-2.3: 3 个 batch 路由审计统一迁移 ✅

| 编号 | 文件 | 变更 |
|------|------|------|
| AT-2.3.1 | `models/batch/route.ts` | `prisma.auditLog.create()` → `writeAudit()`（补 actorId + requestId） |
| AT-2.3.2 | `news/batch/route.ts` | 同上 |
| AT-2.3.3 | `users/batch/route.ts` | 同上 |

> **修复原因**：explorer-2 穿透发现 3 个 batch 路由 import 了 `writeAudit` 但实际用 `prisma.auditLog.create()` 直接调用，遗漏了 `actorId` 和 `requestId` 字段。迁移至 `writeAudit()` helper 统一审计口径（含 BigInt 安全序列化 + 请求追踪）。

**说明**：服务端 CSV 解析器（parseCsv + import route）已完整存在（R-20 修复 + R-33 provenance），本轮仅增强客户端结果展示，未重复实现解析器。
