# 验收方案：身份、支付与微信

> 版本: v1.2 | 更新: 2026-09-17 | 变更: P2.1 依赖口径修正（开放平台资质→认证服务号微信认证资质，依据《登录方案-评审与决策》定版）。前次（v1.1）：细化me/refresh/admin各自状态、删除与版本检查边界；保留全入口验收。

总入口：[验收复核](验收复核-20260917.md)。角色：身份/计费负责人实施，QA独立核验。以下验证使用隔离账号、数据库及服务商沙箱。

## 阶段 A：统一身份撤销契约

### Task A1 封禁及版本失效

#### A1.1 普通会话核查账号与版本
- 【目标】兑现封禁全端失效，不仅退出前端。
- 【范围】apps/web/lib/features/auth/session.ts:23-54、tokens.ts:163-189；契约 docs/API接口文档.md:156。
- 【验收】ACTIVE/未删除/版本一致才放行；封禁、删除、旧版本令牌拒绝；确定即时或有界撤销时限。
- 【验证命令】扩展session/route单测并运行分包Vitest；隔离集成检查各用户业务入口。
- 【产出】共享账号状态守卫与撤销矩阵。
- 【依赖】质量方案Q1；缓存设计不得突破批准时限。

#### A1.2 API Key 继承账号禁用状态
- 【目标】堵住凭据仍有效但账号已禁用的契约缺口。
- 【范围】apps/web/lib/features/apikey/service.ts:143-161及guard调用者。
- 【验收】账号封禁/删除后Key请求拒绝；有效账号的签发、权限、吊销不回归；改密是否吊销Key有明确产品决议。
- 【验证命令】扩展apikey.spec.ts及隔离网关集成测试。
- 【产出】账号与长期凭据生命周期规则。
- 【依赖】A1.1。

#### A1.3 管理及跨端撤销回归
- 【目标】避免管理员或Bearer通道遗漏版本检查。
- 【范围】session.ts:64-101、auth/me:14-17、refresh:50-53及SSO守卫。me查状态但不比ver；refresh查状态/ver；repository.ts:37-44,74-75未投影deletedAt；admin查状态/删除/角色但未比ver，不能整体豁免。
- 【验收】禁用/改密/解封/刷新组合结果一致；解封不复活旧版本JWT；记录每一入口判据。
- 【验证命令】隔离账号状态矩阵＋SSO集成测试。
- 【产出】全入口撤销验收包。
- 【依赖】A1.1、A1.2、Q2.2。

### Task A2 身份扩展候选

#### A2.1 定义SSO二期边界
- 【目标】将back-channel登出、JWKS轮换、consent撤回从笼统候选变为可评审规格。
- 【范围】docs/未完成事项目录.md:36-38、子平台SSO接入指南、现有oauth/密钥代码。
- 【验收】逐项列当前实现、消费方、撤销时限、密钥重叠窗口、回退规则；本轮未完整审查，不能直接认定均无实现。
- 【验证命令】只读追踪端点/密钥读写/客户端调用，形成场景矩阵。
- 【产出】三个独立change-id候选，不提前建微服务。
- 【依赖】A1.3；具体实施另行批准。

## 阶段 P：真实支付与微信闭环

### Task P1 支付渠道

#### P1.1 接入异步真实下单
- 【目标】生产不再仅能报“渠道尚未接入”。
- 【范围】billing/service.ts:175-206、渠道适配层、shared契约；证据为production显式拒绝。
- 【验收】服务商沙箱下单可得有效支付凭据；超时/拒单保持可对账状态；渠道与账本编排分离。
- 【验证命令】适配器契约测试＋服务商沙箱下单记录。
- 【产出】批准渠道适配器；凭据不入库文档或日志。
- 【依赖】服务商资质/凭据、明确币种与商户配置。

#### P1.2 验证服务商原生通知
- 【目标】通知经过身份、订单与金额校验后才改变订单状态。
- 【范围】app/api/v1/billing/recharge-orders/[id]/notify/route.ts:17-38及新增专用回调。
- 【验收】签名、商户、订单、币种、金额和支付终态全部匹配；不匹配通知不入账。
- 【验证命令】沙箱原始通知样本及参数矩阵测试，不在共享环境重放。
- 【产出】服务商通知适配与验证测试。
- 【依赖】P1.1、shared契约先行。

#### P1.3 证明幂等入账与订单对账
- 【目标】重复/并发通知只形成一次充值。
- 【范围】billing service/repository、订单和ledger模型；契约 API接口文档.md:184。
- 【验收】重复与并发回调单次入账；事务失败可恢复；补单不双入账；服务商账单和平台分录可核对。
- 【验证命令】隔离PostgreSQL并发集成测试及沙箱对账；断言逐分一致。
- 【产出】真实支付验收包和异常处理手册。
- 【依赖】P1.2、资金方案F1。

### Task P2 微信扫码登录

#### P2.1 完成扫码状态生命周期
- 【目标】将有凭据仍返回STATE_INIT的桩变为真实状态机。
- 【范围】app/api/v1/wechat/qrcode/route.ts:13-23、登录UI、Redis状态及shared契约。
- 【验收】生成、等待、成功、过期、取消状态可观测；状态一次性绑定当前登录流程；缺配置继续安全降级。
- 【验证命令】状态机单测与沙箱扫码测试。
- 【产出】二维码生成/状态查询闭环。
- 【依赖】认证服务号微信认证资质（qrcode/create 仅认证服务号可调，见《登录方案-评审与决策》）、回调域名、凭据。

#### P2.2 完成回调、绑定和会话签发
- 【目标】微信与邮箱进入同一账号和JWT体系。
- 【范围】微信callback、身份映射、auth签发链路。
- 【验收】合法回调一次生效；重复/过期无重复用户；账号绑定冲突有显式规则；禁用账号不得签发。
- 【验证命令】隔离端到端：扫码→回调→me；增加重复、过期、绑定冲突用例。
- 【产出】微信登录验收包。
- 【依赖】P2.1、A1.3。
