## 二、天梯图核心概念

| 术语 | 含义 |
|---|---|
| **专业版 / 应用版** | 天梯图两套视图：专业版按技术类型（对话/多模态…），应用版按业务场景（办公/图片…） |
| **排行榜表格（矩阵式）** | 行=评分档位（从高到低），列=厂商，单元格=模型名 |
| **柱状图视图** | 横轴厂商、纵轴评分的并列可视化，与表格共用同一份数据 |
| **筛选栏** | 类型/协议/开源/测评集/标签/时间 六个即时生效的筛选器 |
| **综合评分** | 四维加权得分（官方/实际/风评/自测），默认各 25% 权重，后台可调 |
| **自定义排序公式** | 用户用 `${综合评分}` 等变量 + 运算符输入的公式进行排序 |

| 术语 | 含义 |

## 四、技术

| 术语 | 含义 |
|---|---|
| **App Router** | Next.js 13+ 的文件路由（基于 `app/` 目录） |
| **Server / Client Component** | Next.js 服务端组件（数据获取/SEO）与客户端组件（交互） |
| **Repository / Service** | 数据访问层（Prisma 封装）与业务逻辑层（Service Pattern） |
| **Zustand** | 轻量客户端状态管理，仅用于 Client Component |
| **ISR** | Next.js 增量静态再生成，用于产品介绍、帮助文档等低频变动页 |
| **Adapter / Mapper / Writer** | 数据采集三件套：数据源适配器、字段映射器、落库写入器 |
| <a id="term-envelope-exit"></a>**统一信封出口** | （B11-10）`/api/*` 的**一切**响应——含框架层的「方法未实现」与「路径未匹配」——都返回 `{code,message,data,requestId}` 信封：未实现方法 → HTTP 405 + `Allow` + `code=40000`（逐路由 `methodNotAllowed` 存根），未匹配路径 → HTTP 404 + `code=40000`（`app/api/[[...slug]]` 兜底）。见[《API接口文档》§4.1](../architecture/API接口文档.md#api-envelope-exits)、[《API架构设计方案》§7.14](../architecture/API架构设计方案.md#api-envelope-exits-architecture) |
| <a id="term-pagination-parse"></a>**分页参数解析** | （B11-11）查询串整数参数（`page`/`pageSize`/`limit`/整数过滤）的唯一解析口径 `apps/web/lib/http/pagination.ts`：`Number.parseInt`+`Number.isFinite` 双步、非法回退默认、区间钳制、`skip` 封顶，保证不把 NaN 送进 Prisma；守卫 `pagination-guard.mjs` 棘轮跟踪未接入端点。见[《API接口文档》§4.2](../architecture/API接口文档.md#pagination-params)、[《API架构设计方案》§五](../architecture/API架构设计方案.md#pagination-params-architecture) |
| **设计令牌单一命名** | （WF-18 / AT-18.1.2，2026-09-30 落地）CSS 自定义属性唯一命名空间：品牌前景色统一 `--primary-foreground`、危险语义统一 `--danger`，定义真源 `apps/web/app/globals.css`（`:root` + `[data-theme]` 变体；`@theme` 的 `--color-*` 仅为工具类生成命名空间）。组件库 `packages/ui` 禁止私设第二套令牌名（历史名 `--primary-fg` 已废弃，仅存于已标 DEPRECATED 的 `presets.css` 留档）；`cn()` 经 `tailwind-merge` 做类冲突消解，业务方与变体同组类冲突时后写入者胜出 |

## 六、统一计费网关

| 术语 | 英文 / 别名 | 含义 |
|---|---|---|
| **统一计费网关** | Gateway | 一次充值通吃所有接入平台：请求经网关路由，按计费规则扣余额（MVP 核心） |
| **双模式供给** | — | 优先使用用户自有平台 API Key，未配置时走平台 Key 池统一供给 |
| **平台 Key 池** | station_keys | 后台为每个平台配置多个 Key（`station_keys` 表），用于分流 / 并发 |
| **用户等级** | Tier | 普通 / Pro / Max 三级，后台按等级配置 free 模型、折扣与免费额度 |
| **Free 模型** | — | free 等级由系统后台定义用户默认使用的免费模型，控制台自动加载为最低优先级兜底；归一价输入输出均为 0 的免费模型跳过余额校验与预扣（U-23=B，见[《网关计费时序契约》§12](../architecture/网关计费时序契约.md#pricing-normalization)） |
| **免费额度** | Free Quota | 各 free 模型的免费用量上限（`user_free_quotas`），支持天 / 周 / 月刷新 |
| **模型等级** | Model Tier | Opus / Sonnet / Fable / Haiku 四档，固定序 Opus > Sonnet > Fable > Haiku；等级到具体模型的映射由**用户定义** |
| **通用版 / 专业版** | Console Modes | 控制台双形态，共享同一份底层路由配置：通用版将具体模型绑定至等级，专业版配置 1~99 优先级（等级默认映射 1/2/3/4 级） |
| **优先级路由** | Priority Routing | 按优先级 1~99 调用（1 最高），请求不通自动降级到次级优先级 |
| **平台加价率** | Markup Rate | 每站可配（默认 1.0 不加价）；后台敏感配置，用户不可见 |
| **Token 倍率** | Token Multiplier | 每站可配（默认 1.0）；余额扣费 =（上游单价×加价率）×（实际 Token 数×倍率） |
| **协议中转** | Protocol Relay | 网关出向上游协议适配：以 OpenAI 为中枢（hub-and-spoke）兼容 **OpenAI / Anthropic / OpenAI Responses / Gemini** 四种上游格式（2026-10-10 由两值扩为四值），同格式零拷贝透传、跨格式强制聚合回转。真源 [架构 §7.8](../architecture/API架构设计方案.md#upstream-protocol-quad-architecture) |
| **上游协议 / 接入体裁（正交）** | Gateway Format vs Access Format | 两套独立枚举：`GATEWAY_FORMATS`（**上游协议**，网关→供给渠道出向格式，现 4 值）≠ `GATEWAY_ACCESS_FORMATS`（**接入体裁**，客户端→网关入向格式，恒 4 值）。`normalizeAccessRequest`/`serializeAccessResponse` 管入向；`toUpstreamBody`/`toClientResponse` 管出向 |
| **自定义平台渠道** | Custom Channel | 用户自填 base_url + Key 接入任意平台（兼容 OpenAI / Anthropic / OpenAI Responses / Gemini 四种上游格式，`format` 列 `ChannelFormat` enum）；不扣余额（费用用户自理），无限制免费中转 |
| **API 渠道聚合** | API Channel Aggregate | 乙 后端统一：`GET /api/v1/user/channels` 一次返回「外部渠道」面板（原名「API 渠道」，2026-10-10 更名）全量渠道，`kind` 归一 `station`（`station_user_keys` join `api_stations`）与 `custom`（`custom_channels`）。**数据库为唯一事实源**，不合成 `catalog:<code>` 伪行（未落库平台在渠道列表不出现）；替代前端本地拼装 `/user/station-keys`+`/user/custom-channels`。真源 [API接口文档 §5.4 channels 行](../architecture/API接口文档.md) |
| **限时优惠** | Limited-time Offer | 合作平台对某模型的限时优惠，**直接影响计费价**（可能折扣或免费），随上游价格采集同步 |
| **套餐直连** | Package Direct Routing | 兑换某平台套餐后请求路由至该平台，按该平台计费规则计费（加价率与 Token 倍率不生效） |
| **兑换码** | Redemption Code | 后台生成、一次性核销：余额码（得余额）/ 定向套餐码（仅兑指定平台的指定套餐） |

## 七、内容展示

<a id="合作产品"></a>
### 合作产品

`/partners` 三个可配置展示位（学历助手、论文辅导、科研知识库），不等同于 Product 表的平台产品，不表示资质或效果背书。

<a id="systemconfig"></a>
### SystemConfig

既有数据库键值配置模型；合作内容以三个白名单键保存结构化 JSON 字符串，由共享契约验证，不需扩表。

<a id="safeimage"></a>
### SafeImage

应用共享图片组件，校验媒体 URL、限制显示比例与宽度、提供错误占位；原生浏览器加载，不代表上传服务或远程文件检测。详见 [合作内容说明](../product/design/合作产品内容配置.md#内容与媒体)。

<a id="newsitem"></a>
### NewsItem（资讯）

`news_items` 表的独立 Prisma 模型：`slug` 唯一、`title`/`summary`/`category`/`pinned`/`status`（PUBLISHED/DRAFT）/`contentMarkdown`。库内只存 Markdown 源文，HTML 仅前台 SSR 渲染时生成；编辑回读即库内原文。置顶条目恒排列表首位；DRAFT 与未知 slug 前台 404。详见 [架构 §7.3](../architecture/API架构设计方案.md#news-architecture)。

<a id="资讯分类"></a>
### 资讯分类

`NEWS_CATEGORIES` 共享常量白名单（热门/AI/硬件/软件/平台动态/功能更新/功能指引/官方公告）：后台仅可从中选取，前台 `/news?cat=` 仅白名单值生效；新增分类属白名单变更，需同步 `packages/shared` 常量与本页。「官方公告」（S7 迁库新增）承载 5 篇由 `static-articles.ts` 幂等迁入 `NewsItem` 的平台官方资讯。

<a id="登录通道"></a>
### 登录通道

| 术语 | 含义 |
|---|---|
| **登录通道** | 可插拔的身份核验方式注册表（`wechat_qr` / `email_code` / `password`）：通道只负责核验身份，成功后统一签发主平台 JWT 与 `aidean_token` 会话；见《登录方案-实施手册》 |
| **微信扫码登录** | PC 端登录方式：展示带参二维码，用户扫码触发公众号事件完成核验后换票签发会话；定版为主路线 |
| **带参二维码** | 公众号 `qrcode/create` 生成的含 scene_str 的临时二维码，经 `showqrcode` 换图；仅认证服务号可调；已关注用户扫码推 SCAN 事件，未关注推 subscribe（EventKey 带 qrscene_ 前缀） |
| **口令码** | 未认证公众号下的降级登录：用户向公众号发送一次性口令，凭文本消息回调核验身份 |
