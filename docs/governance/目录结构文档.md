## 一、设计原则

1. **Monorepo 分包 = 前后端分离的物理载体**：`apps/web` 承载 Next.js 全栈（页面 + API Routes）；共享能力下沉 `packages/*`；分包边界即 turbo 缓存边界，也是未来拆分独立 API 服务的边界。
2. **分层复用**：基础层（packages/ui、packages/shared、hooks、utils）强制复用；业务层按 feature 隔离不强行共享；业务组件第三次重复才提升为公共（三次法则）。
3. **混合式按类型存储**：路由层按 Next 约定、业务逻辑按 feature 自含（service/repository/schema）、基础层按类型——杜绝单目录文件堆积。
4. **高性能目录五细则**：分包=turbo 缓存边界；路由=代码分割边界；`'use client'` 下沉叶子；业务代码禁 barrel file（仅 packages 入口允许）；重库动态 import。
5. **文档即结构**：实际目录变更后必须同步本文档（铁律 6）。

## 六、复用与性能细则（实施红线）

| 细则 | 规则 |
|---|---|
| 类型契约 | 前后端共享类型一律来自 `packages/shared/src/schemas`（Zod → `z.infer`），禁止两端各写一份 |
| barrel file | 业务代码内禁止 `index.ts` 汇出；仅 `packages/*` 入口允许 |
| 动态 import | ECharts、xlsx 等重库一律 `await import()`；不进公共 bundle |
| 'use client' | 页面/区块组件默认 Server；仅交互叶子标 Client |
| 三次法则 | 业务组件重复第三次 → 提升到 components/common 或 packages/ui |
| turbo 管道 | build/lint/typecheck 按包配置缓存；改 shared 必须触发 web 重build（依赖图自动） |
