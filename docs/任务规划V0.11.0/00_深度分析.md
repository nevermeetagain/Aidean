### 1.2 Why —— 深层原因

- **现象 1+2 的根因是同一条链**：`fx.ts` 的口径是「无行或超陈旧上限 → null」，调用方 **fail-closed**。工程上 TASK-101 只交付了「采集器 + 单测」，**没有交付「入口 + 兜底 + 调度」**，于是功能代码存在而运行链路断裂。只补 seed 一行而不补脚本入口，下一次部署仍会 0 行——所以根因是**交付面缺一环**，不是数据缺失本身。
- **现象 3 的根因**：seed 生成器把演示模型价格默认置 0（免费），`modelPriceCurrency.original=null`。这使得 V0.10 辛苦交付的 U-15 计价口径（currency/unit/fx）与促销划线价在**运行态没有任何可观测样本**——单测能过，界面看不出来。根因是**种子数据形状与契约维度不对齐**。
- **现象 4+5+6 的根因**：协议/能力两张表是 M-002 批次建的表，但**既无采集器写入、也无后台写入路径**（API 只有 GET+POST，无 PATCH/DELETE），前端组件按「展示层」写而就，从未按「可运营模块」验收。因此它不是 bug 堆积，而是**模块完成度定义缺失**：没有 CRUD、没有错误态、没有 testid。
- **现象 7 的根因**：V0.10.0 的五态与 testid 治理（EVD-092/064/075）是**逐卡点状交付**，没有形成「后台面板规范基线」这一横切约束，导致覆盖呈孤岛。
- **现象 8+9 的根因**：`AdminDataTable` 解决了表格，但**表单三件套（Select/Textarea/Label）从未进过组件底座**，各面板只能各自复制 className；`Button` 的存在也不阻止就近裸写，因为没有门禁断言。
- **现象 10 的根因**：`/auth/me` 对匿名会话返回 401 在 REST 语义上正确，但客户端把它当作**每次导航都发的会话探针**，于是"正确的状态码"变成"每页红字"。根因是**探针语义与资源语义未分离**。

## 二、第二轮：收敛与苏格拉底式拷问

**拷问 1：「10 项异常是否都被最新代码证明？」**
依据：每项均给出文件:行号或 JSON 产物键。反证检索：`apicheck011.txt` 曾报 11 条 `NO_ROUTE`、`apicheck011b.txt` 再报 10 条，逐条与 `apps/web/app/api/v1` 的 155 个真实路由清单比对后**全部是静态解析对 query-string 与模板字符串的误报**，已剔除，未计入缺陷清单。→ 结论：保留项均为真。

**拷问 2：「`benchmark` 参数是不是缺陷？」**
实测 `?type=models&benchmark=humaneval` 返回 1000 条（不缩减），一度像是"参数被吞"。穿透 `ladder/service`：`service.ts:168` 与 `types.ts:20/51-52` 明确写「benchmark 服务端透传不过滤」，是**设计如此**（用于 URL 回放锚定某一基准视角）。→ 撤回"过滤失效"判定，改记为 `12_` 中的 UI 语义可辨识度问题（待确认，不进本轮卡集）。

**拷问 3：「`/models` 过滤 50→51→149 是不是过滤器坏了？」**
反证：API 层 `modelType=REASONING,CODE` → 236/1000（真实缩减）。页面侧 `base=50` 与 `restored=149` 的差异来自**无限滚动的加载时序**（route 注释 v1.9：`limit` 缺省=全量、offset/limit 窗口切片），过滤器工作正常。→ 判定为**测试脚本时序假象**，不列为缺陷。

**拷问 4：「把 `if (res.ok)` 无 else 分支说成『错误显示为空态』是否夸大？」**
钢人反方：`adminFetch` 可能自己抛错，被外层 try/finally 吞掉后仍会走到 empty 分支——那结论一样成立（错误没被区分）。钢人正方：若 `res.ok=false` 时 `rows` 保持初值 `[]`，界面文本就是「暂无协议兼容数据」，用户与自动化都无法区分「真的没数据」和「请求失败」。运行态旁证：`audit-crud.json.ui` 中该两页 `errs=[]`（无控制台错误）却有 `rows=0`，与"静默失败"一致。→ 结论保留，但表述限定为**协议/能力两页实证**，其他 33 页仅以「缺错误态」静态证据计入（部分确认）。

**拷问 5：「45 个后台文件缺 testid 是否等于缺陷？」**
追问：testid 缺失不影响用户，是否只是测试洁癖？反证在需求侧：《UI/界面交互文档》与 V0.10.0 的 EVD-092/064 已把「五态 + testid」确立为验收口径，且本轮用户指令明确要求「每个步骤必须由子智能体…测试」——无 testid 时运行态验收无法寻址。→ 判定成立，但定性为**可验证性缺陷**（阻塞验收手段），非用户可见缺陷。

**拷问 6：「seed 改成非零价会不会破坏 U-23（免费模型零扣费）路径？」**
实测依赖：`e2e/tests/promotion-billing.spec.ts` 与 `docs` 均引用「归一价输入输出均为 0 → 免费模型（U-23=B）」。若把全部 1000 行改为付费，该路径的 e2e 将失去样本。→ 因此 seed 必须是**分层**（保留免费层 + 新增付费/多币种/促销层），并先核对该 spec 的选择器不依赖具体行数。此拷问直接改变了 B11-02 卡的【范围】写法。

## 三、第三轮：双向钢人论证（关键裁决）

### 裁决 R11-A：优先修「fx 链路」而非先铺组件规范

- **支持**：一处改动同时解锁 3 个可观测面（币种切换、跨币种计价、促销价），且证据链最短（表 0 行 + 无脚本入口 + fail-closed 注释三证齐）。
- **反对**：组件/数据类缺陷数量更多（8/10），先做链路类可能被视为"避重就轻"；且若 fx 源在本地不可达，B11-01 会卡住。
- **排除**：反对意见的"卡住"分支已在 What-if 中预案（离线兜底 seed + `FX_DAILY_SOURCE_URL` 覆盖），不阻塞。
- **裁定**：维持 R11-A，但 B11-01 的【验收】不依赖外网成功——以外网成功为加分项、离线兜底为必达项。

### 裁决 R11-B：横切"后台面板规范基线"做成可复用件，而非逐页改

- **支持**：`AdminDataTable` 已证明"复合件放在 `apps/web` 而非 `packages/ui`（耦合 adminFetch 类型）"这一决策成立（文件头注释）；同构复制该模式成本最低，且 `ProtocolMatrix`/`CapabilityMatrix` 约 70 行结构重复。
- **反对**：抽象过早可能覆盖不了 45 个文件的差异（编辑类面板 vs 只读看板 vs 树形菜单），强行统一会造成大量 escape hatch。
- **仍然成立的反对**：确实存在无法统一的差异（如 `MenuManager` 树形、`ReportsBoard` 图表）。
- **裁定**：抽象只覆盖**三态外壳（loading/empty/error+retry）+ testid 命名**，不抽象业务列渲染；对差异面板保留现有写法但必须补 testid。范围收敛后进入 B11-05。

### 裁决 R11-C：`@aidean/ui` 扩 Select/Textarea/Label 属于「拓展」而非「偏离技术栈」

- **支持**：ADR-0001 锁定 Tailwind 4 / Next 15，底座本就是 "shadcn 风格占位简化版；零业务逻辑"（`packages/ui/src/index.ts:1`），增补同类原语不换栈。
- **反对**：新增原语会改变 `aidean-ui-refs` 这条 facts 断言的期望值（当前=70），且 50+ 处原生标签迁移面极大。
- **裁定**：拆为两卡且**顺序固定**——B11-04a 只建原语 + 单测 + facts 同步；B11-04b 只迁移**收益最高的 admin 表单热区**（非全量 149 处），全量迁移列入 `12_` 后续批。

### 裁决 R11-D：本轮不动 `/auth/me` 契约，改客户端

- **支持**：改返回码会牵动契约文档、单测、e2e（R10-01 成本），而"已知匿名就不发 favorites 探针"是一处局部客户端闸门，风险近乎零。
- **反对**：401 红字里 `auth/me` 这条仍在（每次导航 1 条），噪声只减半。
- **裁定**：采纳反证，B11-06 同时把 `auth/me` 的调用收敛为「会话状态未知时才探针」并缓存结果，目标 anon 净 401 = 0；若需改契约则升格为 Q-11-02 交决策人。

### 方法论沉淀（入仓约束，非空洞口号）

1. **判定型探针必须做一次反向自检**（让被探对象故意失败，确认输出会翻红）——第 4/6/9/11 次均属同类；第 11 次尤其重要：一个自检样本就足以判定整个扫描器不可信，而不是“读数多算 3 条”这种小事。**边界补充（第 32 次）：反向自检只证明工具“能翻红”，不证明它的分类语义正确**——一个能把现行断言判红的邻近判据，完全可能把“窗口内出现了一个无关的标记词”当成撤回而放绿（假绿，与假零同族但方向相反）。因此：**判定型工具的总数（尤其是一个绿色总数）不得当作“已清零”**，必须逐行人工判读；而控制组应尽可能加“**标记词存在但语义不相关**”这一类样本（本轮尚未做到，属已知局限）。
