## 〇、通用规则（每个 L3 步骤都适用）

### 0.1 Git 标准流程
| 时点 | 命令 | 判据 |
|---|---|---|
| 每张卡开工前 | `git status` → `git fetch origin` → `git rebase origin/main` | 工作区干净；HEAD = origin/main |
| 每个 L2 任务完成 | `git add -A && git commit -m "<卡号>.<L2号>: <一句话>"` | 一个 L2 对应一个提交，不推送 |
| 每张卡完成 | `git fetch origin && git rebase origin/main` → 0.3 全量门禁 → `git push origin HEAD:main` | push 成功；`git rev-parse HEAD` = `git rev-parse origin/main` |
| 推送被拒 | 重复上一行 | 禁止 `--force`、禁止推 `aideanew/Aidean` |
| 403 / 认证失败 | 停手，报用户 | 不碰凭据 |

### 0.2 度量与截图工具（Hark 已入库）
- `node scripts/audit/admin-ui-audit.mjs [--files a.tsx,b.tsx] [--json]`：逐文件统计原生 `button/select/textarea/label/table` 的数量，以及 `mixed`、`testid`、`PanelState`、错误态、重试。三张卡的验收数字都只认它（它替代未入库的 `.scratch/rawbtn011.mjs` 和 `adminmatrix011.mjs`）。
- `ADMIN_EMAIL=… ADMIN_PASSWORD=… node scripts/audit/admin-shots.mjs --out <dir> --routes /admin/x[,..] [--inject 500|offline|empty:/api/v1/admin/x]`：桌面 1440 和移动 390 两档截图，产出 `shots.json`（含每张图的 `data-state`）。**Hark 侧缺浏览器依赖，这个工具还没实跑过。** 第一次使用时先对 1 个路由试跑：成功就继续；失败按 0.5 停手上报。
- 口令只从环境变量读，**不得**写进命令文本、EVD 或截图。

### 0.3 门禁
- **开发中（每个 L3 改完代码后）**：`pnpm --filter web exec tsc --noEmit --incremental false` + 相关 spec（`pnpm --filter web exec vitest run <路径>`）。
- **每张卡推送前跑一次全量**：`tsc`、`pnpm --filter web lint`、`pnpm --filter web test`、`pnpm --filter @aidean/ui test`、`node scripts/check-docs-rule.mjs`、`node scripts/check-docs-facts.mjs`、`node scripts/guard/run-all.mjs`、`pnpm --filter web build`。
- facts 断言会变的地方：新增 spec 改 `spec-count`；新的组件文件开始 import `@aidean/ui` 时改 `aidean-ui-refs`。在 `scripts/check-docs-facts.mjs` 对应的 desc 里写上「本卡 +N，原因」。

### 0.4 证据（每卡一个 `EVD-<卡号>/`）
- `verify.txt` **不超过 40 行**，只写命令、退出码和关键读数（审计 SUMMARY 前后对比、门禁结果、提交号）。
- `deviation.md` 只在真有偏离时写，每条不超过 5 行。
- 截图放 `EVD-<卡号>/shots/`，只提交验收需要的那几张，不提交整批。

### 0.5 停手条件
同一步失败两次就停：写清现象、试过什么、卡在哪个 L3，报 Hark。等 Hark 裁定期间，**只允许**做后面不依赖它的 L3。node_modules 空壳守卫报 FAIL 时，跑一次归档修复命令即可，不做归因。

### 迁移规则（逐个标签对照，不得自由发挥）
| 原生 | 替换为 | 规则 |
|---|---|---|
| `<button>` 无 `type` 且在 `<form>` 内 | `<Button type="submit">` | **必查**：`Button` 默认 `type="button"`，漏写会让表单提交失效（8 个文件有 `<form>`） |
| `<button type="submit">` | `<Button type="submit">` | 保留 type |
| 主操作（保存、新建、确认；蓝、绿、emerald 底色） | `variant="primary"` | 去掉 `bg-*`、`text-white`、`rounded*`、`px/py`、`disabled:opacity-*` |
| 次操作（取消、关闭；白底加边框） | `variant="outline"` | 同上 |
| 删除、禁用（红底） | `variant="danger"` | 同上 |
| 行内文字按钮（编辑、详情；无底色） | `variant="ghost" size="sm"` | 红字删除用 `variant="ghost" size="sm" className="text-[var(--danger)]"` |
| 黑底按钮 | `variant="dark"` | |
| 原 `text-xs` 或 `px-2 py-1` 的小按钮 | `size="sm"` | 其余默认 `md` |
| 标签页式切换按钮 | `variant={active ? "primary" : "outline"}` 或 `ghost` | 保留 `aria-pressed` 和 `aria-selected` |
| `<select className="…">` | `<Select className="<只留布局类>">` | 留 `mt-*`、`w-*`、`max-w-*`、`flex-*`；删 `border`、`rounded`、`px/py`、`text-sm`、`focus:*`；**不要**用 `size` 表示多选行数 |
| `<textarea rows={n}>` | `<Textarea rows={n}>` | 原来**没写** rows 的显式补 `rows={2}`，保持原高度 |
| 包裹式 `<label className="X">文字<input/></label>` | `<Label className="X">` | 18 个文件全是包裹式（没有 `htmlFor`），**原样保留 X**，让 cn 合并覆盖 Label 的基线；截图里文字挤在一起时加 `leading-normal` |
| `<label>` 里是 checkbox 或 radio | `<Label className="flex items-center gap-2 font-normal …">` | |
| `onClick`、`disabled`、`title`、`aria-*`、`data-testid` | 原样透传 | 一个都不能丢 |

import 统一写 `import { Button, Select, Textarea, Label } from "@aidean/ui";`，与该文件已有的 `@aidean/ui` import 合并成一行。

### 每个面板的标准 6 步（L3 模板，14 个面板各执行一遍）
1. **抽 loader**：在组件文件里加模块级 `export const loadXxx = (signal?: AbortSignal) => adminFetch<…>("<原列表 URL>", { signal })`，URL 和原来完全一致。
2. **换状态**：删掉 `rows`、`loading`、`error` 三个 `useState` 和首屏 `useEffect`，改用 `const { resource, reload, refresh } = usePanelResource(loadXxx, isEmptyList 或自定义 isEmpty)`。
