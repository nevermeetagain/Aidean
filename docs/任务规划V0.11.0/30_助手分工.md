## 一、分工原则
- **Hark（核心）**：架构/机制/领域层——B11-10 非 2xx 统一信封机制；B11-11 公共分页 helper + 参考实现 + 守卫脚本；B11-06 客户端会话层；B11-03a 矩阵后端领域层与数据写入路径；后台五态外壳组件。每项附 `EVD-<卡号>/handoff.md` 交接说明。
- **助手甲（UI 线）**与**助手乙（数据/接入线）**：常规实现。两线按文件白名单切开，依赖 Hark 产出的步骤排在各自队列后段。
- 通用纪律：只用 `nevermeetagain/Aidean` 的 `main`；不建分支、不强推；每次推送前 `git pull --rebase`；每卡只写自己的 `06_validation/evidence/EVD-<卡号>/`（`verify.txt` 真实输出+exit code、`deviation.md`）；未跑的检查一律写「待确认」；每卡完成跑 `pnpm --filter web exec tsc --noEmit --incremental false`、lint、全量 vitest、`check-docs-rule`、`check-docs-facts` 全过再推。
