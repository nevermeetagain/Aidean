### Q-11-02 · 匿名会话探针的返回码口径

- **现状证据**：`/api/v1/auth/me` 对匿名返回 401（REST 语义正确），但客户端每页都发 → 游客每页 2 条红字（`audit-runtime.json.netFailures`）。
- **选项 A**：新增轻量会话端点（如 `/auth/session` 返回 200+`{user:null}`），`auth/me` 保持 401 语义不变。需新 route + 契约登记 + R10-01。
- **选项 B（B11-06 默认）**：不动契约，客户端缓存会话状态 + 已知匿名即跳过 favorites 探针。
- **风险**：B 无法把 `auth/me` 的 401 降到 0，除非探针本身被省略或缓存。B11-06 以"探针只在状态未知时发一次 + 结果缓存"逼近 0；若仍有残余，则升格为 A 并请你批准新端点。**裁决结论 = B（已实施并合并）**：客户端单一会话 store + middleware 会话提示 Cookie = `534c722d`（docs `b75166e4`／取证 `e5b5e470`／merge `16e3261f`；证据 `EVD-B11-06/`）；**升格 A 未触发**——2026-10-23 实测 `apps/web/app/api/v1/auth/session` 目录不存在，A 方案（新端点）确未实施，`auth/me` 的 401 语义不变。

### Q-11-03 · 非 2xx 出口是否补齐统一信封 + 单资源 GET？（本轮收口期新发现，DEF-011-13）

- **现状证据**（`.scratch/get011.txt`）：`GET /api/v1/admin/scripts/{id}` → **405 + 0 字节空体 + `content-type=null`**；未知 API 路径 → **404 + 27435 字节 HTML**；`api/v1` 下 53 条动态路由中 **26 条单资源路由无 GET**（`scripts`/`products`/`models`/`prices`/`users`/`vendors`/`roles`/…）。

### Q-11-05 · 分页参数的有限性守卫要不要统一口径？（子智能体审查后的加固中发现，DEF-011-15）

- **现状证据**：同一个写法 `Math.max(1, parseInt(searchParams.get('page'), 10))` 在 `page='abc'` 时得 `NaN`（`Math.max` 不接管 NaN），`NaN` 进 Prisma 的 `skip/take` → **HTTP 500 + `code=50000`**。**运行态已实证**：`admin/audit-logs?page=abc` 与 `admin/tier-mappings?page=abc` 均 500，而本轮已修的 `scripts/[id]/executions` 同参数为 200（对照组）——见 `.scratch/t9-sibling.txt`。仓内**三种口径并存**（静态扫描分档，`FILES_SCANNED=155`）：无守卫 **12 文件 / 22 行**（announcements / api-stations / audit-logs / benchmarks / evaluations / **free-quotas** / intelligence:reports(`limit`) / intelligence:snapshots(`limit`) / scripts / sync:batches / sync:changes / tier-mappings）、靠 `parseInt(…) \|\| 默认值` 兜底而实际上免疫 **3 文件 / 6 行**（capabilities / discovery/candidates / protocols）、分页有限性守卫 **1 文件**（仅本轮新修的 `scripts/[id]/executions`；**修前该档为 0**，即全仓第一处）。
- **更正记录（第 16 次证伪）**：本条原记「无守卫 **11** 个 + 已用 `Number.isFinite` 守卫 **1** 个（`free-quotas`，即**仓内已有同构先例**）」为**失实**。`free-quotas/route.ts:67` 那处 `Number.isFinite` 守的是 **POST body 的 `quotaTokens`**，与分页无关；其分页两行 `:21-22`（`Math.max(1, parseInt(…))`）恰恰是无守卫写法，因此该文件应归入无守卫档、**同构先例并不存在**。复证载体：`.scratch/u2-tiers.txt`（正控「free-quotas 分页行 ∈ 无守卫」= true；负控「executions 的 `toInt` 行 ∉ 无守卫」= true）、`.scratch/u2-blind.txt`（跨行别名盲区：仅本端点 1 文件，无漏检）。
- **选项 A（统一抽公共件）**：把本卡 `executions` 的 `toInt()`（`Number.parseInt` + `Number.isFinite` 双步）提为共享 helper（如 `packages/shared` 或 `lib/http/pagination.ts`），**15 个列表端点全量接入**（无守卫 12 个 + 依赖 `\|\|` 兜底的 3 个改为显式守卫）+ 每端点补一条“非法串不得送 NaN”的单测；估 4–6h，需新 RTM 行与 R10-01 同步。
- **选项 B（只补无守卫 12 处）**：不抽公共件，逐文件就地加守卫；估 2–3h，但**口径仍不统一**（就地字面守卫 / 本端点的 `toInt()` 辅助 / `\|\|` 兜底 三种写法共存）。
- **选项 C（仅登记）**：归入 `明确不做`，只保留本轮已修的那一处。
- **Hark 建议**：A。理由：① 守卫只用标准库 `Number.parseInt`/`Number.isFinite`，**不新增依赖、不换栈**（铁律 5 无冲击）——可行性证据**不是**“仓内已有先例”（该论据已随第 16 次证伪撤销），而是本卡已落的一处实现配 **7 例单测 + 已落盘的变异检验**（正规载体 `.scratch/u3-mutation.txt`：把分页两行改回无守卫写法后第 7 例必失败，`MUT_TEST_EXIT=1`、`expected NaN to be +0`，随后按 SHA 还原 `MATCH=True`；首次尝试的 `u2-mutation.txt` 未写入退出码，不得作凭证——第 17 次证伪）；② 本缺陷的形态是**用户可触发的 500**（前端传非法分页参数或手工改 URL 即可），而后台列表端点数量多且入口同构，选 C 等于默许 12 处可复现的 500 存活；③ 选 B 会留下“三种写法共存”的新分裂，与本轮“口径统一”主题相左。
- **本轮为何不动**：该面触及 **15 个文件**（无守卫 12 + 兜底 3；另有本卡已修的 `executions`），属横向重构；而收口阶段的职责是验证已有改动（与 Q-11-03/04 同一理由）。已登记为候选卡 **B11-11**（不计数），且本轮**不得**在任何总结里写“分页 500 已全站修复”——只有 `scripts/[id]/executions` 一处成立。**裁决结论 = A（已实施并合并）**：共享件 `lib/http/pagination.ts` = `a92b9584`，15 个后台列表端点全量接入（非法串→400，不再送 NaN）= `71a2c782`，终审与变异检验 = `d03976c0`/`2b60193e`；证据 `EVD-B11-11/`。**本句以上的「本轮不动／只一处成立」是 2026-10-21 收口时点口径，已被该裁决解除**；接入后守卫名单清空，唯 intelligence `limit≤1000` 按 Hark 裁定②保持原样。
