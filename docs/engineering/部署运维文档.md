# 部署运维文档

> 版本: v1.2 | 更新: 2026-09-15 | 变更: §9 新增 JWT_SECRET 轮换影响与操作规程（平台 API Key 哈希与自有上游 Key 密文不可逆，须提前公告重建）。前次（v1.1）：§8 新增 Docker 启动故障排查实录（三层根因修复 + 重启复核）
> Docker 部署、环境配置、运维手册。约束：国外网络默认不可用，镜像优先国内源。

## 1. 环境要求

- Node.js 18.18+（Next.js 15 要求）
- Docker + Docker Compose
- PostgreSQL 16 / Redis 7（由 compose 提供，本机不自装）

## 2. 环境变量

`.env.example` 为模板，复制为 `.env.local` 后填写：

| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | PostgreSQL 连接串 |
| `REDIS_URL` | Redis 连接串 |
| `JWT_SECRET` | JWT 签名密钥 |
| `NEXT_PUBLIC_SITE_URL` | 站点地址 |

## 3. 本地开发

```bash
docker compose -f docker/docker-compose.dev.yml up -d   # PG + Redis
npm install
npm run db:generate && npm run db:push                  # schema
npm run dev
```

compose dev 服务（继承旧体系服务骨架，修正其两处坑）：

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| postgres | postgres:16-alpine | 5432 | SQL 经 `/docker-entrypoint-initdb.d` 首启自动初始化 |
| redis | redis:7-alpine | 6379 | |
| pgadmin | dpage/pgadmin4 | 5050 | 可选管理台 |

> **坑位修正**（来自旧体系，见迁移清单）：
> 1. 数据卷改用**命名卷** `pgdata`，不复用旧 compose 写死的 WSL2 by-uuid 设备路径。
> 2. 密码走环境变量，不硬编码进 compose。

## 4. 生产部署

```bash
docker compose -f docker/docker-compose.prod.yml up -d
npm run build && npm start        # 或容器化运行
prisma migrate deploy             # 数据库迁移
```

- 应用容器 + postgres + redis + nginx（反代、TLS、静态缓存）。
- nginx 配置继承旧 `docker/nginx` 骨架，按新域名调整。

## 5. 数据库初始化与备份

- 初始化：Prisma migrate + `docker/sql/init/`（扩展/触发器/seed）。
- 备份：`pg_dump` 定时任务；恢复流程参考旧 `docker/docs/BACKUP_RESTORE.md`（迁移后落地到本文档附录）。

## 6. 运维

| 项 | 说明 |
|---|---|
| 健康检查 | `GET /api/v1/system/health` |
| 日志 | 结构化 JSON，请求 ID 串联 |
| 监控 | 可用率/好评率等聚合由定时任务刷新；应用监控接 Prometheus（后续） |
| 同步任务 | sync 管线 scheduler 定时执行，失败告警 |

## 7. 国内可用性

- Docker 镜像配置国内 registry 镜像加速器。
- 前端不依赖国外 CDN/字体服务，全部自托管。

## 8. Docker 启动故障排查实录（2026-08-30）

> 现象：`docker version` 报 `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`。按下面三层逐级排除；修复后已于同日重启复核通过。

### 8.1 排查链（按序执行）

| 层 | 根因 | 判定特征 | 修复 |
|---|---|---|---|
| 1 | Windows「虚拟机平台」功能被禁用 | `HCS_E_SERVICE_NOT_AVAILABLE`；`wsl -l -v` 异常 | 管理员执行 `dism /online /enable-feature /featurename:VirtualMachinePlatform` 后**重启** |
| 2 | docker-desktop WSL 发行版内部状态损坏 | `wsl -l -v` 中 `docker-desktop` 长期 `Stopped`/VM init 无响应 | `wsl --unregister docker-desktop`（Docker Desktop 自动重建；先确认镜像可舍弃） |
| 3 | WSL 2.6.3 引擎僵死 + 镜像源失效 | `docker pull` 报 `500 Internal Server Error` | 升级 WSL（≥2.7.x）；`.wslconfig` 限资源（本机 8GB/8CPU）；`daemon.json` 更换可用 mirror（`docker.1panel.live` 首位） |

### 8.2 容器内构建联网

容器内下载 pnpm 等资源被墙时，构建命令追加宿主代理：

```bash
docker build --build-arg HTTP_PROXY=http://host.docker.internal:10808 \
             --build-arg HTTPS_PROXY=http://host.docker.internal:10808 .
```

### 8.3 重启复核（2026-08-30）

- `docker version` → Server 29.4.3 正常应答；
- `wsl -l -v` → `docker-desktop` 状态 `Running`；
- 修复期产物 `aidean-web:latest`（252MB）镜像持久化完好。

**结论：三层根因均已修复，Docker 启动链路稳定，故障关闭。**

## 9. JWT_SECRET 轮换影响（GW-KEY-01/RW-2）

> 现象：轮换 `JWT_SECRET` 后，① 平台 API Key（`api_keys.key_hash` = HMAC-SHA256(secret, JWT_SECRET)）全部校验失败（网关 Key 态一律 401）；② 用户自有上游 Key（`station_user_keys.key_cipher`，AES-256-GCM 以 SHA256(JWET_SECRET) 派生密钥，实际为 SHA256(JWT_SECRET)）全部解密失败（UPSTREAM 路径报「StationUserKey 解密失败」500）。两者均不可逆迁移，只能重建。

### 9.1 影响面

| 资产 | 派生方式 | 轮换后表现 | 恢复方式 |
|---|---|---|---|
| 平台 API Key（api_keys） | HMAC-SHA256(secret, JWT_SECRET) | 网关 Key 态全部 401 | 控制台重建 Key，旧 Key 吊销 |
| 用户自有上游 Key（station_user_keys） | AES-256-GCM（SHA256(JWT_SECRET) 派生） | UPSTREAM 路径 500 | 控制台重新录入站点 Key |
| JWT 会话（RS256 密钥束/JWKS） | 独立于 JWT_SECRET 的非对称密钥 | 不受影响 | 无需处理 |

### 9.2 轮换操作规程

1. 提前公告：通知使用平台 API Key 与自有上游 Key 的用户；
2. 低峰窗口轮换 `JWT_SECRET` 并重启服务；
3. 重启后引导用户在控制台重建上述两类凭据；
4. 如需保留上游 Key 明文迁移能力，须在轮换前解密导出（涉及明文落地，须管理者专项批准）。
