# 03b · 需求增量：模型源监控体系（REQ-M-001..016）

> 版本: v0.4 | 更新: 2026-10-14 | 变更: V0.4.0 新增——把用户链接与补充1/补充2 转为可验证需求，做分级、冲突、未知登记（BLOCKING 带条件方案）

## 3.1 复述与拆解

**核心问题（复述）**：Aidean 已有模型天梯、价格表和中转站发现，但「新模型何时出现、哪些平台已上架、各平台卖多少钱、API 是否可用、中转站是不是真货」这些信息靠的是零散采集和人工维护。用户希望有一套能长期运行的**模型源监控体系**：多源采集目录 → 按源保存证据 → 检测变化 → 交叉验证 → 在后台可管理、在前台可查询。

- **关键词**：源注册（分级 S1/S2/A/B/C）、目录快照、provider_model 观测、价格原币、变更事件、可用性/真实性信号、证据链、刷新频率、凭证、条款。
- **用户与边界**：终端用户（前台查「在哪里可调用」）；管理员（后台管源、看变更）；系统边界 = 只**读**第三方公开或授权的目录/文档接口，**不**代用户调用第三方付费接口（除 U-M3 批准的探针预算外）。
- **与现有系统的关系**：在 `lib/sync`（采集）、`lib/discovery`（发现）、`lib/intelligence`（快照/报告）之上新增 `lib/monitoring`，不替换它们（理由见 18b §4.3）。

**明确不做（MUST NOT，框定范围）**：
1. 不宣称「覆盖全网所有模型站点」（补充1 自己也承认没有权威全集）。
2. 不抓需要登录、有反爬或验证码的页面，不绕过任何访问限制。
3. 不把补充2 的「稳定性星级」当作评分写进天梯（只是结构分层）。
4. 不自动下架、不自动 promote 中转站（探针结果只作信号）。
5. 不并入 AGPL 代码（Veridrop）。
6. U-15 裁决前，监控数据不做 CNY 换算展示。

## 3.5 隐含要求与前置条件

- **隐含**：采集响应体有大小上限（OpenRouter ≈0.77MB、AIHubMix ≈0.89MB），需要沿用 `readCappedJson` 并把上限调到 4MB；SSRF 防护（`assertSafeUrl`）同样适用于后台登记的新源端点。
- **前置**：M-002 必须排在 M-001（TASK-011）之后（迁移串行）；TASK-056 依赖 TASK-001（errors.ts 唯一源先落地）。
- **歧义**：「稳定性排序」指结构分层，不是 SLA；「支持 API 采集」不等于能拿到价格（SiliconFlow `/v1/models` 只返回 id）。
- **边界**：同名模型在不同源不一定是同一版本 → 规范化 ID 只用于**关联展示**，不用于自动合并 AiModel（未命中进候选，人工处理）。
- **依赖**：S10 的 E2E（065）依赖 CI e2e job（TASK-006）与唯一 e2e 配置（TASK-037）。
