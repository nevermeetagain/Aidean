### 3.6 REQ-F-011 · 计价口径不统一（旗舰缺陷）—— 已确认并**根因精确化**
- 3.6.1 汇率冲突（discovery）：`git grep -n "7\.2" -- lib/discovery/pricing-extraction.ts` → L217/220/233/238/243 均 `usd * 7.2`；需求文档为 ¥5=\$1（1:5）。**换算口径与需求冲突，复现。**
- 3.6.2 网关扣费根因（**本轮精确化**）：`gateway/service.ts` 三处计费
  - L693-704、L996-1003、L1406-1412 均
    ```
    calcCharge({ pricePerMillionToken: Number(price.priceInput), ... })
    ```
  - 即把 `priceInput` **直接**当作"¥/百万 token"单价；`billingCurrency` 虽被 `repository.ts:92,112` select、并在 L676/L935 类型里携带，却**从未作为入参进入 `calcCharge`**；`billingUnit`（计价单位 per_1k/per_1M）**根本未读取**。
  - 结论修正表述：**缺陷根因 = 计费只认 `priceInput` 数值、忽略币种与计价单位两个维度**（V0.2.0 表述方向正确，本记录补齐"select 却不消费"的调用链证据）。
- 3.6.3 seed 币种分布（**口径精修**）：`git show HEAD:apps/web/prisma/seed.ts | Select-String`：含 `USD` **61 行**、含 `CNY` **48 行**。（V0.2.0 记"48 条 USD"系口径不精确；本轮以可复现 grep 行数为准，价格行级精确数待 `seed.ts` 结构解析，避免伪精确，指令 §13.7。）
- 综合：**REQ-F-011「价格统一 ¥/M、展示与官方一致」未实现且存在资金风险，成立**；R-02/R-03 风险有效；S4b（048/049/053/054/055）仍需 U-15 裁决汇率与单位口径后下发。

### 3.7 REQ-NF-001 · 错误码三源 —— 部分确认（复现方向）
