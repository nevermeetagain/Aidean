> 版本: v1.0 | 基线: main@06bdee1 | 依据: 26_用户裁决记录.md v1.0 | 取代: 21_Agent任务书/外部助手-交接任务书-2026-10-20.md 的波次安排（交付协议与验收标准仍沿用其 §3/§6/§7，本文 §4 为增补）

## 1. 划分口径

- **核心（Hark 独立完成）**：计费正确性、币种与汇率架构、数据一致性（并发/事务/幂等）、跨实体映射——错了会造成错扣费、错下架或数据腐化，需要 5 年以上架构/开发经验。
- **非核心（助手完成）**：接口、页面、脚本、测试、文档、治理——2–3 年开发者按卡面可完成，错了影响局部、容易回滚。
- 核心 6 张 / 非核心 30 张；Hark 不做非核心卡。

## 4. 并行协作规则（增补交付协议 §3）

1. **推送前必须** `git pull --rebase origin main` → 重跑全局门禁 → `git push origin main`；被拒就再 rebase，**禁止强推、改写历史、`--no-verify`**。
2. **共享热点文件**只做最小追加：
   - `scripts/check-docs-facts.mjs`：只改计数期望值；rebase 冲突时以远端为准，再加上本卡的增量。
   - `packages/shared/src/index.ts`：只追加 export 行。
   - `docs/architecture/API接口文档.md`：只增改本卡端点小节，版本头 +1；冲突时保留双方小节，版本号取最大值 +1。
   - `05_execution/task-index.md`、`25_执行记录.md`：只改/追加本卡所在行或段。
3. **不碰别人的独占文件**；确需改时停手，在汇报里写「需要 X 线改 Y」，由用户转达。
4. **数据库只由 Hark 改**。助手的卡需要新表/新列/新索引时停手报告，不得自建迁移。
5. **等待点**：前置未推送到 `origin/main` 前，不得开工依赖卡；可先做本线下一张无依赖卡。
6. 停止条件沿用交接任务书 §3.8；新增：需要改 Hark 独占文件、需要数据库迁移。
