## 背景
补充1/补充2 建议建立 6 类实体的监控库。核验（19）发现：公开可采的源有 5 个；AA 全端点都要 Key、要求署名、再分发需授权；Veridrop 是 AGPL；OpenRouter 文档写需要 Key，但实测公开可用。

## 决策
1. **独立追加型监控表**（M-002：monitoring_sources / catalog_snapshots / provider_model_observations / catalog_change_events），不复用 MarketSnapshot/PriceRule 承载按源事实（理由见 18b §4.3）。
2. **源条款状态是一等字段**（`tos_status`）：`pending` 的源数据**只在后台显示**，不进入前台公开 API；`attribution_required` 的源，前台展示时必须带 `attribution`。
3. **凭证只走环境变量**（`MONITOR_KEY_<SOURCE>`），不进 DB、不进日志、不进快照采样；缺失时返回 50012，不抛异常。
4. **不引入 AGPL 代码**；真实性检测只参考公开方法自研（TASK-071）。
5. **监控价格只展示原币**，U-15 裁决前不做 CNY 换算。

## 后果
- 正面：按源可回溯、可索引；条款风险前置；与计价缺陷隔离。
- 负面：表数 68→72（文档计数需同步）；前台在源条款核验完成前看不到 pending 源的数据。
- 反证与回退：如果用户裁决「监控数据只在后台用」，066/067 可整体降级为 COULD，表结构不受影响。
