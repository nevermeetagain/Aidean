== 2. 实现口径（卡面逐条）==
1) 鉴权：requireAdminApi("admin.models.write")；非 admin → 403（10008）。
2) 契约：PriceBatchUpsertSchema（body.requestId uuid 幂等键；rows 1..500；行 .strict()；价格拒空值）；
   响应 PriceBatchUpsertResponseSchema（total = created + updated + failed.length）。
3) 逐行独立事务：有 isCurrent 价 → update（billingMode 未显式给出时保留原值；价格/缓存价/按次价为整行口径）；
   无当前价 → create（billingMode 缺省 PER_TOKEN、billingUnit 缺省 per_1k_tokens、billingCurrency 缺省 CNY、
   sourceType=OFFICIAL、sourceName=admin-batch、isCurrent=true、effectiveFrom=批次时刻）。
4) 逐行同事务写 audit_logs（create action=1 / update action=2，old/new 值 + x-request-id）。
5) 部分成功（E9-05）：单行异常记 failed[]（index=请求 rows 下标、modelId、code、message），不回滚已成功行；
   模型不存在 → 40000；当前价并发唯一冲突（P2002）→ 40000「请重试」；其他 → 50000。
6) 写后失效：created+updated>0 时调用 invalidatePriceViews() 一次（TASK-097 两层失效）。

== 3. requestId 幂等（无新表/无迁移）==
- Redis（REDIS_URL 存在时）：SETNX PENDING(TTL 300s) 挡并发双击；完成后缓存首次响应 7d；
  重放直接回放；同 requestId 在途 → 429（10006）。
- audit_logs 回执（始终写）：tableName=model_prices_batch、recordId=requestId、action=1、newData=首次响应；
  Redis 缺失/过期后按回执回放（顺序重放幂等），无数据库迁移（铁律：库只由 Hark 改）。
- 口径说明：仓库无通用幂等表；本实现复用既有 Redis 包装（lib/db/redis）与 audit_logs（requestId 字段），
  未新建表/列/索引。Redis 包装 fail-open → 退化为回执判重；并发极端窗口由 ModelPrice 部分唯一索引兜底（冲突行 failed）。
- 回执的 recordId = 批量幂等键；AuditLog.requestId 仍存 HTTP x-request-id，二者不混用。
