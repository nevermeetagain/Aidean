== 2. 实现口径（卡面逐条）==
1) 参数：--source <key|all>（默认 all）、--dry-run、--limit N、--help/-h。
   未知参数 / --source 缺值 / --limit 非正整数 → stderr + exit 1。
2) 源选择：写库与真实 dry-run 从 monitoring_sources 读 enabled=true 且 deleted_at IS NULL；authRequired=true
   的源跳过并打 [skip]（U-M1：当前无凭证体系）。--source 指定未注册/未启用 → exit 1。
3) 逐源执行：每源 try/catch；成功 → lastStatus=ok、lastCount=n、lastError=null、lastRunAt=now；
   失败 → lastStatus=failed、lastCount=null、lastError=message(≤2000)、lastRunAt=now，stderr 打
   `[failed] <key>: <原因>`，继续下一源。至少一源成功 → exit 0（部分成功）；全部失败 → exit 1。
4) fixtures 离线：MONITOR_FIXTURE_DIR + --dry-run 时完全不触 DB/网络（DB 模块动态 import，help/离线路径不加载），
   按 catalog/{key}.json 输出 openrouter/aihubmix/quanzil 三源计数；FETCHED_AT.txt 首行作 fetchedAt。
5) 写库流程（catalog 与 public-pricing 共用）：
   collect/normalize → sha256(原文) → persistCatalogSnapshot（TASK-059，同哈希幂等/空目录守卫）→
   读「写入前」上一快照观测与全目录首见集合 → detect（TASK-061）→ persistCatalogChangeEvents。
   同哈希（idempotent）不产事件；空目录守卫抛错计 failed，不把整源打成下架。
6) public-pricing：safeFetch（SSRF 策略）+ readCappedText(4MB) + blockedPageReason（登录/反爬标记即停该源）+
   robots.txt best-effort 守卫（User-agent: */aidean 的 Disallow 前缀命中即抛 robots_disallowed；
   robots 404/不可达不阻断）；parse 0 条或 ok:false → 该源 failed（不以空列表冒充成功）。
7) --limit N 仅 dry-run 生效（预览条数）；写库模式给出 --limit 直接拒绝：截断观测会让未列出的现有模型被 writer 误下架。
8) robots 检查仅作用于 public-pricing（公开 JSON 目录源不加额外请求）。
