## 3. 每张卡的交付协议（硬约束）

1. **开工前**：`git pull --ff-only`；`git log -1` 记基线；通读卡面「目标 / 允许修改 / 禁止修改 / 验收标准 / 验证命令」。
2. **只改允许路径**；卡面未列但确需改的文件（如 facts 期望值、spec 只能落 `lib/**`），在证据里写「偏离说明 + 依据」，不得静默扩大范围。
3. **新增 route/page/spec/@aidean/ui 引用**时同步 `scripts/check-docs-facts.mjs` 期望值，desc 写「TASK-xxx 新增 … a→b，R10-01；前次 …」。
4. **新增接口**必须先在 `docs/architecture/API接口文档.md` 登记（版本头 +1，保留上一版摘要），再实现。
5. **证据**写入 `docs/任务规划V0.10.0/06_validation/evidence/EVD-xxx/`：`verify.txt`（验证命令完整输出 + 退出码）、全局门禁输出、UI 卡的桌面/移动截图、偏离说明。
6. **提交**：一卡一提交，信息格式 `type(TASK-xxx): 摘要`，正文列改动点与证据路径；禁止强推、禁止改写历史、禁止 `--no-verify`。
7. **推送后**在交付消息里给出：提交 SHA、`git diff --name-only HEAD~1` 清单、验证命令退出码、全局门禁五项结果。
8. **停止条件**（立即停手并报告，不得自行裁决）：需要改冻结契约 `docs/任务规划V0.5.0/contracts/**`；需要改排名算法或计费公式；需要真实密钥/外网付费调用；卡面与代码事实冲突且无法按卡面完成；同一问题连续两次修复失败。
