### 7.35 V0.9.0 TASK-013 · R-01 价格历史唯一约束缺陷闭环（文档同步轮，v2.36，2026-10-19）

> 来源：任务规划V0.9.0 TASK-013（S1 价格历史唯一约束修复）｜追溯 REQ-F-019｜决策 ADR-P003｜迁移 M-001（`20261014000000_model_prices_partial_current_unique`）｜前置 TASK-012 已合并

**缺陷（R-01）**：早前 #63（v2.6 轮，迁移 `20260925170000_align_unique_indexes`）为消除 schema↔DB 唯一索引漂移，给 `model_prices` 建了**全列唯一** `@@unique([model_id, is_current])`。该约束使同一 `model_id` 仅能存在**一行** `is_current=false` 历史价——`persistPrices` 的「`updateMany(current→false)` → `create(新 current)`」（见 #29）在**第三次及以后采集**时必撞该唯一键，抛 `23505`/`P2002`（连续采集同一模型写价失败）。

**闭环**：迁移 `20261014000000_model_prices_partial_current_unique` 将约束改为**部分唯一索引** `UNIQUE(model_id) WHERE is_current = true`——每个模型至多一条「当前价」，历史价（`is_current=false`）不再受唯一约束限制、可无限追加。Prisma schema 无法表达带 `WHERE` 的部分唯一索引，故 schema 移除全列唯一、约束下沉到 DB 层（`prisma migrate diff` 会将其列为已知差异，属 ADR-P003 登记的豁免项，非漂移，勿据此回滚）。

| 环节 | 状态 | 证据 |
|---|---|---|
| 迁移实施 | ✅ | `20261014000000`：`DROP INDEX "model_prices_model_id_is_current_key"` + `CREATE UNIQUE INDEX "model_prices_model_id_current_key" ON "model_prices"("model_id") WHERE "is_current" = true` |
| 前置数据核验 | ✅ | 实施前 `dup_current_groups = 0`（无同模型多条当前价）——见 TASK-011 EVD-011；迁移 SQL 头部注释留痕 |
| 真库复核 | ✅ | TASK-091 隔离 PG16 真库取证：收藏 23505 + `model_prices` 部分唯一生效（提交 f666f0da） |
| schema 口径 | ✅ | `schema.prisma` `ModelPrice` 段 R-01 修复注释 + `@@index([isCurrent])` |
