## 一、深度分析（三轮思考）

### 第一轮：5W1H 发散拆解

#### What（客观事实是什么？）

| 维度 | 事实 | 证据来源 |
|------|------|------|
| 项目定位 | Aidean 是 AI 模型聚合平台，核心三层：信息层+网关层+展示层 | README.md + 项目结构 |
| 数据模型 | 37个Prisma模型，覆盖模型/站点/计费/额度/套餐/用量全链路 | schema.prisma 1816行 |
| 同步适配器 | 10个适配器：openrouter/huggingface/artificial-analysis/llmstats/lmsys/epochai/agentindex/skillsmp/smithery + base | apps/web/lib/sync/adapters/ |
| 预置站点 | 20个APIStation（seed.ts L296-316） | seed.ts |
| 网关 | 双格式入口(OpenAI/Anthropic)，5种计费路径，跨格式自动转换 | gateway/chat/route.ts + adapters.ts |
| 缓存 | cachedTokens已落库但不参与计费折算 | UsageLog.cachedTokens + 网关计费时序契约 |
| OpenRouter适配器 | 仅提取5个字段(id/name/context_length/prompt/completion)，API返回15+字段 | openrouter.ts L20-40 |
| 模型详情页 | TOC_ITEMS硬编码4项(基本介绍/参数信息/基准测试/测评示例)，未展示可用渠道 | page.tsx L24-28 |
| 管理页面 | 22个admin页面，含api-stations/free-quotas/packages/sync等 | apps/web/app/(admin)/ |
| 定时脚本 | ScheduledScript模型支持cron/interval配置 | schema.prisma L1650 |

#### Why（深层原因是什么？）

- **OpenRouter适配器只提取5字段**：不是偷懒，是RawModelData类型(sync.ts L34-62)限制了可用字段。适配器受类型约束，需扩展RawModelData→Mapper→Writer全链路
- **模型详情页未展示可用渠道**：前后端不同步。stations API已就绪(`GET /api/v1/models/[id]/stations`)，前端TOC_ITEMS未更新
- **缓存价格未折算**：网关计费时序契约明确记录为"待闭环项"。数据已采集(cachedTokens落库)但calcCharge未接入
- **302.AI等未预置**：seed.ts只覆盖20个官方/国产站点，未覆盖中转站。但CustomChannel机制已实现，用户可自助添加

#### Where/When（边界条件？）

| 边界 | 说明 |
|------|------|
| 端口约束 | Aidean 3000-3100，网关入口 /api/v1/gateway/chat |
| 格式约束 | ChannelFormat仅OPENAI(1)/ANTHROPIC(2)，Google/Responses未实现 |
| 路径约束 | 网关路径非标准 /v1/chat/completions，工具可能拼接出错 |
| 区域约束 | 302.AI/DeerAPI从当前区域不可达(超时/403) |
| 频率约束 | OpenRouter免Key有速率限制；HuggingFace免Key限速 |

#### Who（涉及主体？）

| 主体 | 角色 | 关注点 |
|------|------|------|
| 普通用户 | 消费模型服务 | 在哪用、怎么用、价格、额度 |
| 开发者用户 | 接入工具/SDK | 工具兼容性、API格式、缓存命中率 |
| 管理员 | 配置运维 | 采集源管理、计费规则、额度配置、监控 |
| 系统自身 | 自动化 | 定时采集、路由降级、计费闭环 |

#### How（实现路径？）

1. **立即可用（零开发）**：CustomChannel添加中转站 → CallPlayground测试 → 工具接入
2. **短期开发（1-2周）**：扩展OpenRouter适配器 → 模型详情页展示渠道 → 网关路径别名 → 预置中转站
3. **中期开发（2-4周）**：缓存价格折算 → 缓存命中率报表 → 工具兼容性矩阵 → coding plan视图
4. **长期开发（1-2月）**：Google/Responses协议 → 分段定价 → 中转站价格自动同步

#### What if（前提变了会怎样？）

| 变化 | 影响 |
|------|------|
| OpenRouter停服 | 降级到HuggingFace+Models.dev;dev+LiteLLM采集，核心需求仍可覆盖 |
| 302.AI可达 | 可预置为APIStation，用户只需填Key |

| 路径别名上线 | Cursor/Cline等工具一键接入，零配置路径 |
| Google协议实现 | Gemini CLI/Vertex AI SDK可接入 |

### 第二轮：苏格拉底追问

**追问1：CustomChannel真的能替代预置APIStation吗？**
- 不合理。普通用户不应手动填baseUrl。应预置主流中转站为APIStation，CustomChannel作为长尾兜底
- **结论**：两者都需要。预置覆盖主流，CustomChannel覆盖长尾

**追问2：缓存价格折算真的重要吗？**
- 重要。OpenRouter实测缓存命中时输入价格降低20倍。重度用户(coding场景反复发相同system prompt)多付20倍
- **结论**：P1优先级待闭环项

**追问3：RawModelData只5字段是设计缺陷还是MVP？**
- MVP设计。类型系统限制，需扩展RawModelData→Mapper→Writer全链路
- **结论**：不是偷懒，需类型扩展

**追问4：网关路径 /api/v1/gateway/chat 能被工具正确使用吗？**
- 真实问题。Cursor等工具默认拼接 /v1/chat/completions，路径不匹配
- **结论**：需添加路由别名，P0阻断性问题

**追问5：模型详情页为什么不展示可用渠道？**
- 前后端不同步。API已就绪，前端TOC_ITEMS未更新
- **结论**：前端需补"可用渠道"section

### 第三轮：双向钢人论证

**论点：OpenRouter是最佳单一模型信息来源**

| 支持论证 | 反对论证 |
|------|------|
| 免Key可读，464模型，7天新增15个 | 依赖单一来源，OpenRouter停服则采集中断 |
| 含created时间戳+价格+缓存价格+架构+模态 | 部分模型信息可能延迟(API可用晚于发布) |
| 含provider信息(112个provider) | 中转站价格可能不等于官方价格 |
| 实测稳定，HTTP 200 | 免Key有速率限制 |

**结论**：OpenRouter是最佳单一来源，但必须有多源备份(HuggingFace+Models.dev+LiteLLM)。单一来源风险通过多源交叉验证对冲。

### 5.1 核心缺口清单

## 十三、执行总结（说人话版）

### 现状一句话
Aidean已经有完整的模型聚合架构（37个数据模型+10个采集适配器+双格式网关+22个管理页面），但**三个关键环节断了**：用户找不到在哪用（详情页缺渠道）、工具接不进来（路径不对）、缓存白省了（价格没折算）。

### 最该先做的3件事

1. **加路径别名**（1天）：让 `/v1/chat/completions` 转发到网关，Cursor/Cline等工具就能直接接入了
2. **详情页加渠道**（2天）：调已有API展示"这个模型在哪些站点可用、多少钱、延迟多少"
3. **提取缓存价格**（3天）：OpenRouter API已经返回了缓存价格数据，适配器没提取，补上就行

### 做完这3件事的效果

- 工具接入：从"不知道怎么配"→"复制Base URL+Key，2分钟搞定"
- 模型发现：从"不知道在哪用"→"详情页直接看渠道列表"
- 费用节省：缓存命中时费用降低10-20倍

### 再做3件事（1-2周）

4. **缓存价格折算**：calcCharge公式加上cacheDiscount项
5. **预置中转站**：seed.ts加3行，OpenRouter/302.AI/无问芯穹立即可用
6. **使用文档**：详情页加curl/Python/工具配置示例

### 采集源扩展

现在有10个适配器，再加2个就够：
- **Models.dev适配器**：225提供商8558模型，免Key
- **LiteLLM适配器**：6000条模型注册表，价格交叉验证

### 更新频率

系统已有ScheduledScript+cron机制，只需在/admin/scripts页面配置：
- 每日采集：OpenRouter+HuggingFace+Models.dev
- 每周验证：ArtificialAnalysis+LMSys+EpochAI
- 触发式验证：官方定价页（新模型上线时）

### 一句话总结

**不是从零开始，是补3个断点+扩展2个数据源+配置更新频率。核心架构已经就位，缺的是最后10%的闭环。**
