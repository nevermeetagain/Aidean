## 三、怎么使用：API调用完整链路

### 3.1 统一网关入口

**入口**：`POST /api/v1/gateway/chat`（`apps/web/app/api/v1/gateway/chat/route.ts`）

**双格式判别**：`detectGatewayFormat(body)` — 自动识别OpenAI/Anthropic格式

**鉴权双通道**（`requireGatewayPrincipal`）：
- `Authorization: Bearer aid_ak_...` — 平台API Key
- `x-api-key: aid_ak_...` — 兼容Anthropic SDK
- 无Header → 回落 JWT cookie

### 3.2 五种计费路径（UsageBillingPath enum，schema.prisma L892-898）

| billingPath | 扣费 | 触发条件 | 适用场景 |
|------|:---:|------|------|
| PLATFORM | ✅ hold→capture | 站点规则PLATFORM，无套餐覆盖 | 标准付费调用 |
| UPSTREAM | ❌ | billingMode=UPSTREAM + 用户有自有Key | 用户自带Key直调上游 |
| PACKAGE | ❌ | 用户有生效套餐覆盖本站 | 套餐直连 |
| FREE_PROXY | ❌ | 用户isActive自定义渠道 | 用户自有渠道（302.AI等） |
| FREE_QUOTA | ❌+扣周期额度 | free候选（路由链兜底） | 免费额度调用 |

### 3.3 调用示例

**OpenAI格式**：
```bash
curl -X POST https://aidean.ai/api/v1/gateway/chat \
  -H "Authorization: Bearer aid_ak_xxx" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"Hello"}],"max_tokens":100}'
```

**Anthropic格式**（同一入口，自动判别）：
```bash
curl -X POST https://aidean.ai/api/v1/gateway/chat \
  -H "x-api-key: aid_ak_xxx" \
  -H "Content-Type: application/json" \
  -d '{"model":"claude-sonnet-4-20250514","messages":[{"role":"user","content":"Hello"}],"max_tokens":100}'
```

**跨格式自动转换**（`adapters.ts` L265-310）：
- 入口OpenAI → 上游Anthropic：`openaiToAnthropic()` — system提取到顶层，tool折叠为user，temperature clamp至≤1
- 入口Anthropic → 上游OpenAI：`anthropicToOpenai()` — system注入messages头部

**响应头暴露计费事实**：
```
x-aidean-billing-path: PLATFORM
x-aidean-quota-minor: 1500
x-aidean-model-id: xxx
x-aidean-station-id: xxx
```

### 3.4 路由降级链（buildRouteChain，service.ts L60-100）

```
用户请求模型(优先级-1，恒链首)
  → 等级映射(Opus=1/Sonnet=2/Fable=3/Haiku=4)
  → 自定义优先级(1~99)
  → free兜底(优先级100，额度未耗尽才入链)
```
降级序：换Key → 换站 → 换候选模型 → free兜底 → 全链失败(30003)

### 5.2 缓存价格支持

**Schema层**：
- `ModelPrice.priceCache` — 缓存价格字段（`schema.prisma` L392）✅ 已定义
- `ProviderModelOffering.priceCache` — 提供商缓存价格（L496）✅ 已定义
- `ProviderModelOffering.discountCacheMin/Max` — 缓存折扣价区间（L505-506）✅ 已定义

**采集层**：
- OpenRouter API 返回 `pricing.input_cache_read` 和 `pricing.input_cache_write`（2026-09-30 实测确认）
- 示例：GPT-6.1 `input_cache_read: $0.0000001/token`, `input_cache_write: $0.0000025/token`
- **问题**：`OpenRouterAdapter`（`openrouter.ts` L20-40）仅提取 `pricing.prompt` 和 `pricing.completion`，**未提取缓存价格字段**

**展示层**：
- 模型详情页展示 `priceCache`（`page.tsx` L239）✅ 但显示为"缓存价格：未公开"（因采集层未填充）
- 模型详情页展示提供商折扣价（L247-326）✅ 但未展示缓存折扣价列

**计费层**：
- `calcCharge` 计费函数（`service.ts` L1030-1045）仅按 `priceInput` 和 `priceOutput` 计算
- `cachedTokens` 落库但不参与折算（`网关计费时序契约.md` 明确记录此为待闭环项）
- **结论**：缓存价格数据结构完整，但采集→展示→计费链路未打通

### 5.4 计费公式（service.ts L1030-1045）

```
quotaMinor = calcCharge(priceInput, promptTokens, markupRate, tokenMultiplier)
```

- `tokenMultiplier`：Token倍率，默认1.0

## 六、额度多少：免费额度与Coding Plan

### 6.1 免费额度体系（已实现）

**数据模型**（`schema.prisma` L791-824）：

| 模型 | 用途 | 关键字段 |
|------|------|------|
| UserFreeQuota | 按等级×模型配置免费额度 | tier(NORMAL/PRO/MAX), modelId, quotaTokens, refreshCycle(DAY/WEEK/MONTH) |
| UserQuotaUsage | 用户免费额度用量 | userId, modelId, used, periodStart |
| AccountTier | 账户等级 | NORMAL(1) / PRO(2) / MAX(3) |
| RefreshCycle | 刷新周期 | DAY(1) / WEEK(2) / MONTH(3) |

**周期起点计算**（`service.ts` L102-110）：
- DAY：当天零点
- WEEK：本周一零点
- MONTH：本月1日零点

**额度核验**（`service.ts` L139-150）：
- 当期用量 < 配额 → 可用（加入路由链free兜底）
- 当期用量 ≥ 配额 → 出链（不参与降级）

**控制台展示**（`console/page.tsx` L58-62）：
- 三段固定顺序：天刷新 / 周刷新 / 月刷新
- 每段展示：模型名、配额、已用、下次重置日期

### 6.2 "Coding Plan"概念分析

用户提到"coding plan包含了每天/每周多少额度"。当前系统**无专门的"coding plan"概念**，但有等价能力：

| 用户期望 | 系统现状 | 差距 |
|------|------|------|
| Coding plan 每天N tokens | UserFreeQuota tier=NORMAL refreshCycle=DAY quotaTokens=N | ✅ 可配置 |
| Coding plan 每周N tokens | UserFreeQuota tier=NORMAL refreshCycle=WEEK quotaTokens=N | ✅ 可配置 |
| 专属coding模型池 | 可通过 isCodingOptimized=true 筛选 | ⚠️ 需管理员手动配置每个coding模型的额度 |
| coding plan 套餐 | Package + PackageOrder 可实现 | ✅ 已有套餐体系 |
| 超额自动转付费 | 路由链free兜底后→付费候选 | ✅ 已实现降级链 |

**结论**：系统数据结构已支持"coding plan"语义，但需要：
1. 管理员预配置一批coding模型（isCodingOptimized=true）的免费额度
2. 或创建"coding"命名的Package套餐
3. 前端无"coding plan"专属展示页面

### 6.3 套餐体系（Package，schema.prisma L1062-1084）

| 字段 | 用途 |
|------|------|
| stationId | 绑定特定站点（null=平台通用） |
| priceMinor | 兑换价（分） |
| durationHours | 有效时长（天卡=24h） |
| benefits | 权益内容（JSON） |
| status | ACTIVE/DISABLED |

**计费**：套餐覆盖站点 → billingPath=PACKAGE（免扣仍写用量）
**兑换**：Redemption 兑换码 → PackageOrder（ACTIVE/EXPIRED/CANCELLED）

## 十、第二轮收敛与拷问（苏格拉底追问）

### 追问1：CustomChannel真的能替代预置APIStation吗？

**追问**：用户说"我要用302.AI"，你让他去控制台手动填baseUrl和Key，这合理吗？

**回答**：不合理。CustomChannel是高级功能，普通用户不应需要手动填写baseUrl。应预置302.AI等为APIStation，用户只需填Key。但CustomChannel作为兜底机制，确保任何新中转站都能立即接入，无需等开发。

**双向钢人论证**：
- 支持CustomChannel：零开发成本，立即可用，用户自主性强
- 反对CustomChannel：用户体验差，需技术能力，无法享受平台Key池/计费规则/监控
- **结论**：两者都需要。预置APIStation覆盖主流中转站，CustomChannel作为长尾兜底。

### 追问2：缓存价格折算真的重要吗？

**追问**：cachedTokens不参与计费，用户多付了钱，但系统也没亏，为什么要改？

**回答**：重要。OpenRouter数据显示缓存命中时输入价格降低20倍。对于重度用户（如coding场景反复发送相同system prompt），缓存折扣是核心成本优势。不折算意味着：
1. 用户多付20倍输入费用（缓存命中部分）
2. 平台竞争力下降（其他平台如302.AI可能已支持缓存折算）
3. 数据已采集（cachedTokens落库）但未利用，是浪费

**结论**：缓存折算是高优先级待闭环项。

### 追问3：OpenRouter适配器只提取5个字段，是设计缺陷还是有意为之？

**追问**：适配器代码只提取id/name/context_length/pricing.prompt/pricing.completion，是偷懒还是MVP？

**回答**：MVP设计。`RawModelData`类型定义（`sync/types/sync.ts` L34-62）只有基本字段，不含缓存价格/模态/架构等。适配器受限于RawModelData的字段定义。要提取更多字段，需要：
1. 扩展RawModelData类型
2. 扩展Mapper将新字段映射到AiModel/ModelPrice
3. 扩展Writer写入新字段

**结论**：不是偷懒，是类型系统限制。需要扩展RawModelData → Mapper → Writer全链路。

### 追问4：模型详情页为什么不展示可用渠道？

**追问**：API已经有了（`/api/v1/models/[id]/stations`），页面为什么不调用？

**回答**：页面开发优先级问题。模型详情页（`page.tsx` L24-28）TOC_ITEMS硬编码4项，开发时聚焦于模型参数和基准测试展示。stations API是后实现的（Task L.3.3），前端未同步更新。

**结论**：前后端不同步。API已就绪，前端需补一个"可用渠道"section调用此API。

### 追问5：网关路径 `/api/v1/gateway/chat` 能被工具正确使用吗？

**追问**：Cursor等工具默认拼接 `/v1/chat/completions`，你的入口是 `/api/v1/gateway/chat`，路径不匹配怎么办？

**回答**：这是真实问题。工具配置Base URL为 `https://aidean.ai/api/v1/gateway` 后，工具会请求 `https://aidean.ai/api/v1/gateway/chat/completions`，但实际路径是 `https://aidean.ai/api/v1/gateway/chat`。需要：
1. 添加路由别名 `/api/v1/gateway/chat/completions` → 转发到 `/api/v1/gateway/chat`
2. 或添加标准路径 `/v1/chat/completions` → 转发到网关

**结论**：路径兼容性是阻断性问题，需验证并可能需要添加路由别名。

- 缓存命中报告：`usage.prompt_tokens_details.cached_tokens` + `cache_write_tokens` + `cache_discount`
- 粘性路由：自动路由到同一提供商以最大化缓存命中，10分钟不活动后过期，可通过 `session_id` 或 `x-session-id` 控制

**B. Response Caching（OpenRouter级，请求级）**

| 项目 | 内容 |
|------|------|
| 适用范围 | 所有模型/提供商，无需提供商支持 |
| 启用方式 | `X-OpenRouter-Cache: true` 请求头或preset配置 |
| 缓存命中费用 | **免费**（所有usage计数器归零，不计费） |
| TTL | 1~86,400秒（默认300秒/5分钟） |
| 缓存状态头 | `X-OpenRouter-Cache-Status: HIT|MISS` · `X-OpenRouter-Cache-Age` · `X-OpenRouter-Cache-TTL` |
| 作用域 | 按API Key隔离，不同Key不共享 |
