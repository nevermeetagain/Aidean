# 研究发现

## 数据库设计文档分析

### 数据库设计文档_opencode.md
- **覆盖功能**：用户系统、模型核心、资讯系统、定时脚本、Skills/MCP/Agent/API站、收藏系统、功能开关
- **优点**：
  - 通用字段模板全面（30+个预留字段）
  - 字段预留充足（attr_01~05, attr_int, attr_num, attr_bool, attr_json）
  - Skills多源同步字段完整（source, source_id, stars, install_command）
  - 索引策略完善（包含GIN索引、复合索引、部分索引）
  - 触发器设计（自动更新updated_at和search_vector）
- **缺陷**：
  - 缺少Schema分区设计
  - 缺少厂商表(vendors)的层级设计
  - 缺少价格历史表设计
  - 缺少天梯图定义表
  - 缺少导航菜单表
  - 缺少字典表设计
  - 表名前缀不统一（sys_/ai_/fin_/content_）

### 数据库设计文档_trae.md
- **覆盖功能**：用户系统（含分区设计）、模型系统（厂商、模型、价格、基准测试、评分）、天梯图系统（定义、排名）、Skills系统（含多源同步）、数据源配置、Redis缓存架构
- **优点**：
  - Schema分区清晰（7个Schema：core/models/tools/user/system/dict）
  - 分区表设计（用户表16个HASH分区，模型表按月RANGE分区）
  - 厂商层级设计（tier_level, is_featured, featured_weight）
  - 价格历史设计（effective_from, effective_until, is_current）
  - 天梯图完整设计（ladder_charts + ladder_rankings）
  - Skills多源同步更详细（4个平台预设配置）
  - ER关系图完整
  - Redis缓存设计（Key模式、TTL、一致性策略）
- **缺陷**：
  - 缺少Agent表详细设计
  - 缺少MCP表详细设计
  - 缺少API站表设计
  - 缺少收藏表设计
  - 缺少功能开关表设计
  - 缺少导航菜单表设计
  - 缺少审计日志表设计
  - 通用字段比_opencode.md少（无地理、安全、生命周期字段）

### 数据库设计文档_windsurf.md
- **覆盖功能**：整合了_opencode和_trae方案的所有功能，增加了更多细节
- **优点**：
  - 综合了前两者的优点
  - 支持历史版本管理（价格、评分）
  - 详细的多级分类体系
  - 更完善的用户系统（MFA、隐私设置）
  - 更详细的模型信息（多维度评分、支持语言）
  - 更完整的工具生态（skill_sources、skill_sync_logs）
  - 支持多级导航菜单
  - 增加了统计分析Schema
- **缺陷**：表结构复杂度进一步增加，维护成本较高

### 数据库设计文档_workbuddy.md
- **静态界面统计**：42个页面，包括核心天梯图页面、资源页面、产品页面、文档页面、关于页面、认证页面、Demo页面
- **预设功能统计**：用户系统、模型天梯图功能、资源功能、系统功能
- **对比分析**：详细对比了_opencode和_trae方案的优缺点，提出了整合建议
- **缺陷总结**：缺少多级层级结构设计、业务规则表、统计分析表、消息通知表
