# Aidean 功能设计文档（统一架构版）

> 文档版本：v1.0  
> 更新日期：2026-05-06  
> 设计目标：在不更换主技术栈前提下完成全量重构，优先保障核心闭环与可部署性。

## 1. 架构目标
- 三产品一体化：共享基础设施与通用能力，产品模块相对独立。
- 用户体验优先：服务端聚合数据，减少前端多接口拼接复杂度。
- 部署可复制：本地、测试、生产环境使用一致的容器化规范。

## 2. 统一技术架构
### 2.1 前端与服务端
- 框架：Next.js 14 App Router（SSR/ISR/CSR 混合）。
- 状态：Zustand（仅客户端交互状态）。
- 图表：ECharts（仅客户端图表渲染）。

### 2.2 数据与缓存
- 主库：PostgreSQL（Prisma ORM）。
- 缓存：Redis（热点列表、筛选结果、聚合接口缓存）。
- 数据同步：脚本任务统一通过 `scripts/` 编排执行。

### 2.3 接口分层
- API Route：输入校验、鉴权、错误归一化。
- Service：业务编排与事务边界。
- Repository：数据读写与查询优化。

## 3. 核心功能模块设计
### 3.1 Aidean（天梯图）
- 榜单模块：模型、Skills、MCP、Agent、API 站五类榜单能力。
- 交互模块：筛选、排序、自定义公式、详情跳转、对比收藏。
- 决策模块：模型详情页展示评分、价格、上下文、来源链接。

### 3.2 AideanSpace（工具管理）
- 列表模块：Skills/MCP/Agent 多维筛选与排序。
- 试用模块：登录校验、余额校验、扣费执行、结果记录。
- 同步模块：多源采集适配器 + 调度任务 + 管理端触发。

### 3.3 Sphere（知识库+数字分身）
- 知识库模块：创建、上传、解析、向量化、检索测试。
- 数字分身模块：角色配置、知识库绑定、对话验证。
- 咨询模块：工单提交、对话追踪、状态管理。

## 4. Docker 与部署设计（强约束）
### 4.1 原则
- 国外环境访问不通，默认镜像必须是国内镜像源。
- 文档、配置、脚本中禁止仅提供国外 registry 示例。

### 4.2 必需服务
- `postgres`：主数据库服务。
- `redis`：缓存服务。
- `web`：Next.js 服务。
- `nginx`：反向代理与静态资源出口。

### 4.3 镜像策略（示例）
- `registry.cn-hangzhou.aliyuncs.com/library/postgres:15`
- `registry.cn-hangzhou.aliyuncs.com/library/redis:7`
- `registry.cn-hangzhou.aliyuncs.com/library/node:20-alpine`
- `registry.cn-hangzhou.aliyuncs.com/library/nginx:alpine`

## 6. 风险与控制
- 风险1：旧文档与现状不一致导致返工。  
  控制：以根目录 `.docs` 为唯一真源，旧版文档仅作参考。
- 风险2：接口改造影响前端主路径。  
  控制：先产出接口兼容层，再逐步替换调用。
- 风险3：镜像下载失败导致环境不可用。  
  控制：强制国内镜像 + 离线缓存镜像策略。
