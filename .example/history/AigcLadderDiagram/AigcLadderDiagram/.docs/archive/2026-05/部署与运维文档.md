# Aidean 部署与运维文档（国内镜像强约束）

> 文档版本：v1.0  
> 更新日期：2026-05-06

## 1. 目标
- 提供可复制的 Docker 部署规范，确保在国内网络环境稳定拉起。
- 保证 PostgreSQL、Redis、Web、Nginx 四类核心服务统一编排。

## 2. 强制约束
- 默认镜像源必须使用国内镜像仓库。
- 禁止在主文档中仅保留国外镜像拉取方式。
- 配置变更后必须记录版本与变更说明。

## 3. 服务清单
- `postgres`：主数据库（账号、密码、库名通过环境变量注入）。
- `redis`：缓存与会话辅助。
- `web`：Next.js 应用服务。
- `nginx`：反向代理、静态资源入口、网关层。

## 4. Docker Compose 基线要求
- 网络：统一自定义 bridge 网络。
- 存储：数据库与缓存必须挂载持久卷。
- 健康检查：`postgres`、`redis`、`web` 均应配置健康检查。
- 启动顺序：`web` 依赖 `postgres` 和 `redis` 健康状态。

## 5. 环境变量规范
- `DATABASE_URL`：指向 `postgres` 容器服务名。
- `REDIS_URL`：指向 `redis` 容器服务名。
- `NODE_ENV`：按环境区分 `development` / `production`。
- 禁止在仓库中提交真实密钥，使用 `.env.example` 提供模板。

## 6. 启动与验证流程
1. 准备 `.env` 与镜像源配置。
2. 执行 `docker compose up -d`。
3. 检查容器健康状态。
4. 访问健康检查接口验证服务可用。
5. 执行基础冒烟测试并记录结果。

## 7. 运维检查项
- 数据库连接与迁移状态正常。
- Redis 缓存可读写。
- Web 服务日志无启动级错误。
- Nginx 反代正常，静态资源可访问。

## 8. 故障排查优先级
1. 镜像拉取失败：优先检查国内镜像源地址。
2. 服务未就绪：检查依赖服务健康检查与网络连通。
3. 接口超时：检查数据库、缓存连接与池配置。
4. 页面异常：检查 Web 构建与运行日志。
