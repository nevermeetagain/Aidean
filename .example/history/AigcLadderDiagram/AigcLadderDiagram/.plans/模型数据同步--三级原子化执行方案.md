## 二、最优方案选择：方案C - 双源聚合

**选择理由**：
1. **互补性强**：OpenRouter提供价格+技术参数，Arena AI提供评测评分，单一源无法覆盖天梯图所需的"价格×评分"双维度
2. **故障容错**：任一源不可用时，另一源仍可提供部分数据，不会全量中断
3. **架构可扩展**：双源聚合框架一旦建立，后续加入HuggingFace/SiliconFlow等数据源只需新增adapter
4. **与现有Schema完美匹配**：`ModelScore.actualScore`对应Arena Elo分，`ModelPrice`对应OpenRouter价格，`SyncBatch`追踪批次，`ModelChangeLog`记录变更——全部字段有落点

**降级策略**：
- Arena API不可用 → 仅同步OpenRouter价格+参数，评分保持上次值
- OpenRouter API不可用 → 仅同步Arena评分，价格保持上次值
- 双源不可用 → 跳过本次同步，记录失败批次

### 触发→路由→处理→请求→数据库→响应 6步逻辑（前端+后端分离）

**后端 - 自动同步流程**：
1. **触发**：cron调度器每日0点 → 读取ScheduledScript表
2. **路由**：`scheduler.ts` → 匹配scriptPath → 调用`sync-orchestrator.ts`
3. **处理**：orchestrator → fetchOpenRouter + fetchArena → mergeData → computeDiff → upsertModel/Price/Score → recordChangeLog → updateRanking
4. **请求**：HTTP GET `openrouter.ai/api/v1/models`(Bearer Token) + HTTP GET `api.wulong.dev/arena-ai-leaderboards/v1/leaderboard?name=text`
5. **数据库**：Prisma → `ai_models`(upsert) + `model_prices`(upsert) + `model_scores`(upsert) + `model_change_logs`(insert) + `sync_batches`(update) + `ladder_rankings`(upsert) + Redis DEL缓存
6. **响应**：SyncResult写入ScriptExecution.output，status=1(成功)/2(失败)

**后端 - 手动触发API**：
1. **触发**：管理员点击"立即同步"按钮
2. **路由**：`POST /api/v1/admin/sync` → route.ts
3. **处理**：解析body(source/dryRun) → 构建SyncConfig → executeSync → 返回结果
4. **请求**：同自动流程的③④
5. **数据库**：同自动流程的⑤
6. **响应**：`{ success: true, data: SyncResult }` JSON

**前端 - 同步管理页面**：
1. **触发**：管理员访问`/admin/sync`
2. **路由**：Next.js App Router → `admin/sync/page.tsx`
3. **处理**：useApi钩子 → GET `/api/v1/admin/sync` 获取批次列表 + ScriptExecution日志
4. **请求**：fetch → `/api/v1/admin/sync`
5. **数据库**：无直接操作（通过API层）
6. **响应**：渲染批次表格(批次号/来源/状态/成功数/失败数/时间) + 手动触发按钮 + dry-run按钮
