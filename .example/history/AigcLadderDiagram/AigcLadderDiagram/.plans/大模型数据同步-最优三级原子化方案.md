## 三、数据源深度可行性分析

### 三个候选数据源对比

| 数据源 | 优势 | 劣势 | 可行性评分 | 推荐度 |
|--------|------|------|-----------|--------|
| **OpenRouter.ai** | 官方API，数据结构化，包含价格/上下文/速度/架构，400+模型 | 需要API Key，有请求限制 | ⭐⭐⭐⭐⭐ | **主数据源** |
| **Arena.ai** | 权威评测数据，ELO评分系统 | 无官方API，需要爬虫，反爬虫机制 | ⭐⭐ | 不推荐 |
| **Poe.com** | 多模型聚合 | 无官方API，数据结构复杂，需要登录 | ⭐ | 不推荐 |

### 关键发现：补充数据源

通过deep-research技能分析，发现**替代Arena的更好方案**:

| 数据源 | 数据类型 | 获取方式 | 稳定性 |
|--------|---------|---------|--------|
| **api.wulong.dev** | Arena排行榜快照 | REST API，免费无认证 | ⭐⭐⭐⭐ 第三方维护 |
| **GitHub Raw JSON** | Arena历史数据 | 直接读取JSON文件 | ⭐⭐⭐⭐ 社区维护 |
| **HuggingFace Leaderboard** | 多任务评测 | REST API | ⭐⭐⭐⭐ 官方支持 |

**结论**: 使用 **OpenRouter(主源) + api.wulong.dev(辅源)** 替代 Plan A 的 Arena 直接访问

## 五、最优方案：双源聚合架构（方案B）

### 选择理由

1. **互补性强**: OpenRouter提供价格+技术参数，第三方快照提供评测评分
2. **故障容错**: 任一源不可用时，另一源仍可提供部分数据
3. **架构可扩展**: 双源聚合框架一旦建立，后续加入新数据源只需新增adapter
4. **与现有Schema完美匹配**: 字段有明确落点

### 降级策略

| 场景 | 降级行为 |
|------|----------|
| Arena API不可用 | 仅同步OpenRouter价格+参数，评分保持上次值 |
| OpenRouter API不可用 | 仅同步Arena评分，价格保持上次值 |
| 双源不可用 | 跳过本次同步，记录失败批次，发送告警 |

## 七、触发→路由→处理→请求→数据库→响应 六步逻辑

### 后端 - 自动同步流程

1. **触发**: cron调度器每日0点 → 读取ScheduledScript表
2. **路由**: `scheduler.ts` → 匹配scriptPath → 调用`sync-orchestrator.ts`
3. **处理**: orchestrator → fetchOpenRouter + fetchArena → mergeData → computeDiff → upsertModel/Price/Score → recordChangeLog → updateRanking
4. **请求**: HTTP GET `openrouter.ai/api/v1/models` + HTTP GET `api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`
5. **数据库**: Prisma → `ai_models` + `model_prices` + `model_scores` + `model_change_logs` + `sync_batches` + `ladder_rankings` + Redis DEL缓存
6. **响应**: SyncResult写入ScriptExecution.output，status=1(成功)/2(失败)

### 后端 - 手动触发API

1. **触发**: 管理员点击"立即同步"按钮
2. **路由**: `POST /api/v1/admin/sync` → route.ts
3. **处理**: 解析body(source/dryRun) → 构建SyncConfig → executeSync → 返回结果
4. **请求**: 同自动流程
5. **数据库**: 同自动流程
6. **响应**: `{ success: true, data: SyncResult }` JSON

### 前端 - 同步管理页面

1. **触发**: 管理员访问`/admin/sync`
2. **路由**: Next.js App Router → `admin/sync/page.tsx`
3. **处理**: useApi钩子 → GET `/api/v1/admin/sync` 获取批次列表
4. **请求**: fetch → `/api/v1/admin/sync`
5. **数据库**: 无直接操作（通过API层）
6. **响应**: 渲染批次表格 + 手动触发按钮 + dry-run按钮

## 十、数据库表结构

### ai_models（主表）
```sql
CREATE TABLE ai_models (
  id SERIAL PRIMARY KEY,
  model_id VARCHAR(255) UNIQUE NOT NULL,
  model_name VARCHAR(255) NOT NULL,
  provider VARCHAR(100),
  context_length INTEGER,
  pricing_prompt DECIMAL(10, 8),
  pricing_completion DECIMAL(10, 8),
  pricing_image DECIMAL(10, 8),
  supported_parameters JSONB,
  architecture JSONB,
  description TEXT,
  ranking_score DECIMAL(10, 4),
  ranking_position INTEGER,
  category VARCHAR(50),
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  last_sync_at TIMESTAMP
);
```

### sync_logs（同步日志表）
```sql
CREATE TABLE sync_logs (
  id SERIAL PRIMARY KEY,
  task_id VARCHAR(100) UNIQUE NOT NULL,
  status VARCHAR(20) NOT NULL,
  trigger_type VARCHAR(20),
  models_fetched INTEGER,
  models_created INTEGER,
  models_updated INTEGER,
  models_deleted INTEGER,
  error_message TEXT,
  started_at TIMESTAMP NOT NULL,
  completed_at TIMESTAMP,
  duration_seconds INTEGER
);
```
