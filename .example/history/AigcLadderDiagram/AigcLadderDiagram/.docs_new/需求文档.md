# Aidean 项目需求文档（全量重构基线）

> 文档版本：v1.0  
> 更新日期：2026-05-06  
> 适用范围：Aidean（大模型天梯图）/ AideanSpace（AI Skills/MCP 工具管理）/ Sphere（知识库+数字分身）

## 1. 文档目的
- 统一全项目重构范围与优先级，确保先完成核心功能闭环，再推进视觉升级与体验优化。
- 明确不可变约束：国外网络不可用，Docker 部署必须优先使用国内镜像。
- 作为后续 UI/UX 重构、开发实施、测试验收、上线发布的唯一需求基线。

## 2. 项目目标
### 2.1 总体目标
- 打造 Aidean 品牌下的三产品统一平台，用户能在首页一眼识别产品价值并快速进入核心功能。
- 以 UI/UX 为最高优先级，在保证功能完整性的前提下提升可理解性、可操作性、可转化性。

### 2.2 三个核心产品
- Aidean：大模型天梯图，支持筛选、排序、对比与详情决策。
- AideanSpace：Skills / MCP / Agent 工具发现、管理与试用。
- Sphere：知识库上传向量化、数字分身配置与业务咨询闭环。

## 3. 重构范围
### 3.1 在范围内
- 前台信息架构重构：首页、产品入口、核心流程页面。
- 后台与 API 的统一能力边界梳理与接口口径统一。
- 文档体系重建：需求、交互、功能、目录结构、测试验收、部署运维。
- 容器化部署规范统一：开发、测试、生产三环境基线。

### 3.2 不在范围内（本阶段）
- 新增第四产品线或跨项目平台化改造。
- 更换基础技术栈（Next.js、Prisma、PostgreSQL、Redis 保持不变）。

## 4. 优先级原则
### 4.1 P0（必须先完成）
- 核心功能闭环完整可用。
- 用户从首页到核心功能路径清晰。
- Docker 国内镜像部署链路可用且可复现。
- 核心页面与核心 API 冒烟测试通过。

### 4.2 P1（与 P0 并行推进）
- 视觉统一升级（品牌一致、层级清晰、交互反馈明确）。
- 关键流程性能与稳定性优化（加载、筛选、切换、提交）。

### 4.3 P2（P0/P1 稳定后）
- 深度增长能力（更细分运营、实验性功能、扩展场景）。

## 5. 核心功能闭环定义
### 5.1 Aidean 闭环
- 入口：`/` 首页产品卡片 -> `/aidean` 或 `/models`。
- 过程：榜单选择 -> 筛选排序 -> 模型详情 -> 对比/收藏。
- 结果：用户完成模型选型决策并可回溯对比依据。

### 5.2 AideanSpace 闭环
- 入口：`/` 首页产品卡片 -> `/space`。
- 过程：工具检索筛选 -> 详情查看 -> 试用触发 -> 余额扣费/记录。
- 结果：用户完成工具发现与低成本试用验证。

### 5.3 Sphere 闭环
- 入口：`/` 首页产品卡片 -> `/sphere`。
- 过程：创建知识库 -> 上传文档 -> 向量化 -> 检索测试 -> 绑定数字分身。
- 结果：用户完成从数据到应用角色的可运行配置。

## 6. 用户体验目标
### 6.1 体验原则
- 先理解再操作：页面首屏必须回答“这是什么、能做什么、下一步做什么”。
- 先主路径后扩展：每页只突出一个主行动按钮，次要动作降权。
- 一致性优先：命名、布局、按钮语义、反馈文案统一。

### 6.2 体验指标（验收口径）
- 新用户 10 秒内识别三产品差异与入口。
- 核心任务首次完成率达到可观测标准（以测试方案定义）。
- 关键交互无阻断错误，用户测试反馈无 P0/P1 体验问题。

## 7. 技术与部署强约束
### 7.1 架构约束
- 全项目统一 Next.js App Router 全栈架构。
- 数据层统一 Prisma + PostgreSQL，缓存统一 Redis。
- 容器化统一 Docker Compose 规范，避免多套部署口径并存。

### 7.2 网络与镜像约束（强制）
- 国外环境访问不通，禁止依赖国外镜像直拉作为默认方案。
- 所有部署文档、脚本、Compose 示例必须优先给出国内镜像地址。
- 构建失败时优先检查镜像源、网络策略与 registry 配置。

## 8. 验收标准（总体验收）
- 文档验收：`.docs` 文档体系完整、版本一致、相互引用准确。
- 功能验收：三产品核心闭环可执行，关键 API 可用。
- 体验验收：UI/UX 优化目标达成，主流程可用性通过用户测试。
- 技术验收：Docker 国内镜像部署成功，环境可一键拉起。
- 测试验收：冒烟、核心流程、回归测试通过并留档。

## 9. 里程碑（文档先行）
- M1：文档基线重建完成（本阶段）。
- M2：按文档执行统一架构重构与 UI/UX 升级。
- M3：全量测试、用户测试、上线验收与文档回写。
