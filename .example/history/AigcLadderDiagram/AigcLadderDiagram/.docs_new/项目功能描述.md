> 项目名：Aidean（曾用名：AigcLadderDiagram）
> 版本：v3.0 | 更新日期：2026-05-06
> **重点更新**：3个核心产品（Aidean、AideanSpace、Sphere）+ 首页体验 + Docker国内镜像

## 一、项目概述

### 1.1 项目定位
Aidean品牌下**3个核心产品**，每个产品有独立官网，共享Docker容器化基础设施（PostgreSQL、Redis等服务）。

### 1.2 核心产品与首页体验

#### 首页核心功能
用户打开首页（/）**一眼看到平台3个核心产品**，直接点击进入体验：
```
用户打开首页 → 看到3个产品卡片（Aidean / AideanSpace / Sphere）
```

## 二、Aidean（大模型天梯图）

### 2.1 功能概览
天梯图是Aidean的核心差异化功能，提供**多维度模型评测可视化**，支持：
- **5类天梯图**：大模型、Skills、MCP、Agent、API站

- **2种视图**：排行榜表格（矩阵式）、柱状图

#### 前端实现逻辑（Zustand Store）

**状态存储**：
```typescript
// stores/filterStore.ts
interface FilterState {
  // 筛选条件
  type: string[];           // 类型：['CHAT', 'MULTIMODAL', ...]
  protocol: string[];       // 协议：['OPENAI', 'ANTHROPIC', ...]
  openSource: string[];     // 开源：['true', 'false'] 或空（不过滤）
  benchmark: string;        // 测评集：'INFERENCE' | 'BENCHMARK_X' 或 ''（单选）
  tags: string[];          // 标签：['免费', 'CodingPlan', '用户新增标签']
  timeRange: {            // 时间范围
    start: Date | null;
    end: Date | null;
  };
  
  // 方法
  toggleType: (t: string) => void;     // 切换类型选中状态
  toggleProtocol: (p: string) => void; // 切换协议选中状态
  setBenchmark: (b: string) => void;  // 设置测评集（单选）
  addTag: (tag: string) => void;        // 新增标签
  setTimeRange: (s: Date|null, e: Date|null) => void;
}
```

**筛选流程**：
1. 用户操作（如勾选"对话"类型）→ 调用`toggleType('CHAT')`
2. 更新`filterStore.type`状态 → 触发`useEffect`监听
3. 生成筛选参数hash：`filterHash = MD5(JSON.stringify({type, protocol, openSource, benchmark, tags, timeRange}))`
4. 调用API：`GET /api/v1/models?filters={filterHash}`
5. 更新模型列表：`modelStore.setModels(newModels)`
6. 缓存结果：Redis存储`models:v1:list:{filterHash}`，过期时间1小时

### 2.4 排序功能交互逻辑

#### 排序栏整体布局
- **位置**：位于6个筛选按钮的最右侧，与筛选按钮**同行排列**
- **宽度**：180px，与筛选按钮视觉平衡
- **默认显示**：显示当前排序方式名称 + 下拉箭头（如"基准排序 ▾"）
- **面板展开**：点击排序栏展开下拉面板（高度自适应，最大300px，超出滚动）

#### 五种排序方式详解

##### 1. 基准排序（综合评分）【默认】
| 属性 | 说明 |
|---|---|
| **排序逻辑** | 按四维加权综合得分**降序**（分数高→低） |
| **计算公式** | `(官方得分×官方权重 + 实际得分×实际权重 + 风评得分×风评权重 + 自测得分×自测权重) / 100` |
| **默认权重** | 官方25% + 实际25% + 风评25% + 自测25%（管理员可调整） |
| **单位** | 分（0-100） |
| **默认值** | **默认选中**，高亮显示 |
| **交互** | 点击即选中，面板收起，排行榜立即重排 |

**实现效果**：
- 点击"基准排序"→ 立即按`compositeScore DESC`排序
- 面板收起，显示"基准排序 ▾"
- 对应API：`GET /api/v1/models/ranking?sort=benchmark_desc`

##### 2. 上下文长度排序
| 属性 | 说明 |
|---|---|
| **排序逻辑** | 按上下文窗口大小**降序**（窗口大→小） |
| **单位** | K tokens（如192K、128K） |
| **数据字段** | `ai_models.context_length` |
| **默认值** | 否（非默认） |
| **交互** | 点击即选中，面板收起，排行榜立即重排 |

##### 3. 响应速度排序
| 属性 | 说明 |
|---|---|
| **排序逻辑** | 按输出速度**降序**（速度快→慢） |
| **单位** | tokens/秒 |
| **数据字段** | `ai_models.benchmarks`（需解析速度数据） |
| **默认值** | 否（非默认） |
| **交互** | 点击即选中，面板收起，排行榜立即重排 |

##### 4. 价格排序
| 属性 | 说明 |
|---|---|
| **排序逻辑** | 按输入价格**升序**（价格低→高） |
| **单位** | ￥/M Tokens（¥5=$1换算） |
| **数据字段** | `model_prices.price_input`（当前有效价格） |
| **默认值** | 否（非默认） |
| **交互** | 点击即选中，面板收起，排行榜立即重排 |

##### 5. 自定义排序【公式输入】
| 属性 | 说明 |
|---|---|
| **排序逻辑** | 用户输入计算公式，系统解析后计算得分并排序 |
| **变量支持** | `${综合评分}`/`${benchmark}`、`${上下文长度}`/`${context}`、`${响应速度}`/`${speed}`、`${价格}`/`${price}` |
| **运算符** | `+`（加）、`-`（减）、`*`（乘）、`/`（除）、`()`（括号）、`^`（幂）、`<`（升序）、`>`（降序） |
| **默认值** | 否（非默认） |
| **交互** | 点击展开公式输入框，输入后立即解析生效 |

**公式语法规则**：
```
expression := term (('+' | '-') term)*
term       := factor (('*' | '/') factor)*
factor     := base ('^' exponent)?
base       := variable | number | '(' expression ')'
variable   := '$' '{' NAME '}'
NAME       := '综合评分' | '上下文长度' | '响应速度' | '价格' | 'benchmark' | 'context' | 'speed' | 'price'
```

**公式示例与语义**：
| 公式 | 语义 | 排序方向 |
|---|---|---|
| `${价格}/1000000*${响应速度}` | 价格越低×响应越快，得分越高 | 降序（>） |
| `${综合评分}/${价格}` | 得分高且价格低优先 | 降序（>） |
| `${上下文长度}*0.5+${综合评分}*0.5` | 上下文与得分均衡 | 降序（>） |
| `${价格}<100000` | 仅价格在100000内的模型，按价格升序 | 升序（<） |

### 2.7 背后数据逻辑

#### 排名算法详解

##### 四维评分体系
| 维度 | 来源 | 默认满分 | 权重（可配置） | 数据字段（Prisma） |
|---|---|---|---|---|
| 官方评测基准 | 模型官方/评测机构公布数据 | 100 | 25% (可调) | `model_scores.official_score` |
| 实际评测基准 | 第三方平台实测数据（Arena等） | 100 | 25% (可调) | `model_scores.actual_score` |
| 风评 | 用户社区/网络评价 | 100 | 25% (可调) | `model_scores.review_score` |
| 自测 | 平台自主测试 | 100 | 25% (可调) | `model_scores.self_test_score` |

**综合得分计算公式**：
```
综合得分 = (官方得分 × 官方权重 + 实际得分 × 实际权重 + 风评得分 × 风评权重 + 自测得分 × 自测权重) / 100
```

##### 数据库查询逻辑
```typescript
// app/api/v1/models/route.ts
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const filterHash = searchParams.get('filters') || '';
  const sortKey = searchParams.get('sort') || 'benchmark_desc';
  
  // 1. 尝试从Redis获取缓存
  const cacheKey = `models:v1:list:${filterHash}`;
  const cached = await redis.get(cacheKey);
  if (cached) return Response.json(JSON.parse(cached));
   
  // 2. 构建筛选条件
  const where: any = { isActive: true, status: 'ACTIVE' };
  if (filterHash) {
    const filters = JSON.parse(decodeURIComponent(filterHash));
    if (filters.type?.length) where.modelType = { in: filters.type };
    if (filters.protocol?.length) where.protocol = { in: filters.protocol };
    if (filters.openSource?.length) where.isOpenSource = filters.openSource.includes('true');
    if (filters.benchmark) where.benchmarks = { some: { sourceType: filters.benchmark } };
    if (filters.tags?.length) where.tags = { hasSome: filters.tags };
    if (filters.timeRange?.start) where.publishedAt = { gte: new Date(filters.timeRange.start) };
    if (filters.timeRange?.end) where.publishedAt = { lte: new Date(filters.timeRange.end) };
  }
     
  // 3. 构建排序条件
  const orderBy: any = {};
  if (sortKey === 'benchmark_desc') orderBy.model_scores = { compositeScore: 'desc' };
  else if (sortKey === 'context_desc') orderBy.contextLength = 'desc';
  else if (sortKey === 'speed_desc') orderBy.benchmarks = { some: { totalScore: 'desc' } };
  else if (sortKey === 'price_asc') orderBy.model_prices = { some: { priceInput: 'asc' } };
  else if (sortKey.startsWith('custom:')) {
    // 自定义排序：先查所有，再在前端按公式计算
  }
     
  // 4. 查询数据库
  const models = await prisma.aiModel.findMany({
    where,
    orderBy: Object.keys(orderBy).length ? orderBy : { model_scores: { compositeScore: 'desc' } },
    include: {
      vendor: true,
      model_scores: true,
      model_prices: { where: { isCurrent: true } },
      benchmarks: { take: 1, orderBy: { recordedAt: 'desc' } },
    },
    take: 100,  // 最大显示100个模型
  });
     
  // 5. 缓存结果
  await redis.setex(cacheKey, 3600, JSON.stringify(models));  // 1小时
     
  return Response.json(models);
}
```

```typescript
// scripts/crawl/crawl_skills.ts
export async function crawlSkills(sources?: string[]) {
  const sourcesToCrawl = sources || ['skillsmp', 'smithery', 'skills_sh'];
   
  for (const source of sourcesToCrawl) {
    let adapter;
    if (source === 'skillsmp') adapter = new SkillsmpAdapter();
    else if (source === 'smithery') adapter = new SmitherySkillsAdapter();
    else adapter = new SkillsShAdapter();
       
    const rawSkills = await adapter.fetch();
    const normalized = adapter.normalize(rawSkills);
       
    for (const skill of normalized) {
      await prisma.skill.upsert({
        where: { source_sourceId: { source, sourceId: skill.sourceId } },
        update: {
          name: skill.name,
          description: skill.description,
          downloads: skill.downloads,
          stars: skill.stars,
          avgRating: skill.avgRating,
          lastSyncedAt: new Date(),
        },
        create: {
          name: skill.name,
          source: source,
          sourceId: skill.sourceId,
          ...skill,
          lastSyncedAt: new Date(),
        },
      });
    }
  }
   
  // 清理缓存
  await redis.delPattern('tools:v1:skill:*');
}
```

### 5.2 渲染策略配置
| 页面类型 | 渲染策略 | 配置方式 | 适用场景 |
|---|---|---|---|
| Aidean天梯图 | ISR | `export const revalidate = 3600` | 数据更新频率低（1小时） |
| 模型详情页 | SSR | `export const dynamic = 'force-dynamic'` | 个性化数据，需要实时SEO元数据 |
| AideanSpace首页 | ISR | `export const revalidate = 3600` | 静态内容为主，定期更新 |
| Sphere知识库 | SSR | `export const dynamic = 'force-dynamic'` | 需要认证，实时数据 |
| 搜索结果页 | SSR | `export const dynamic = 'force-dynamic'` | 动态内容，需要实时数据 |
| 静态帮助页 | SSG | `export const dynamic = 'force-static'` | 完全静态，不需要更新 |
